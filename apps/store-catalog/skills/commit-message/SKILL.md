# 提交信息起草

给当前仓库的暂存改动起草一条规范提交信息。

## 步骤

1. 看暂存面：`git diff --cached --stat` 总览 + `git diff --cached` 细读；暂存为空时改看工作区 `git diff` 并提示用户先暂存。
2. 定类型与范围：
   - 类型词：feat（新功能）/ fix（修复）/ refactor（重构）/ docs（文档）/ test（测试）/ chore（杂务）/ perf（性能）；
   - 范围 = 受影响的主要模块或子系统（小写，可缺省）。
3. 写标题：一行、祈使语气、说「做了什么」不说「改了哪个文件」；中文仓库用中文标题。
4. 写正文（改动跨多个关注点时才要）：每行一个要点，说动机与影响，不复述 diff。
5. 有破坏性变更（对外 API/配置面/数据格式）时正文显式单列一行并在标题加 `!`（或 `BREAKING CHANGE:` 段，按仓库既有惯例）。

## 输出形态

直接给出可用的完整提交信息（标题 + 空行 + 正文），不要解释起草过程；用户确认后再执行 `git commit`（提交动作须用户明示，本技能不自动提交）。

## 边界

- 不猜未暂存改动的意图——只对暂存面起草；
- diff 里看不出动机时如实说，不编造；
- 提交信息不出现「根据用户要求」之类的会话痕迹。
