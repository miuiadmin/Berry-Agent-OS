# 插件开发指南

> 面向插件作者：插件形状、inject 服务面、扩展点词汇、组合树、生命周期、插件数据、调试与反模式。

## 1. 插件形状（单形状纪律，钉死）

一个插件 = 一个入口模块，**唯一合法形状是一种函数**：

```ts
// entry.ts（入口解析序：harness.extensions → extensions/index → index）
import { Type } from 'typebox';   // 宿主实例经虚拟注入，勿自装第二份（双实例防线）

export const name = 'my-plugin';           // 必填：日志归因标识（非空字符串）
export const inject = ['tools', 'prompts']; // 硬依赖服务：全就绪才激活，缺 = 响亮失败
export const optionalInject = ['llm'];      // 软依赖：不阻塞激活，ctx.tryGet 探测
export const config = Type.Object({         // 可选：行配置 schema（启动时一次性校验）
  greeting: Type.Optional(Type.String()),
});
export const events = [                     // 可选：自定义活体事件声明（总线词汇）
  { name: 'my-plugin/tick', mode: 'emit', note: '周期心跳' },  // name 小写含 '/'
];

export default async function apply(ctx, cfg) {
  // 一切注册走 ctx.effect —— 作用域 LIFO 回卷即注销，/reload 卸载半边自动干净
  const tools = ctx.get('tools');
  ctx.effect(() => tools.register({ /* ToolDefinition */ }));
}
```

规则：

- **零 import 约束**：文件插件的 entry.ts 不能 import 宿主内部实现——唯一可 import 的是虚拟模块 `berryagent`（contracts 公共面：AppError / 错误码 / 事件常量与目录 / 插件与 Job/子代理契约类型）与 `typebox` 三入口（宿主注入的同实例，防双实例）。
- 形状违例（default 非函数 / name 缺失 / inject 非字符串数组 / config 非对象 schema）→ `PLUGIN_SHAPE_INVALID`，装载即拒。
- apply 抛错 → 加载器先 LIFO 回卷已激活件、再进失败清单；**失败行非空 = 启动断言拒启**（你会在启动时看到全部失败行聚合，而不是静默缺件）。
- 官方件（`builtin:memory` 等）与文件插件完全同轨装载，只是不经 jiti（宿主随包函数引用）。

## 2. inject 服务面（ctx.get / ctx.tryGet）

| 服务名 | 面 | 说明 |
|--------|-----|------|
| `tools` | `register(def: ToolDefinition): Disposer` | 贡献模型可见动词。注册即 tools_change → 活跃 loop 工具集原位刷新 |
| `prompts` | `registerSection({ id, render }): Disposer` | 系统提示词具名段。宿主固定分节序；render 仅重建时点求值（随会话冻结，prompt cache 友好）；禁整串替换 |
| `llm` | `complete()` / `canAfford()` | 单发补全唯一合法路径（不走 loop；禁收 apiKey）；canAfford 预算闸门——后台低优先级活必须先问 |
| `sessions` | `appendEvent(type, data)` | 向当前活跃会话落 durable 事件（活引用，/new 热切换跟随）。核心词汇拒写（`SESSION_CORE_TYPE_FORBIDDEN`）；只许写自注册词汇 |
| `agent` | `sendUserMessage()` / `onRunSettled()` | 以插件身份注入用户消息（source 归因）/ 订阅 run 结算（goal 续跑触发位） |
| `subagents` | `register(provider)` | 注册 SubagentProvider（进程内子代理执行器） |
| `jobs` | `registerKind()` / `run()` / `create()` / `list()` | 后台任务注册表：状态机 running→stopping→唯一终态，结算必发 job_settled |
| `channels` | `registerCommand(cmd)` | TUI 斜杠命令（同名后写胜出） |
| `ui` | `notify()` | UI 通知（三通道自适应：通知器/时间线/状态行） |
| `skills` | `registerProvider(p)` | 技能来源（本地 FS 为默认 provider） |
| `approval` / `sandbox` | 安全栈面 | 高级用法；常规插件经工具管道间接受益即可 |
| `paths` | 数据目录路径族 | 定位插件自身数据目录与宿主路径（数据契约见 §6） |
| `plugins` | `list()` 等 | 插件清单只读面 |

`inject` 是 Kahn 硬依赖（轮次激活：声明即等待，无解响亮失败）；`optionalInject` 是软依赖（激活后 `ctx.tryGet` 探测，缺省 undefined 自行降级）。

## 3. 扩展点词汇

| 扩展点 | 注册 API | 出处模块 |
|--------|----------|----------|
| 工具 | `ctx.get('tools').register(def)` | tools |
| 系统提示词段 | `ctx.get('prompts').registerSection({id, render})` | app/prompts |
| TUI 命令 | `ctx.get('channels').registerCommand(cmd)` | channels |
| 自定义活体事件（总线词汇） | 模块 `events` 声明（`{name, mode, note}`——加载器装载阶段统一登记） | context 总线 |
| LLM provider | `ctx.get('llm')` 运行时面 `registerProvider` | llm |
| 技能来源 | `ctx.get('skills').registerProvider(p)` | skills |
| Job kind | `ctx.get('jobs').registerKind(kind)` | subagent |
| 自定义消息角色 | `registerMessageRole` | agent——**当前仅宿主/官方件可用**（不在 berryagent 虚拟面；Ring 3 开放项） |
| 自定义会话事件类型 | `registerSessionEventType` | session——**当前仅宿主/官方件可用**（同上；文件插件 durable 事件面走 `ctx.sessions.appendEvent` 只写自注册词汇——词汇注册 Ring 3 开放） |

请求尾注入的标准姿势：订阅 `context_transform`（瀑布钩子，`ctx.on` 直接可订）——每 handler 至多追加一条消息，`memory-recall` / `memory-diff` 即此形态（角色注册属宿主/官方件特权，见上表注）。

## 4. 组合树

默认层（官方全家桶，随包）+ 用户 overlay 合成，**字段级后写胜出**：

```yaml
# ~/.berry/overlay.yaml（文件不存在 = 纯默认层，首启零配置即合法）
rows:
  - id: memory                 # 替换官方行：省略 plugin = 沿用官方引用，只改其余字段
    config: { recallTopK: 5 }
  - id: memory-strict          # insert 行必须自带 plugin
    plugin: builtin:memory
    config: { unusedDays: 14 }
  - id: goal                   # 禁用官方行（真·可卸）
    disabled: true
  - id: darwin-only-thing      # 平台门控
    plugin: ./plugins/my-thing
    disabled: darwin
```

- 行字段：`id` / `plugin` / `config` / `disabled` / `fixed`——未知字段拒绝式（pre-release 纪律）。
- `config` 整体替换不做深合并，经插件声明的 schema 启动时一次性校验。
- 文件插件 `plugin` 字段：包名（装入 `<数据目录>/plugins/node_modules` 子树）或显式相对/绝对路径；入口解析序 `harness.extensions` → `extensions/index` → `index`。
- **分发 = npm 三源**（无自定义容器格式）：npm registry 包名 / git 源（含自有托管）/ 本地目录。压缩包过境 = 解压后按本地目录源处理——zip 是搬运方式，不是格式声明。
- 生态挂靠：`package.json` keywords 带 `berry-plugin`。
- 未安装的行 = `unresolved`，**永不自动安装**——装机是 operator 动作（`/plugin-install`）。

## 5. 生命周期与事件

| 时点 | 行为 |
|------|------|
| boot | 组合树合成 → jiti 加载 → 形状校验 → Kahn 轮次激活（硬依赖全就绪） |
| 激活成功 | `plugin/activated` durable 事件 |
| 激活失败 | apply 抛错 → LIFO 回卷已激活件 → `plugin/failed` + 启动断言（聚合全部失败行拒启） |
| 静态禁用/平台门控 | 行不解析入口（挂载休眠）→ `plugin/skipped` |
| `/reload` | 卸载半边（dispose 回卷全部注册）→ 重读组合树 → 重装 |
| 退出 | shutdown 序列：插件作用域回卷 → jobs 排空 → 落盘屏障 → 关库 |

注册纪律：**一切注册挂 `ctx.effect`**（注册即 effect）——你不需要手工管理注销序，作用域回卷自动完成。

## 6. 插件数据（所有权与生命周期）

插件的一切持久状态归三桶，各走各的正门：**配置**走组合树行 `config` 字段（随 overlay 管理，启动时按你声明的 schema 一次性校验）/ **凭证**走宿主 credentials 面（插件不经手）/ **自有数据**住本节的数据目录。宿主不提供通用 KV 存储与 secret 存储——需要 KV 化的配置回行 config，需要保密的交宿主，剩下的才是你要自己管的。

自有数据契约：

- **目录所有权（双键一桥）**：每个插件行一个数据目录（`<数据目录>/plugins/<行 id>/`）。目录键 = 组合树行 id；目录内一份 `data.json` 记 `{ plugin: '<插件名>' }` 作认领桥——行改名后新行靠它认领旧目录，跨包重装不丢数据（`data.json` 认领桥**契约先立、尚未落码**——当前版本仅建目录，认领读写随 uninstall 纵切落码，见下节卸载处置注记）。
- **写入纪律**：自有数据是低频配置类数据（设置、缓存索引、账本），不是每轮热数据——热数据走 durable 事件（`ctx.sessions.appendEvent`）或内存态。写文件用原子写（写临时文件 + rename），不留半文件。
- **默认私有，共享走三桥**：插件间数据共享与能力共享同门——服务面（`provide` 一个读接口）、事件总线（emit 变更）、工具面（注册查询工具）。默认私有由结构保证（各写各的目录）；显式共享 = provide 那一行代码。没有独立的数据授权声明，也没有独立的存储诊断面——服务注册表本身就是共享清单。
- **会话数据不加插件私键**：会话事件日志按会话归属（`sessions` 表记来源应用）；插件读跨会话数据走 `ctx.sessions` 只读投影——同库不同视图，不在事件上分插件库。

卸载处置（`/plugin-uninstall` 随应用面后续纵切落码，契约先立）：

- 装机物（包目录、组合树行）**必删**；数据目录**默认保留**（数据是用户的，不是包的），删除显式问 operator。
- **ignorable 纪律**：有持久语义的自定义事件词汇，注册时一律声明 `ignorable: true`——否则卸载你的插件后，读侧遇未知事件类型会整体拒绝解读会话（宁拒绝不误读），历史会话因卸载变砖。

## 7. 错误码族（`berryagent` 面）

`PLUGIN_LOAD_FAILED`（jiti 加载失败）/ `PLUGIN_SHAPE_INVALID`（形状违例）/ `PLUGIN_CONFIG_INVALID`（行配置不过 schema）/ `PLUGIN_INJECT_UNRESOLVED`（硬依赖无解——Kahn 轮次耗尽）/ `PLUGIN_APPLY_FAILED`（apply 抛错）/ `PLUGIN_ENTRY_UNRESOLVED`（入口解析失败）/ `PLUGIN_INSTALL_FAILED`（装机失败）；另有 `COMPOSITION_ROW_INVALID`（组合树行非法）。抛错统一 `AppError(码, 信息)`——字符串码单一路线，无错误类层级。

## 8. 调试

- `berry dump-config`：合成树 + 每行装载状态（activated / failed / skipped / unresolved 及原因）——「我到底跑的是什么」的第一诊断面。
- `APP_LOG_LEVEL=debug` 跑 `npm run dev`：插件装载、服务提供、工具管道全链 debug 日志。
- `/plugins`（TUI 内）：同 dump-config 的装载状态面。
- 写测试：参考 `src/app/plugins.test.ts` / `src/memory/plugin.test.ts` 的组合根全栈测试形态——真 Context + 真服务面，mock 只停在模型层。

## 9. 反模式（来自双蓝本 60 包生态读码，编号固定）

1. **类型面 ≠ 运行面**：声明了扩展点类型却不在运行时接线（声明零导线）——贡献必须真注册。
2. **逃生门半造**：开了口子却没有完整语义（半个 API 比没有更糟）。
3. **特权分层塌方**：插件面暴露宿主特权操作（绕过守门/审批/归因）—— Berry 对应防线：核心事件词汇拒写、审批对、source 归因。
4. **peerDep 蔓延**：把宿主当 peer 依赖锁版本自保——插件只依赖 `berryagent` 虚拟面，无版本锁（同仓同版本零漂移；hostVersion 门控 Ring 3 出现再议）。
5. **直开 SQLite 库文件**：跨会话数据必须走 `ctx.sessions` 只读投影/事件面，绕投影攒第二份账 = 双事实源错误。
6. **进程日志独扛 bug**：只在 debug 出现的分支，其行为必须同时是 durable 事件或运行时断言。
7. **绕过数据契约**：自造 KV 文件格式 / 每轮热写配置文件 / 在数据目录外藏状态——数据三桶各走各的正门（见 §6）。
