# 运维手册

> ⚠️ **2026-08-22：1.0 重置起草中**。本文描述 old-v2（当前运行代码）的现状与规范，开发照常适用；1.0 落地时是否沿用待重审（[设计文档索引](../设计文档/index.md)）。

> 日常运维操作参考：服务管理、日志清理、数据库重置、健康检查、故障排查。

## 数据存储位置

| 路径 | 说明 |
|------|------|
| `~/.berry/` | 应用主目录（可通过 `SERVICE_HOME` 环境变量覆盖） |
| `~/.berry/data/agent.db` | 主数据库（SQLite + WAL 模式） |
| `~/.berry/logs/berry.log` | 运行日志 |
| `~/.berry/run/` | PID 文件、Unix socket |
| `~/.berry/agents/` | Agent 工作目录 |
| `~/.berry/missions/` | Mission 数据（plan.json、squad.json） |
| `~/.berry/plugins/` | 插件数据 |
| `~/.berry/skills/` | 技能数据 |
| `~/.berry/runs/` | Run artifact |

## 服务管理

### 启动

```bash
# 本地开发（硬规则：必须 debug 模式）
npm run dev:debug              # 后端 + 前端 + debug 日志（推荐）

# 单独启动
npm run dev                    # 仅后端 (CLI + API :3888)
npm run dev:web                # 仅前端 (Vite :3889，绑定 0.0.0.0)

# 生产模式
npm run build:full             # 先构建
berry service start            # 后台启动（看护进程守护，崩溃自动重启）
berry service start --foreground --debug   # 前台 + debug 日志

# 自定义参数
berry service start --port 8080 --host 0.0.0.0
```

### 停止

```bash
berry service stop             # 优雅停止看护进程和子进程

# 强制清理（进程不响应时）
ps aux | grep -E "tsx src/index|concurrently.*backend|agents/bundled" | grep -v grep | awk '{print $2}' | xargs kill -9
```

### 状态查看

```bash
berry service status           # 看护进程 PID、重启次数、运行时长
curl -s http://localhost:3888/api/health   # 健康检查（应返回 logLevel + debugMode）
```

### 重启

```bash
# 本地开发：杀掉进程后重新启动
# 1. 停止
ps aux | grep -E "tsx src/index|concurrently.*backend|agents/bundled" | grep -v grep | awk '{print $2}' | xargs kill -9

# 2. 确认停止
ps aux | grep -E "tsx src/index" | grep -v grep

# 3. 重新启动（必须 debug）
npm run dev:debug
```

## 日志管理

### 查看日志


### 完全重置（删库重建）

```bash
# ⚠️ 慎用！会丢失所有配置、记忆、知识、技能/插件元数据
# 停止服务后执行
rm -f ~/.berry/data/agent.db ~/.berry/data/agent.db-wal ~/.berry/data/agent.db-shm
# 重启后 Drizzle ORM 自动 push schema，重建空数据库
```

### FTS5 索引损坏修复

**症状**：日志出现 `fts5: corruption found reading blob N from table "xxx_fts"`，导致对话/记忆写入全部失败（`saveConversationTurn 失败`、`user 消息入口入库失败`），conversations 等表永远是 0 行。

**根因**：直接 `DELETE FROM <fts>_data/_docsize/_idx` 影子表会破坏 FTS5 内部段结构。清空 FTS 必须用 `rebuild`。

**修复**（external-content FTS5 表，从内容表重建索引）：

```bash
DB=~/.berry/data/agent.db
# 1. 全局完整性检查定位损坏的表
sqlite3 "$DB" "PRAGMA integrity_check;"

# 2. 逐个重建损坏的 FTS 表（内容表为空时重建出空但有效的索引）
for fts in conversations_fts global_memories_fts agent_memories_fts workspace_memories_fts; do
  echo "rebuild $fts"
  sqlite3 "$DB" "INSERT INTO $fts($fts) VALUES('rebuild');"
done

# 3. 验证（integrity-check 无输出 = 正常）
sqlite3 "$DB" "INSERT INTO conversations_fts(conversations_fts) VALUES('integrity-check');"
sqlite3 "$DB" "PRAGMA integrity_check;"   # 应返回 ok
```

### Mission 清理

`~/.berry/missions/` 存放每个 mission 的 `plan.json` / `squad.json`。陈旧 mission 会持续触发 `brain:plan_stalled` 日志并干扰 Brain 路由决策。

```bash
# 查看陈旧 mission（按日期）
ls -la ~/.berry/missions/ | head

# 清理某天之前的 mission（例：清理 6月10日的）
rm -rf ~/.berry/missions/m-20260610-*

# 清理所有 mission（确认无在途任务后）
rm -rf ~/.berry/missions/*
```

## 常见故障排查

### 进程残留

```bash
# 查找残留进程
ps aux | grep -E "tsx src/index|concurrently|agents/bundled" | grep -v grep

# 批量清理
ps aux | grep -E "tsx src/index|concurrently.*backend|agents/bundled" | grep -v grep | awk '{print $2}' | xargs kill -9
```

### 数据库锁死

```bash
# 检查 WAL 文件大小（过大说明有未 checkpoint 的事务）
ls -lh ~/.berry/data/agent.db-wal

# 手动 checkpoint（进程停止后执行）
sqlite3 ~/.berry/data/agent.db "PRAGMA wal_checkpoint(TRUNCATE);"
```

### 端口占用

```bash
# 检查 3888 端口
lsof -i :3888
# 检查 3889 端口
lsof -i :3889

# 释放端口
kill -9 $(lsof -ti :3888)
```

### 数据库诊断

```bash
# 查看各表行数
DB=~/.berry/data/agent.db
for t in $(sqlite3 $DB ".tables" | tr ' ' '\n' | sort); do
  n=$(sqlite3 $DB "SELECT count(*) FROM $t;" 2>/dev/null)
  [ "$n" != "0" ] && printf "%-40s %s\n" "$t" "$n"
done

# 检查数据库完整性
sqlite3 ~/.berry/data/agent.db "PRAGMA integrity_check;"
```
