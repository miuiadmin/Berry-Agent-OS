# 运维手册

> 数据目录、备份、清理、双开护栏、故障排查、常驻形态。全部操作以 operator 身份执行；删除类动作不可逆，先备份。

## 1. 数据目录布局

缺省 `~/.berry/`（`APP_DATA_DIR` 覆盖）：

```
~/.berry/
├── sessions.db              # 唯一 SQLite 库（WAL 模式）
├── sessions.db-wal / -shm   # WAL 附文件（运行期存在，正常）
├── overlay.yaml             # 组合树覆写（缺省不存在 = 官方默认层）
├── project-aliases.json     # 项目根别名表（缺省不存在 = 零重定向；形如
│                            #   { "现根绝对路径": "记账根绝对路径" }——项目目录改名/移位后
│                            #   配它，记忆与项目域键续用旧根——见 §7 故障排查）
├── allowlist.json           # 审批对 allowlist 持久面（缺省不存在 = 首次落 allowlist 决策时建）
├── skills/                  # 技能目录（每子目录一份 SKILL.md）
├── exec/                    # 子进程登记簿（children.json——exec 域 spawn 的登记与
│                            #   boot 孤儿清扫面；分域行崩溃/卡死排查先看这里，见 §7）
├── mcp/                     # MCP 桥子进程登记簿（children.json；惰性——首装 MCP
│                            #   server 时才建）
├── lsp/                     # 语言服务器桥域（惰性——首配 lsp servers 并首连时才建）：
│                            #   children.json 子进程登记簿（boot 孤儿清扫同 mcp）+
│                            #   tmp/ 服务器临时文件钉域（TMPDIR 钉此处，防写 /tmp
│                            #   逃出可写根——external carrier 先例）
├── agents/                  # 用户全局子代理定义（*.md 散文件——声明式子代理发现
│                            #   四地之一，与项目层 .agents/agents 并列）
└── apps/                    # 应用面布局：装机子树 + 各行数据根
    ├── node_modules/        # npm 装机子树（--legacy-peer-deps --omit=peer）
    ├── git/                 # git 源克隆子树
    ├── sources.json         # 装机出处账本（源 URL/ref/装机 id 记录——uninstall
    │                        #   检视与对账依据；local 装机也记）
    └── <行id>/              # 各应用行数据根（data.json 认领桥与词表账本；
                             #   内含 tmp/ 子目录 = 件临时空间）
```

会话按**启动目录**归属：换目录即换会话序列。当前目录有哪些会话、续接哪条，由库内 sessions 表按 cwd 记录。

启动清扫：宿主每次启动会扫全体 `apps/<行id>/tmp/`，删除其中 mtime 超过 **7 天**的文件并剪除空目录（固定常数，无配置项；另一 berry 实例启动也会触发——含本实例运行中的场合）。这是件临时空间的 GC 语义：`tmp/` 无持久保证，件的正式数据放数据根其余位置，不要落 tmp。例外：`berry dump-config` 诊断命令（`:memory:` 库零落盘装配）不扫——清扫只在真实数据目录 + 持久库档的启动路径发生。

## 3. 备份

```bash
# 方法一（推荐）：停进程后整目录拷贝
cp -a ~/.berry ~/.berry.backup-$(date +%Y%m%d)

# 方法二：运行期 SQL 备份（含 WAL 合并，得到一致快照）
sqlite3 ~/.berry/sessions.db ".backup '/tmp/sessions-backup.db'"
```

不要只拷 `sessions.db` 而丢 `-wal`：运行期的最新写入可能还在 WAL 里。

方法二只备份数据库；`overlay.yaml`、`project-aliases.json` 等目录内配置文件不在 SQL 快照里——完整恢复请用方法一（整目录），或在方法二之外单独保存这几个文件。

注意：`credentials` 表存 provider 凭证（明文形态 + 数据库文件 0600 权限 + 预留加密 seam，pre-release 拍板）——**备份文件即含密钥**，备份产物按密钥保管（加密盘/受限权限），不要进同步盘或公开位置。

## 4. 清理与重置

按破坏性从小到大：

```bash
# 只清记忆（保留会话与技能）：memory_fts 是投影会自动跟随
sqlite3 ~/.berry/sessions.db "DELETE FROM memories; DELETE FROM memory_fts;"

# 只清跨会话检索索引（可重建，重启后自动对账补齐）
sqlite3 ~/.berry/sessions.db "DELETE FROM session_fts; DELETE FROM session_fts_state;"

# 清全部会话历史（保留记忆/goals/凭证/技能）
sqlite3 ~/.berry/sessions.db "DELETE FROM events; DELETE FROM sessions; DELETE FROM goals;"

# 整库重置（全新开始）
rm ~/.berry/sessions.db*
```

删除会话是 operator 动作——没有应用 API 能删会话（跨会话只读面故意无 delete 词汇）。

## 5. 双开与多机护栏

允许两个进程同时开（不同目录或同目录）：

- **WAL 模式**：读写不互斥，各进程经 WAL 看到彼此提交。
- **同会话单写者护栏**：会话头带 `incarnation:revision`，旧 incarnation 对已换代会话的写入会被拒——双开续接同一会话不会写花。
- 最稳的姿势仍是**一目录一进程**。

多机与网盘的边界（明示不支持，不是缺陷是立场）：

- Berry 是**单 operator 单活跃机**的个人系统：同一数据目录同一时刻只应有一个机器在写。
- 多机使用的正确姿势 = **单活跃机 + 他机只读冷备**：在他机上消费停机拷贝的备份（§3 方法一的产物），不做实时双活。
- **数据目录放网盘/云盘同步（Dropbox / iCloud / NAS 实时同步等）明示不支持**：SQLite 的 WAL 一致性协议建立在普通本地文件系统语义上，跨网络文件系统必然损坏——库损坏是文件系统真相，不是可修的 bug。备份产物进网盘没问题（它是静态文件），活跃库不行。

## 6. 日志

- 级别 `APP_LOG_LEVEL`（debug/info/warn/error）；`npm run dev` 缺省 debug。
- 进程日志只是观察面：审计与回放的权威载体是库内 durable 事件（`events` 表），不是日志文件。
- 排查应用装载：`berry dump-config`（只读不落库）——合成树、每行 activated/failed/skipped/unresolved 及原因、默认应用解析（带标清单 + 两跳回落链 + 缺场原因链）一次看全。
- **零遥测**：宿主默认不发任何网络包——无使用统计、无崩溃上报、无版本检查，你配置的模型调用是唯一出网流量。若未来引入回传：四段式公告（What/How/How to disable）先行、默认关闭（默认值反转视为 Breaking）、关闭通道机器可验证。

## 7. 故障排查

| 症状                                               | 原因与处置                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 启动即拒：`user_version` 高于已知                  | 库被更新版本写过。用对应新版本二进制打开，或备份后整库重置。不降级是设计行为                                                                                                                                                                                                                                                                                                                                                                                      |
| 启动断言：应用失败行清单                           | 失败处置两桶：**官方件行失败 = 拒启**（全家桶与宿主同仓同版本，失败即宿主 bug 不带病跑）；**第三方行失败 = 隔离降级**——平台照启，启动横幅点名 + 诊断文件 `<数据目录>/boot-failures.json`（行 id/错误码/栈/应用作用域，boot 批整替写）。`dump-config` 看行级原因（失败行在场退 1）；修 overlay（`disabled: true` 先隔离）；`APP_ENTRY_UNRESOLVED` 行需 `/apps-install` 装机 + `/apps-mount <装机id> --apps <应用id>` 挂载（两态：装机零生效，写行才进组合树）      |
| 官方件坏行锁死启动（TUI 起不来）                   | 安全模式自救：`berry --no-apps` 起最小内核（组合树空装只留 Ring 1 硬装配——TUI 无对话驱动但命令面/应用管理完好），修好 `overlay.yaml` 后 `/reload` 恢复全树；旗标只影响本次 boot，`/reload` 读盘不受它约束。`berry dump-config --no-apps` 同径看安全模式树（第三方行失败已隔离降级不锁启动——锁启动的只剩官方行/Ring 1 断言）                                                                                                                                       |
| `--port` 启动即拒（`WEBUI_PORT_IN_USE`）           | 端口被占——诚实失败非运行期警告。换 `--port <n>` 或停占用者（`lsof -nP -iTCP:<端口> -sTCP:LISTEN` 定位）；webui 行 `host` 配了非回环值同理拒启（`WEBUI_BIND_FORBIDDEN`——单机形态不开局域面）。缺省 `enabled: false` 零监听，不开 `--port` / 不配 overlay 即无此面                                                                                                                                                                                                  |
| `SESSION_FORMAT_UNSUPPORTED`                       | 读到了未知事件类型且非 ignorable——通常是用旧版本读新应用词汇写的库。用写它的那个版本组合打开                                                                                                                                                                                                                                                                                                                                                                      |
| 会话「丢」了                                       | 会话按 cwd 归属。回到原启动目录启动即续接；或查 `sessions` 表按 cwd 找                                                                                                                                                                                                                                                                                                                                                                                            |
| 记忆检索变慢                                       | `session_fts` 水位落后属正常（激活期对账 + 运行期增量）；重启自动对账补齐                                                                                                                                                                                                                                                                                                                                                                                         |
| Ctrl+C 没退出                                      | 多会话在跑时首次 Ctrl+C 是**打断聚焦会话的 run**（aborted 终值、不退 OS）——用 Ctrl+D 或 `/quit` 退出；单会话形态首次即优雅退出（等在途 run 结算），再按一次立即 130                                                                                                                                                                                                                                                                                               |
| 子代理任务卡住                                     | `/apps` 确认 subagent 行激活；Job 结算通知走 ui 三通道，看通知器；进程退出时 shutdown 序列会排空 jobs                                                                                                                                                                                                                                                                                                                                                             |
| 卸载提示行不在 / 「无动作」                        | `/apps-uninstall <id>` 裸调先检视（受影响会话计数与数据域体积在报告里），`--confirm` 才执行；回执「无动作」= 行不在且无残迹（已卸载过或从未安装），「残迹收尾」= 上次段间失败的收敛重跑——两者都是幂等合法终态非错误。Ring 1 底座行（当前 = tools）拒卸是设计行为                                                                                                                                                                                                  |
| `/reload` 没立即生效                               | run 进行中不拒而是排队——本次 run 结算后自动执行一次（连发合并），结果另行通知；失败时原组合仍在运行，修 overlay 后重试                                                                                                                                                                                                                                                                                                                                            |
| 项目目录改名/移位后旧记忆不见                      | 记忆按 canonical 工作区根记账，根变了即新键。在 `<数据目录>/project-aliases.json` 配 `{ "现根绝对路径": "记账根绝对路径" }`（键 = 移动后的新路径，值 = 原路径），重启后 canonical 根重定向，续用旧记忆                                                                                                                                                                                                                                                            |
| 分域行（worker/external 载体）崩溃 / OOM           | 该域死不伤宿主（故障域分域）：行状态转 failed（`/apps` 可见，与 `app/failed` 广播同源），**不自动重启是设计行为**——修好后 `/reload` 重装载。第一手死因在结算消息里（OOM 签名 = `reaching memory limit`，另有 `worker/oom` 活体事件；内存档 = 应用清单 `budget.memoryMb` 或宿主缺省 512MB——只限 JS 引擎堆）。`dump-config` 组合树带 `@worker` / `@external` 载体标注可核对行归属域；exec 域拉起的子进程登记在 `exec/children.json`（§1），宿主 boot 会按簿清扫孤儿 |
| 分域行卡死无响应                                   | 心跳丢拍（缺省 15s × 3 拍 ≈ 45s）判冻结 → watchdog 自动 kill 走意外死亡结算（`worker/froze` 事件）。装载期慢**不是**冻结——boot 冷启窗归 load 超时监督，两窗分治不互借判据；挂起族可判可杀、CPU 燃烧不可判（如实收窄）                                                                                                                                                                                                                                             |
| `--sandbox-host` 退出码 1（`SANDBOX_UNAVAILABLE`） | fail-closed 设计：平台无沙箱后端即拒跑——Windows 无后端；Linux 需安装 bubblewrap（Ubuntu 23.10+/24.04 需先放行 userns，三法见 §7.1）；macOS 用内建 seatbelt。不是 bug：去掉旗标即可跑，或在受支持平台/装好 bwrap 后再用。沙箱内可写面只含档位根与数据目录，报写入错误先核这两处                                                                                                                                                                                    |
| 分域行调用报 `BRIDGE_SURFACE_NARROWED`             | 设计行为非故障：分域行（worker/external 载体）五个 ctx 同步编排面（`parallel`/`serial`/`waterfall`/`registerMessageRole`/`registerSessionEventType`）不开放，服务调用是 RPC Promise 唯一形态——件编排逻辑改走服务调用 + 事件订阅（作者须知见[应用开发指南](应用开发指南.md)）                                                                                                                                                                                      |
| LSP 工具报「已熔断」/ 服务器不可用                 | lsp 件对单服务器 **3 连败熔断**（spawn/握手连续失败即记 dead，此后调用直接回「已熔断」不再重试）。修法：核对行 config `servers.<名>.command` 是**绝对路径**（相对路径在连接期即拒）、server 二进制可执行，改好 overlay.yaml 后 `/reload`（熔断态随行重置）。半途死掉的服务器子进程登记在 `lsp/children.json`（§1），宿主 boot 会按簿清扫孤儿——运行中孤儿可手动 kill 后 `/reload` 重连                                                                             |
| TUI `@` 补全不出文件路径                           | `@` 文件段依赖 [fd](https://github.com/sharkdp/fd) 可执行（PATH 上的 `fd`；Debian/Ubuntu 装 `fd-find` 后实名 `fdfind`，两者都认；win32 `fd.exe`）。缺失是诚实缺席不报错——文件段无建议、命令段与 `@路径#` 符号段（LSP 件在场时）不受影响。修法：装 fd 或设 `APP_FD_PATH` 指向兼容实现后重启（发现序在启动时探测，长命进程中途装 fd 须重启方可见）                                                                                                                  |

### 7.1 OS 沙箱后端部署（三平台）

`--sandbox-host` 宿主沙箱与 exec 沙箱三档共用平台后端，部署事实分平台如下（fail-closed：后端不可用即拒跑，不静默降级）：

- **Linux（bubblewrap）**：Ubuntu 23.10+/24.04 起 AppArmor 默认限制非特权 user namespace，**bwrap 开箱即坏**（典型症状：bwrap 自报 "bwrap: setting up uid map" 类错误、工具执行以 `EXEC_SPAWN_FAILED` 响亮失败——`SANDBOX_UNAVAILABLE` 只出现在 `--sandbox-host` 启动期后端链为空/探测全败的路径，不在 exec 执行期〔冷读闸 2026-08-29 勘正：单候选链构造期不预探测〕）——这是发行版安全策略，不是 Berry 的 bug。放行三法任选其一：
  1. **系统级放开**：`sysctl kernel.apparmor_restrict_unprivileged_userns=0`（写入 `/etc/sysctl.d/` 持久化）——最简单，代价是全系统放开该限制；
  2. **自定义 AppArmor profile**：仅对 bwrap 二进制授予 user namespace 权限（`userns,` 规则）——最小面放行，推荐多用户/在意攻击面的机器；
  3. **setuid 安装的 bwrap**：改用带 setuid helper 的 bubblewrap 构建/发行包——setuid 路径不依赖非特权 userns。
- **macOS（seatbelt）**：使用内建 `sandbox-exec`。Apple 将其标记废弃已近十年但**至今仍工作**，且无官方 CLI 替代（同类工具同依赖此路径）；若未来 macOS 版本实际移除，届时按 `SANDBOX_UNAVAILABLE` fail-closed 拒跑并跟进替代后端。
- **Windows**：当前无 OS 沙箱后端（`--sandbox-host` 直接 fail-closed）；write-restricted token 路线已在进程隔离规划中立项，落地前 Windows 平台不带 `--sandbox-host` 运行。

诚实边界一条（PoC 实证，CVE-2026-21711 同型）：external 分域行的 Node permission-model 中层只管文件系统路径访问与 addon，不管 `bind()` 创建 Unix domain socket 文件这条 syscall 路——实测写白名单外目录的普通文件被拒（`ERR_ACCESS_DENIED`）而同目录 UDS bind 通过。因此 PM 是叠加的中层、不是墙：external 域的执法面 = 进程墙（per-行 fork）+ OS 沙箱层（宿主基线 ∩ 行声明交集）；白名单内目录的 UDS bind + 回环通信正路可用（域 IPC 选型不受此判影响，判的是越界 bind）。

## 8. 升级

1. 备份（§3）。
2. 源码形态：`git pull && npm install && npm run build`。npm 分发形态（`npm i -g berryagent` 后 `berry --version` 核对）随首次 npm 发布生效（发布走 release 机器，六道契约见[开发指南](开发指南.md) §11）——升级同为「备份 → 换二进制 → 首次启动迁移链」序。

## 9. 常驻形态（daemon）——现行（刀一刀二已落码）

> 命令族与行为随第三十八批拍板（2026-08-30 刀一落码、同日刀二 attach/doctor 落码）生效。TUI / run / tick 仍为前台进程形态，终端关闭即触发优雅退出——daemon 是显式选择非迁移。

**为什么**：现状「宿主 = 唯一活进程」——终端一关（SIGHUP 优雅退出），在飞 run 中断、未决审批悬死、web 观看面消失。daemon 形态把执行体搬进单个常驻进程，webui HTTP/SSE 面随行常开（bind 127.0.0.1 + 缺省 7860 + 持久 token 鉴权）；TUI / 浏览器 / curl 全部退为纯客户端。TUI 进程内形态保持合法存续（短会话场景），与 daemon 是显式选择关系非迁移关系。

**命令族**（六命令 + 一旗标）：

```bash
berry daemon start        # 后台起 daemon：spawn detached + ready-gate（须 token 端点真握手成功才 exit 0，
                          #   超时响亮非零并杀子进程——「活」的唯一判据是真握手，不猜 pid）
berry daemon stop         # SIGTERM → 轮询确认消失（缺省 30s 预算）→ SIGKILL 兜底 → 清 daemon.json
berry daemon status       # 读 daemon.json + 真握手：会话清单 / 活跃 run 数 / 升级窗口可辨识
berry daemon doctor       # 常驻形态体检七项：pid 判活 / health+真握手+events 即连即关 / 僵尸态 /
                          #   token 0600（只读禁自造）/ 库 readonly+迁移版本 / 版本对齐 / 端口占用
                          #   （仅判死路——活 daemon 顶号是双开，非占用问题）；全绿 exit 0
berry attach              # 纯客户端接上 daemon：零本地装配零本地库，daemon.json 取端口 + token 只读；
                          #   SSE 流 + 断线指数退避重连（401 自停）；会话缺省选本工作区最近 active
                          #   （--port 覆盖端口）。审批卡照常呈现，按 id 重放应答；Ctrl+D 退 attach 时
                          #   在身卡留 daemon 侧待决（撤销不落拒绝账——重连/他腿应答/超时收场）
berry daemon --foreground # 前台常驻（launchd/systemd 监视直接子进程的唯一正确形态——自 fork 会双实例循环）
```

保活归 **OS 服务管理器**（macOS launchd LaunchAgent / Linux systemd --user + linger），不内置看护与自动重启；开机自启与 unit 生成随后续批次。

**鉴权**：token 一次生成落 `<数据目录>/daemon/daemon-token`（0600，手动轮换=删文件重启）；curl / TUI attach 走 `Authorization: Bearer`；浏览器首屏一次性引导（贴 token 换 HttpOnly cookie）。所有 API 端点无 token 一律 401（含 SSE 升级）；token 不进 URL / 查询参数 / CLI 参数。

**场景三句（诚实预期，落码后照此验收）**：

1. 「明早接着**看**」✓——durable 账 + 投影重拉，任何客户端任何时候（`berry attach` 接上即续流）。
2. 「明早接着**批**」止于首个夜间审批——无应答腿在场时审批 30min 超时 fail-closed 落 `'unavailable'`（run 吊死更糟，这是设计语义非缺陷）。精化：attach / SPA / 监控尾任一持 token 的活 SSE 连接在场 = 人在场，超时腿**不武装**（人在时干扰降发无意义）。
3. 「晚上继续**跑**」= **中断语义**非续跑语义——daemon 死则在飞 run 中断、账不丢（撕裂尾恢复兜底）、不自动续跑；goal 续跑链随宿主死（激活态不持久化是既有拍板）。

**撞持有的两触达面**：会话被活 daemon 持有（heldSessions 租约防双写者）时——`berry` 裸起 TUI 若续接撞持有，横幅示明改道（`berry attach` / `POST /api/sessions/:id/submit`）并另开新会话继续；`berry run --tick` 会话投递路撞持有则非零退 + 同款指引（不烧抢占，OS 钟下一跳重撞）。**裸 berry 检测** = 真握手成功是唯一正判——提示退出非零、不猜 pid。

**daemon 形态下全量 `/reload` 禁用**（活账撕裂防线——heldSessions 在飞时整袋回卷会悬空 SSE 活尾/审批竞速/在飞 run）；单区 `/reload --app <应用id>` 照常放行。

**macOS 合盖即 sleep，daemonize 不解**：合盖后 daemon 同样冻结——需要隔夜跑请配电源设置（防合盖睡眠 / 外接电源不睡）或 `caffeinate`，插电开盖是唯一稳妥姿势。不写明这条即是错误预期。

**升级程序（daemon 形态下）**：`berry daemon stop` → `git pull && npm install && npm run build` → `berry daemon start`。升级窗口 = 全部在飞 run 中断（`status` 可辨识），与「中断语义」同款诚实账。
