# 智能体架构

## 三级智能体

| 级别 | Agent | 类型 | 角色 | 职责 |
|------|-------|------|------|------|
| L1 | brain | 常驻 | reviewer | 每轮回复必经审核 |
| L2 | learning | 按需 | — | 发现可学习/沉淀的知识 |
| L2 | skills | 按需 | — | 创建和维护 SKILL.md |
| L2 | plugin-builder | 按需 | — | 生成和修改插件包 |
| L2 | code | 按需 | — | 代码阅读、修改、测试、重构 |
| L2 | evolution | 按需 | — | 能力进化提案与执行 |
| L2 | memory | 按需 | — | 深度记忆检索与整理 |
| L2 | skill-tester | 按需 | — | 验证技能质量 |
| L3 | conversation | 常驻 | primary, plugin-host | 直接与用户对话 |

## 核心组件职责

- **Berry Service** — 对外后台常驻服务
- **AppCore** — 服务内核运行时，编排 Agent Manager、IPC 路由、权限 token、审计落库
- **Agent Manager** — Agent 生命周期：启动、停止、重启、心跳、升级、状态查询
- **AgentRegistry** — Agent 发现与注册，维护 taskType/role 索引，路由任务到对应 Agent
- **AgentLifecycle** — 运行时热插拔编排：install/remove/upgrade/enable/disable

## Agent Manifest（agent.json）

```jsonc
{
  "apiVersion": "agent.v1",
  "name": "echo",                    // kebab-case
  "version": "0.1.0",
  "description": "描述",
  "level": 2,                        // 1|2|3
  "kind": "on-demand",              // resident|on-demand
  "source": "user",                 // bundled|user|generated|installed
  "taskTypes": ["echo_task"],       // 至少 1 个
  "roles": [],                      // reviewer|primary|plugin-host
  "entry": "entry.ts",
  "ipcProtocol": "module-agent",    // module-agent|custom
  "requiresBrainReview": false,
  "dependencies": [],
  "capabilities": {}
}
```

## 两种 Agent 模式

**常驻 Agent**（`startResidentAgent`）— brain、conversation：
- 长期运行，监听 IPC 消息
- 自定义协议处理多种消息类型

**模块 Agent**（`startModuleAgent`）— learning、skills、code、evolution、memory、skill-tester 等：
- 按任务启动，执行完退出
- 无状态，一个 handler 处理一个 task

## IPC 消息类型

| 类别 | 消息 |
|------|------|
| 生命周期 | `agent.register`, `agent.heartbeat`, `agent.shutdown` |
| 对话流 | `user.message`, `draft.response`, `final.response` |
| Brain 审核 | `review.request`, `review.result` |
| 权限 | `permission.request/result/validate/consume` |
| 任务 | `agent.task`, `agent.task.result`, `task.progress` |
| 记忆 | `memory.query`, `memory.add`, `memory.delete` |
| 模型控制 | `model.override`, `model.takeover.request` |
| 插件 | `plugins.register_tools`, `plugin.execute/result` |

## Brain 审核流程

1. Conversation Agent 生成草稿 → `draft.response`
2. Core 按复杂度分级（A/B/C）→ `review.request` 发给 Brain
3. Brain 返回 `review.result`（approve/modify/reject）
4. Conversation 发出 `final.response`

分级标准：A 级（< 800 字无工具）快速审核；B 级（< 3200 字或有工具调用）完整审核；C 级（> 3200 字）详细分析。

## 对话内联呈现（见 [`设计文档/22-对话内联统一.md`](../设计文档/22-对话内联统一.md)）

工具调用 / MCP 调用 / 子 Agent 委派**全部内联进对话流**，对齐 Claude Code 与 OpenCode：

- 一条消息 = 有序 `Block[]`（`text` / `thinking` / `tool` / `delegation` / `review`），存于 `messages` + `message_blocks`。
- 工具调用是 `tool` block（4 态机：pending→running→completed/failed），MCP 与普通工具同源。
- Brain→Code 等**委派是内联 `delegation` block**（状态 + 摘要），子 Agent 内部对话是**可展开的嵌套会话**（`childSessionId`），取消独立 agent 对话面板。
- 中间产出统一为 `stream.block` 事件族，前端 `blocks.map` 内联渲染。Missions 仍保持独立背景概念。

## Agent 工作目录

```
~/.berry/agents/{agent-name}/
├── agent.yaml            # 机器配置（AppCore 生成）
├── AGENT.md              # 人类可编辑指令
├── capabilities.json     # 路由能力声明
├── state.db              # 局部状态（其他 Agent 不可读）
├── runtime/              # 运行时工作目录
├── tasks/{task_id}/      # 每个任务独立目录
│   ├── task.json         # 冻结输入镜像（仅 AppCore 可创建）
│   ├── context.json
│   ├── transcript.jsonl
│   └── outputs/
├── cache/
└── logs/
```

**规则：**
- Agent 不得私自创建任务目录绕过路由
- 工作目录不能作为跨 Agent 通信通道，协作必须通过 `AgentTaskRequest`
- Code Agent 额外包含 `patches/`、`test-runs/`、`sdk-runs/`
- Plugin Builder 额外包含 `plugin-drafts/`、`validator-runs/`

## 任务状态机

```
created → persisted → dispatched → acknowledged → running → completed
                                                         ↘ failed
                                                         ↘ timeout
                                                         ↘ cancelled
```
