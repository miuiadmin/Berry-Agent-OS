# 测试规则

> BerryAgent 测试策略：三层分明，不造假信心

## 三层测试架构

| 层级 | 类型 | 运行时机 | LLM | 目标 |
|------|------|---------|-----|------|
| 1 | 单元模块测试 | 每次 commit / CI | 无（纯逻辑） | 验证函数、类、模块的确定性行为 |
| 2 | 1-to-1 测试 | 每次 CI | mock/takeover | 验证单个模块与其真实依赖的协作，不启动完整系统 |
| 3 | 真实测试 | Nightly / 手动 | 真实模型 API + 真实 HTTP 服务 | 像前端一样调用 CRUD API，做真实对话测试 |

---

## 第 1 层：单元模块测试

**范围：** 纯逻辑模块，无外部依赖或依赖已被 vitest.mock() 替换。

**规则：**
- 使用 `:memory:` SQLite（不读磁盘）
- 不启动 CoreService，不创建 socket
- 不调用真实模型 API
- 一个测试文件对应一个源文件
- 只测本模块公开 contract，不 import 其他模块内部实现
- 断言确定性输出，不断言 AI 生成内容

**命名：** `<module>.test.ts`，与源文件同目录。

**示例场景：**
- Schema 校验（manifest 解析、config 解析）
- 数据库迁移（表创建、字段约束）
- 纯计算函数（ID 生成、路径拼接、格式化）
- 注册表增删查（AgentRegistry.register/unregister）
- 事件总线分发（EventBus.emit/on 回调触发）

---

## 第 2 层：1-to-1 测试

**范围：** 验证单个模块与其真实依赖的协作，不启动完整 CoreService 系统。LLM 调用被 mock/takeover 截断。

**规则：**
- 可使用真实 SQLite（hermetic 临时目录），不使用 `:memory:` — 验证真实文件 I/O
- LLM 模式为 `mock` 或 `takeover`，不调用真实模型
- 可启动部分服务（如单独的 Agent 进程、单独的 HTTP 路由），但不启动完整 CoreService
- 断言 DB 状态链路、文件系统副作用
- 超时设置宽松（15-30s）
- 必须使用 hermetic 环境

**命名：** `<module>-e2e.test.ts`

**示例场景：**
- 单个 Agent 生命周期（install → enable → disable）
- 单个 Agent 执行真实任务（file-editor 修改文件、echo 回显）
- Socket handler 路由（特定 `agents.*` 命令）
- 权限拒绝/通过链路
- 单模块 DB 状态一致性验证
- 插件加载/验证/执行（不启动完整系统）

**与旧"集成测试"的区别：** 旧 Harness E2E 测试启动完整 CoreService + 所有 Agent 进程，是重量级全系统测试。1-to-1 测试只验证目标模块与其直接依赖，不启动完整系统，更快更聚焦。

---

## 第 3 层：真实测试

**范围：** 真实启动完整后端 HTTP 服务，使用真实模型 API，**通过 HTTP CRUD 接口**（与前端完全相同的方式）进行端到端对话测试。

**核心原则：必须像前端一样调用 API。** 真实测试不使用 harness 内部方法（如 socket `sendMessage`），而是直接调用 HTTP API 接口，验证从 HTTP 请求到响应的完整链路。

**规则：**
- 真实启动后端 HTTP 服务（Hono + WebSocket）
- 使用真实模型 API（`BERRY_LLM_MODE=live`）
- **通过 HTTP API 端点进行所有交互**，包括：
  - `POST /api/conversations` — 创建对话
  - `POST /api/conversations/:id/messages` — 发送消息
  - `GET /api/conversations` — 列出对话
  - `GET /api/conversations/:id` — 获取对话详情
  - `GET /api/conversations/:id/messages` — 获取消息历史
  - `DELETE /api/conversations/:id` — 删除对话
  - `GET /api/agents` — 列出 Agent
  - `GET /api/agents/:id/status` — Agent 状态
  - 其他所有公开 CRUD 端点
- 依赖环境变量 `BERRY_TEST_LIVE_API_KEY`（或 `LLM_API_KEY`）
- 无 key 时自动 skip（`describe.skipIf`）
- 不断言具体内容（模型输出不确定），只断言：
  - HTTP 状态码正确（200/201/204 等）
  - 响应 JSON 结构符合契约（字段存在、类型正确）
  - 响应非空
  - 无 error 返回
  - 对话能保持上下文（多轮消息关联同一 session）
  - WebSocket 事件与 HTTP API 状态一致
  - **对话内联（[22 号文档](../设计文档/22-对话内联统一.md)）**：工具调用 / MCP / 委派作为 `Block` 内联在消息里——断言 `GET /api/sessions/:sid/timeline` 返回的 message 含正确 `block_type` 与 `state`（如 `tool` block 最终 `state='completed'`），断言 `stream.block` 事件按 `blockId` 幂等推进；**不断言 AI 生成的具体文本 / 工具入参字符串**
- 超时宽松（60-120s），因模型推理耗时
- CI 中作为 nightly job 运行，不阻塞普通 PR

**运行方式：**
```bash
# 手动运行（通过 berry test real CLI，它内部建立 hermetic 环境并启动真实后端）
BERRY_TEST_LIVE_API_KEY=<key> LLM_BASE_URL=<url> LLM_MODEL=<model> \
  berry test real

# 或使用项目默认配置
LLM_API_KEY=tp-xxx berry test real
```

**模板：**
```typescript
import { describe, expect, it } from 'vitest';

const HAS_KEY = !!(process.env.BERRY_TEST_LIVE_API_KEY || process.env.LLM_API_KEY);

// 直接 fetch 后端 HTTP API（与前端完全相同的方式），不依赖任何 harness 包装类
const BASE = process.env.BERRY_TEST_BASE_URL ?? 'http://localhost:3888';

async function api(path: string, init?: RequestInit) {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: { 'content-type': 'application/json', ...(init?.headers ?? {}) },
  });
  if (!res.ok) throw new Error(`${path} -> ${res.status}`);
  return res.status === 204 ? null : res.json();
}

describe.skipIf(!HAS_KEY)('真实测试 — HTTP API 对话', () => {
  it('通过 API 创建对话并发送消息', async () => {
    const conv = await api('/api/conversations', { method: 'POST', body: '{}' });
    expect(conv.id).toBeTruthy();

    const msg = await api(`/api/conversations/${conv.id}/messages`, {
      method: 'POST', body: JSON.stringify({ content: '你好' }),
    });
    expect(msg.response?.length).toBeGreaterThan(0);
  }, 90_000);

  it('多轮对话保持上下文', async () => {
    const conv = await api('/api/conversations', { method: 'POST', body: '{}' });
    await api(`/api/conversations/${conv.id}/messages`, {
      method: 'POST', body: JSON.stringify({ content: '请记住数字 42' }),
    });
    const reply = await api(`/api/conversations/${conv.id}/messages`, {
      method: 'POST', body: JSON.stringify({ content: '我刚才说的数字是什么？' }),
    });
    // 不断言具体回复内容，只断言结构
    expect(reply.response?.length).toBeGreaterThan(0);
  }, 120_000);

  it('列出对话、获取详情、删除', async () => {
    const conv = await api('/api/conversations', { method: 'POST', body: '{}' });

    const list = await api('/api/conversations');
    expect(list.some((c: any) => c.id === conv.id)).toBe(true);

    const detail = await api(`/api/conversations/${conv.id}`);
    expect(detail.id).toBe(conv.id);

    await api(`/api/conversations/${conv.id}`, { method: 'DELETE' });
    const afterDelete = await api('/api/conversations');
    expect(afterDelete.some((c: any) => c.id === conv.id)).toBe(false);
  }, 60_000);
});
```

## 前端 E2E 测试（Playwright）

> 前端 E2E 测试是独立于三层架构的补充验证，测试 Web UI 渲染和交互，不走 HTTP API 对话链路。
> **注意：Playwright 尚未安装，此部分为规划中的测试方向，待落地。**

**范围：** 启动后端 + 构建后的前端，在真实浏览器中验证 Web UI 行为。

**工具：** Playwright（待安装到 `web/package.json` devDependencies）

**规则：**
- 测试文件位于 `web/e2e/` 目录
- 不依赖真实模型 API — 后端以 mock/takeover 模式启动
- 验证页面路由、WebSocket 连接、组件交互、暗色/亮色主题、响应式布局
- 移动端专项：侧边栏 overlay 导航、触控目标 ≥ 44px、hover 适配、iOS 安全区域

**运行：**
```bash
npx playwright test --config web/playwright.config.ts
```

## 禁止的测试模式

以下模式提供虚假信心，不允许出现：

1. **Mock 中间层测试** — 对 mock 了所有依赖的高层模块做断言（如 mock AgentManager + mock DB 测试 CoreService 逻辑）。这类测试只验证 mock 的行为，不验证真实系统。
2. **断言 AI 输出内容** — 不要在单元/1-to-1 测试中 expect 模型生成特定文本。模型输出不确定，这类断言会随模型更新而脆弱地失败。
3. **跨模块 import 内部实现** — 测试只能依赖目标模块的公开 contract，不 import 私有函数。
4. **无 hermetic 环境的测试** — 1-to-1 / 真实测试必须用临时目录，不能读写 `~/.berry`。
5. **真实测试使用内部 API** — 第 3 层真实测试必须通过 HTTP CRUD 接口交互，禁止使用 harness 的 `sendMessage` 等内部 socket 方法。

## 环境与基建

### Hermetic Environment

所有非单元测试必须在隔离环境运行：
- 临时 `BERRY_HOME`（`mkdtempSync`）
- 清除 `ANTHROPIC_*`、`CLAUDE_*`、`OPENAI_*` 环境变量
- 固定 `TZ=UTC`、`LANG=en_US.UTF-8`
- 测试结束后清理临时目录

### 1-to-1 测试与 hermetic 环境

1-to-1 测试（`<module>-e2e.test.ts`）通过 `createHermeticEnv`（`src/testing/hermetic-env.ts`）建立隔离环境：临时 `BERRY_HOME`、清除厂商环境变量、固定 `TZ=UTC`，结合 takeover/mock LLM 模式（`TakeoverController`，`src/testing/model-takeover.ts`）截断真实模型调用。`TakeoverController` 是生产代码 `bootstrap.ts` 在 `llm.mode==='takeover'` 时实例化的控制器（不是仅测试用），1-to-1 测试通过它注入确定性的模型响应。

### Real Test Profiles（`src/cli/real-test-profile.ts`）

真实测试凭据解析（由 CLI `berry test` 命令调用）：
- 优先 `BERRY_TEST_LIVE_*` 环境变量
- 回退 `LLM_*` 环境变量
- 再回退项目 config 默认值
- `applyRealTestEnv()` 设置 `BERRY_LLM_MODE=live` + hermetic home

## 运行命令

```bash
npm test                                    # 全部（真实测试无 key 会 skip）
npm test -- --watch                         # watch 模式
npm test -- src/kernel/agent-lifecycle.test.ts  # 单文件
npm run typecheck                           # 类型检查（提交前必过）

# 真实测试（需 API Key，通过 berry test real CLI 跑）
BERRY_TEST_LIVE_API_KEY=<key> berry test real
```
