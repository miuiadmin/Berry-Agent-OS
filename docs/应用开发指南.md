# 应用开发指南

> 面向应用作者：应用形状、inject 服务面、扩展点词汇、组合树、生命周期、应用数据、调试与反模式。

## 1. 应用形状（单形状纪律，钉死）

一个应用 = 一个入口模块，**唯一合法形状是一种函数**：

```ts
// entry.ts（入口解析序：harness.extensions → extensions/index → index）
import { Type } from 'typebox'; // 宿主实例经虚拟注入，勿自装第二份（双实例防线）

export const name = 'my-app'; // 必填：日志归因标识（非空字符串）
export const inject = ['tools', 'prompts']; // 硬依赖服务：全就绪才激活，缺 = 响亮失败
export const optionalInject = ['llm']; // 软依赖：不阻塞激活，ctx.tryGet 探测
export const config = Type.Object({
  // 可选：行配置 schema（启动时一次性校验）
  greeting: Type.Optional(Type.String()),
});
export const events = [
  // 可选：自定义活体事件声明（总线词汇）
  { name: 'my-app/tick', mode: 'emit', note: '周期心跳' }, // name 小写含 '/'
];

export default async function apply(ctx, cfg) {
  // 一切注册走 ctx.effect —— 作用域 LIFO 回卷即注销，/reload 卸载半边自动干净
  const tools = ctx.get('tools');
  ctx.effect(() => tools.register({/* ToolDefinition */}));
}
```

规则：

- **零 import 约束（装载期门禁执法）**：文件应用的 entry.ts 及其**全部依赖图**不能 import 宿主内部实现——可 import 的白名单三道：① 虚拟面六键 `berryagent`（contracts 公共面：AppError / 错误码 / 事件常量与目录 / **ctx 面与服务面契约类型（`AppContext` / `ToolsService` / `PromptsService` 等）**）、`typebox` 三入口（宿主注入同实例，防双实例）、`berryagent/llm`（provider 工厂面：`createProvider` / `hasApi` / `lazyApi` / `anthropicMessagesApi`——写 provider 应用用宿主同版本工厂，勿自捆 pi-ai）、`berryagent/sqlite`（`openDatabase(path)` 开自管库——宿主同实例 better-sqlite3，**主库路径拒开**（`APP_MAIN_DB_FORBIDDEN`），自管库读写全权含建表迁移）；② `node:` 内建（裸名 `path` 等同放行）；③ **应用目录树内**（相对路径与自带 `node_modules`——自身依赖自捆分发是正路）。越界即拒载 `APP_IMPORT_FORBIDDEN`（import 了未使用也拦——解析对账不等使用；错误消息附六键清单与指路）。子路径（如 `berryagent/typebox`）不在白名单——同样被拦，消息列出全部可用键。
- **类型直取**：`import type { AppContext, ToolsService, GateInput } from 'berryagent'` ——ctx 与服务面类型不再需要局部重声明（编辑器/tsc 解析随 npm 分发批提供 `.d.ts`；当前在包外项目里可先 type-only 引用或 `any` 起步，装载期虚拟注入保证运行时正确）。
- 形状违例（default 非函数 / name 缺失 / inject 非字符串数组 / config 非对象 schema）→ `APP_SHAPE_INVALID`，装载即拒。
- apply 抛错 → 加载器先 LIFO 回卷已激活件、再进失败清单；**失败处置两桶**：官方件行失败 = 启动断言拒启（全家桶与宿主同仓同版本，失败即宿主 bug 不带病跑）；**第三方行失败 = 隔离降级**——你的应用装坏了不拖死平台启动，但启动横幅与诊断文件 `<数据目录>/boot-failures.json`（行 id/错误码/栈/应用作用域）会点名，`app/failed` 事件照发——修好后 `/reload` 即回。
- 官方件（`builtin:memory` 等）与文件应用完全同轨装载，只是不经 jiti（宿主随包函数引用）。

## 2. ctx 面速览：核心原语与 inject 服务

### ctx 核心面（context 模块）

| 成员                                                         | 语义                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ctx.effect(fn)` → Disposer                                  | 可逆注册的统一挂点——fn 返回的清理函数入栈，作用域 LIFO 回卷即注销                                                                                                                                                                                                                                                     |
| `ctx.on(event, handler, { prepend? })` → Disposer            | 订阅钩子（清单见 §3 钩子速览）；词汇须在目录或自声明——拼错名 `EVENT_UNKNOWN` 响亮失败                                                                                                                                                                                                                                 |
| `ctx.emit` / `ctx.parallel` / `ctx.serial` / `ctx.waterfall` | 事件四模式——mode 是事件契约的一部分，声明 mode 与派发法不一致抛 `EVENT_MODE_MISMATCH`                                                                                                                                                                                                                                 |
| `ctx.get(name)`                                              | 必需服务解析——缺即 `CONTEXT_SERVICE_NOT_FOUND`（装配错误语义）                                                                                                                                                                                                                                                        |
| `ctx.tryGet(name)`                                           | 软依赖探测——缺返回 undefined；禁轮询重试/鸭子探测                                                                                                                                                                                                                                                                     |
| `ctx.provide(name, impl)` → Disposer                         | 发布具名服务供他应用 inject；第三方行名必含恰一 `/` 域前缀                                                                                                                                                                                                                                                            |
| `ctx.registerMessageRole(name, def)` → Disposer              | 自定义消息角色（名必含 `/`；未注册角色的消息在 LLM 边界蒸发并记 debug）                                                                                                                                                                                                                                               |
| `ctx.registerSessionEventType(def)` → Disposer               | 自定义 durable 词汇——`ctx.sessions.appendEvent` 的钥匙                                                                                                                                                                                                                                                                |
| `ctx.fork({ name, config? })` → 子 ctx                       | 应用内部组织原语（三律见下节）                                                                                                                                                                                                                                                                                        |
| `ctx.config`                                                 | 本行配置只读快照（经你声明的 schema 校验后冻结）                                                                                                                                                                                                                                                                      |
| `ctx.host`                                                   | 宿主自省面（只读，问宿主而非探测猜）——`version` 宿主包版本 / `apiVersion` API 面独立号 / `formFactor` 运行形态（standalone/daemon）/ `capabilities.has(name)`·`list()` 本构建面能力集（有无是构建面问题，非组合树挂载态——两问不混）/ `experimental.enabled(name)` 实验键在场且启用的探针（启用义务见下文清单 api 块） |
| `ctx.rowId`                                                  | 本行 id——数据目录键的正规取值口（禁从应用名自推）                                                                                                                                                                                                                                                                     |
| `ctx.logger`                                                 | 带作用域前缀的子 logger                                                                                                                                                                                                                                                                                               |
| `ctx.signal`                                                 | AbortSignal——作用域销毁时触发，长任务/定时器对齐监听                                                                                                                                                                                                                                                                  |

### inject 服务面（ctx.get / ctx.tryGet）

| 服务名                 | 面                                                     | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tools`                | `register(def: ToolDefinition): Disposer`              | 贡献模型可见动词。注册即 tools_change → 活跃 loop 工具集原位刷新。**可见性随行作用域**（狗粮实证）：挂 `apps` 的行注册落该**应用域层**——只有所挂应用的驱动可见（`listFor(appId)` 读面 = 全局层 ∪ 该域层），全局裸行注册才进全局层                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| `llm`                  | `complete()` / `canAfford()`                           | 单发补全唯一合法路径（不走 loop；禁收 apiKey）；canAfford 预算闸门——后台低优先级活必须先问                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `exec`                 | `exec(cmd, args, opts)`                                | 子进程执行原语（Ring 1 exec 件）：内部合成 def 走同一三段管道——守门/沙箱/durable 落账不旁路；返回结构化 `ExecResult`（exitCode / stdout / stderr / 60KiB 保尾截断标记 / sandbox 归因）；守门拒绝/超时一律 throw `AppError`（调用方是宿主侧代码，异常面比模型面的结构化拒绝更有用）                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `fetch`                | `fetch(url, { caller, signal })`                       | 出网抓取原语（web 件）：与模型面 `fetch` 工具同一 execute 同一卫生件（私网拒/限流/字节预算/重定向逐跳），内部合成 def 走同一三段管道——守门/durable 落账不旁路；返回结构化 `WebFetchResult` 九字段（url/finalUrl/status/contentType/text/bytes/truncated/redirects/durationMs）；`caller` 必传应用名（归因进 durable details——服务被调时调用方身份结构性不可知，显式声明是唯一诚实形态）；SSRF/超跳等异常 throw `AppError`（WEB_* 码族）。另有 `downloadToFile(url, { destPath, allowedHosts, caller })` 装机下载原语：流式落盘 + SHA256 记档（512MiB 独立预算，超限删档不截断交付）——`allowedHosts` 域白名单必传（装机域钉死面，首跳与每跳重定向都过），不走三段管道（装机命令面非模型面）；官方消费先例 = browser 件 `/browser install` |

| `ui`                   | `notify()`                                             | UI 通知（三通道自适应：通知器/时间线/状态行）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

| `apps`                 | `list()` / `install()` / `mount()` 等                  | 应用管理服务（装机/挂载/更新/卸载——两态动词面；组合树为枚举唯一事实源）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

`inject` 是 Kahn 硬依赖（轮次激活：声明即等待，无解响亮失败）；`optionalInject` 是软依赖（激活后 `ctx.tryGet` 探测，缺省 undefined 自行降级）。

### ctx.fork：应用内部组织原语（已落码）

复杂应用的长生命周期子结构（per-任务态、per-面板注册集、缓存分代）不需要拿 effect 模拟——`ctx.fork({ name, config? })` 派生一个**持完整 ctx 面**的子作用域（effect/on/provide/两注册面全可用，撞名域与事件词汇执法同父同规）：

- **继承律（只继承不可自选）**：rowId/行籍/区身份全随父级联——fork 出的作用域仍是你的行，无法借 fork 造出官方名位作用域。
- **回卷律**：子作用域显式 `dispose()` 或父卸载（/reload）都级联回卷子树全部 effect（LIFO）；宿主有兜底接线，忘显式销毁也不泄漏。
- **护栏**：单作用域直系子代计数帽 128，超帽抛 `CONTEXT_FORK_LIMIT`（fork 循环防线）；子 dispose 即释放名额（循环 fork+dispose 不误伤）。

典型用法：长任务各自 fork（结算即 dispose，注册面整树回卷）、多面板各持一个子作用域（面板关闭即回收其全部注册）。

### API 稳定性与兼容性（面分级 / 废弃机制）

你 import 的 `berryagent` 虚拟面是**分级承诺面**——每个符号带三级标签之一：

- **stable**：minor 只增不破（你依赖的主力层）；
- **experimental**：任意 minor 可破可删（试新可以，别托付生产）；
- **deprecated**：废弃窗内（替代指引与死期随符号公告）。

符号级清单见 [API 参考](API参考.md)（从面快照自动生成，构建期再生——永远与代码同步）；跨版本变更与判级见仓库根 [COMPATIBILITY.md](../COMPATIBILITY.md)（逐版 diff 自动判级：销账 / MAJOR / MINOR）。

**清单 api 块（版本协商声明——装载门读清单不读你的代码）**：`.app.yaml` 可声明 `api` 块三字段，向宿主声明你锚定的 API 面：

- `minApiVersion`（块在场即必填，`MAJOR.MINOR` 形如 `"1.0"`）：**硬地板**——宿主 API 面版本低于它即拒载 `API_VERSION_MISMATCH`（错误消息带升级指引）；
- `targetApiVersion`（可选）：**行为锚**——缺省 = min 粘性锚（不声明恒持 min 时点的面与行为；「跟新」从来不是缺省，升 target 是显式发布动作）；
- `experimental`（字符串数组）：**实验键启用声明**——`import` experimental 级虚拟键而未在此点名 = 装载期拒 `API_EXPERIMENTAL_UNDECLARED`（契约即知情：能用可破面 = 你签了字）。

**必填预告**：pre-release 窗口内 api 块缺席 = legacy 容忍态（启动诊断聚合 warn，不影响装载）；**首个正式版（dist-tag=latest）发布起 api 块必填——缺席即拒载**。第三方应用现在就写上 `api: { minApiVersion: "1.0" }` 是零成本免疫（与宿主同仓的官方清单同款声明）。

废弃走**登记制**：每个 deprecated 符号有 DEP 编号（登记进注册簿）+ 死期（`introducedIn` 起至少 3 个 minor 窗）+ 替代指引（`replacement` 非空——废弃不给替代是断头路）。你的应用无需人工跟踪：`berry apps check` 一命令出全部已装应用 × 当前 apiVersion 的三色体检（✓ 通过 / ⚠ 用废弃·带替代指引与死期 / ✗ 断裂·带首错位置与升级指引），废弃使用另有遥测聚合。

请求尾注入的标准姿势：订阅 `context_transform`（瀑布钩子，`ctx.on` 直接可订）——每 handler 至多追加一条消息，`memory/recall` / `memory/diff` 即此形态。注入消息用自定义角色时先经 `ctx.registerMessageRole` 注册（`toLlm` 定义 LLM 边界转换——建议映射为防注入句式包裹的 user 消息，`render: {intent:'hidden'}` 不进时间线）；轻量替代 = 直接追加原生 user 角色并自带包装句式（免注册，但语义上是机器注入伪装用户轮）。注意：未注册角色的消息在 LLM 边界被静默过滤并记 debug 日志（角色名入日志）——自造角色名不注册会蒸发。

### 活体总线词汇速览（27 词全目录；mode 标在词后）

唯一真源 = `src/contracts/events.ts` 的 `LIVE_EVENT_CATALOG`（`check-events` 门禁对目录与派发点双向断言——本表是它的展开速览，非另一份账；表词集与标题计数亦由门禁第五族对照锁死，手改一边 CI 即红）。`ctx.on` 可订全部目录词汇；`waterfall` 钩子不调 `next()` 即短路（工具管道三段与守门拦截依赖此语义）。

| 层                 | 词汇                                                                                                                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话（3）          | `session/event`（emit，durable 镜像·hostReserved 旁听）/ `session_start`（emit）/ `session_shutdown`（parallel）                                                                                                                   |
| 工具管道（4）      | `tools_pre_execute`（waterfall，守门段）/ `tools_execute`（waterfall，执行段·hostReserved）/ `tools_post_execute`（waterfall，审计段）/ `tools_change`（emit，工具集变更）                                                         |
| 消息/轮次（4）     | `context_transform`（waterfall，喂给模型的历史变换）/ `user_input`（waterfall，单条用户消息变换）/ `turn_stopping`（serial，run 结算后征询续跑）/ `agent_pre_step`（waterfall，进模型步前复验——短路 `{stop:true}` = run 正常收场） |
| 注册面变更（2）    | `prompts_change`（emit，系统提示词段集变更）/ `skills_change`（emit，技能提供方链变更）                                                                                                                                            |
| 任务（1）          | `job_settled`（emit，后台任务结算）                                                                                                                                                                                                |
| 生命周期（4）      | `app/activated` / `app/failed` / `app/skipped` / `app/uninstalled`（均 emit——宿主发射，应用只订阅）                                                                                                                                |
| 宿主机制/观测（5） | `approval/answer`（waterfall·hostReserved，审批决议位）/ `composition/reloaded`（emit，组合树就绪信号）/ `worker/spawned` / `worker/froze` / `worker/oom`（均 emit——分域舰队观测锚）                                               |
| 测试资产（4）      | `echo/tick`（emit）/ `echo/par`（parallel）/ `echo/ser`（serial）/ `echo/wf`（waterfall）——金样/收窄探针词汇，产品面零派发                                                                                                         |

注：hostReserved 三词（`session/event` / `tools_execute` / `approval/answer`）是宿主机制位——非官方行籍 `on/emit` 即抛 `EVENT_HOST_RESERVED`（旁听需官方行位）；其余词汇第三方行均可订。总线词汇另有**应用声明层**：官方件自有词经件 `events` 声明装载期登记（在树首例 `obs/alert`，可订阅联动）——词汇承诺位在各件声明，不在本表（本表是对宿主目录的承诺面）。

## 4. 组合树

默认层（官方全家桶，随包）+ 用户 overlay 合成，**字段级后写胜出**：

```yaml
# ~/.berry/overlay.yaml（文件不存在 = 纯默认层，首启零配置即合法）
rows:
  - id: memory # 替换官方行：省略 pkg = 沿用官方引用，只改其余字段
    config: { recallTopK: 5 }
  - id: memory-strict # insert 行必须自带 pkg
    pkg: builtin:memory
    config: { unusedDays: 14 }
  - id: goal # 禁用官方行（真·可卸）
    disabled: true
  - id: darwin-only-thing # 平台门控 + 第三方行范例（必挂 apps + sandbox 块）
    pkg: ./apps/my-thing
    apps: [chat] # 第三方行必填——挂应用作用域（多元素 = 多应用共享件）
    sandbox: { carrier: main } # carrier 三值 main | worker | external
    disabled: darwin
```

- 行字段：`id` / `pkg` / `config` / `disabled` / `fixed` / `sandbox` / `apps`——未知字段拒绝式（pre-release 纪律）。`sandbox` 块（沙箱声明）：`carrier` **必填**三值枚举 `main | worker | external`（main = 主线程直载；worker = 宿主内 worker 线程域；external = per-行 fork 进程域——进程墙隔离，第三方件缺省档），`net` 声明即拒（网络面 v1 不开放）、`fs`/`caps` 纯对象；半块（缺 carrier）机器拒写；`builtin:` 官方行声明 sandbox 块（任何 carrier）= 拒——官方随包件恒主线程。`apps` 键 = 作用域（数组、元素 = 在册应用清单 id）：缺省挂全局作用域（**v1 官方专属**——第三方行不带 `apps` 直接拒绝式拦下，见下方专节）；多元素 = 同一实例服务多应用（挂载只是可见性投影）。
- **Ring 1 必备行**（`tools` 起算，随行树化逐行累加）：组合树必备行**可换实现不可禁用**——overlay 禁用/平台门控/引用解析失败 = 启动断言拒启（`COMPOSITION_ROW_INVALID` 带修法指引）；要换实现请替换行 `pkg` 引用（新件须 provide 同名服务，工具行还须携带管道 executor）。此类行挂宿主独立装载锚：**/reload 不回卷**，行合成结果变化在 `composition/reloaded` 载荷以 `ring1RestartRequired` 报告（重启后生效，不静默吞）。
- `config` 整体替换不做深合并，经应用声明的 schema 启动时一次性校验。运行期改配置两条路：模型面 `apps_configure` 工具（patch 按顶层键整值替换——要改哪些键带哪些键，未列出键保持现值；校验不过即拒不落盘，防错配置写盘后下次启动拒启）或直接编辑 overlay 后 `/reload`。
- 文件应用 `pkg` 字段：包名（装入 `<数据目录>/apps/node_modules` 子树）或显式相对/绝对路径；入口解析序 `harness.extensions` → `extensions/index` → `index`。
- **分发 = npm 三源**（无自定义容器格式）：npm registry 包名 / git 源（含自有托管）/ 本地目录。压缩包过境 = 解压后按本地目录源处理——zip 是搬运方式，不是格式声明。
- 生态挂靠：`package.json` keywords 带 `berry-app`。
- 未安装的行 = `unresolved`，**永不自动安装**——装机是 operator 动作（`/apps-install` 装机入仓 + `/apps-mount --apps` 写行挂载，两步都不静默）。

### 作用域两档与装机/挂载两态（D1-D4 已落码）

- **行增可选 `apps` 键（数组）定作用域**：缺省 = **全局作用域**（v1 官方专属——官方件档，注册面落全局层、进一切组成面）；`apps: [<应用id>, …]` = **应用作用域**（第三方能力件的档位，注册面落该应用域层、只进所列应用的组成面；多元素 = 多应用共享）。四触发拒绝式（`COMPOSITION_ROW_INVALID`）：未知应用 id / 第三方行缺省挂全局（全局作用域 v1 官方专属，第三方跨应用需求走 MCP 桥或挂默认应用）/ Ring 1 必备行带 `apps` / 官方引用行带 `apps`（官方件恒挂全局）。
- **依赖单向**：应用作用域件可 inject 全局作用域件提供的服务；反向与**跨应用作用域** inject 拒启（`APP_INJECT_UNRESOLVED`——分区装载执法：系统区先行收口，每应用各一区，跨区视同目标缺失）。
- **装机/挂载两态**：`install` = 仓库态（代码进装机子树 + provenance 出处落账，不落组合行 = 零生效——**应用独立不生效的机制化**）；挂载动词写行才生效（`mount(id, {apps, config?, rowId?, carrier?})`——`apps` 必填〔第三方件挂应用作用域，挂全局 v1 拒〕，行 id 缺省 = 装机推导 id、`rowId` 显式命名位〔同包第二应用挂载必经〕；`carrier` 三值显式降格位：**缺省不落 sandbox 块 = 闩一装载期推 external**〔出生即进程墙〕，显式 `main`/`worker` = operator 降格，三值落盘皆成块唯缺省零块〔R1 2026-08-29 解冻收口〕；`config` **唯显式 `main` 行可携**——分域行〔worker/external/缺省 external〕的生效 schema 在域侧、宿主拒绝代校验〔带非空 config 挂分域行即拒；行配置手编 overlay 后 `/reload`〕；unmount 删行保码，重挂回装机推导 config 缺省）。同件多应用挂载 = 同一实例服务多应用（实例全局单例，挂载只是可见性投影）。应用清单 components 在场断言值域 = 挂全局 ∪ 挂本应用（**挂他应用 ≠ 在场**）。
- **单区 reload（D3 已落码）**：`/reload --app <应用id>` 只换该应用名下第三方挂载行——他应用运行时不动（驱动与会话不死）；官方件与 Ring 1 行不在此径，其变更走全量 `/reload`。
- **分发不变**：npm 三源。应用包同款——一切装载件同包形态（可零代码，清单文件即应用包唯一源），无独立容器格式；「上市场」= npm 生态本身，不自建商店。
- **渲染主题（D4 已落码）**：清单可声明 `theme: { accent: <色> }`（色 = 白名单色名八字 `red | orange | yellow | green | cyan | blue | magenta | gray` 或 `#rrggbb` 六位 hex；值域外拒装 `APP_INVALID`）。accent 是多应用并行时的会话归属色：聚焦切换随应用换装（状态行 ● 指示符 / 输入框边框 / 页脚标题段），非聚焦摘要行（⧗/✓ 后台状态）各归各色。缺省不写 = 零色恒等（合法缺省态，非待修）。
- **默认应用键（组装批落码）**：清单可声明 `default: true`——**官方专属词汇**，第三方清单携带即拒登记（`APP_INVALID`；发现面接通日执法）。全局恰一：>1 份带标 = 拒启（发版事故级）。运行时解析两跳回落（带标在场 → chat 锚点 → 兜底态不认领），per-open 活取、`/reload` 即时反映。当前全仓唯一带标 = `apps/berrycode.app.yaml`（代码智能体应用）——它也是**纯清单应用**的活样例：零自有行为件，能力面全走 `components` 六件声明 + `agent.persona` 人格段（人格非任务指令段——open 装配消费于代理默认位，请求侧 persona 被清单钉死覆盖）。

### 运行域（sandbox.carrier）作者须知

第三方件可声明运行域装载：**缺块 = external 进程墙（闩一缺省档，无需声明）**；组合树行写 `sandbox: { carrier: … }` 显式声明（`main` = operator 降格主线程直载；`worker` = 宿主内 worker 线程域；`external` = per-行 fork 进程域——与缺省等价的显式形态）。宿主侧编舞（舰队/心跳/内存档/死亡结算）与整体定位见[架构总览](架构总览.md)「进程隔离与沙箱」；作者侧需知五件：

- **同一段码两域可跑**：main 域拿真作用域 / worker·external 域拿桥接代理——`ctx.provide` 服务、`ctx.get` 调用、事件订阅（经转发器过桥）、工具注册（声明面本地、execute 过桥）、`ctx.host` 自省面（宿主以纯数据快照随行过河、对岸同构物化——同步可读、不走 RPC 收窄、不 `BRIDGE_SURFACE_NARROWED`）两域同形。官方 Echo 金样（`src/app/echo.ts`）即同一入口双拓扑 parity 的活样例——第三方作者与它用同一导入面（`berryagent` 虚拟面）。
- **调用面异步收窄**：非 main 域 `ctx.get` 返回的服务调用是 RPC Promise（唯一形态）；五个同步编排面 throw `BRIDGE_SURFACE_NARROWED`——`ctx.parallel` / `ctx.serial` / `ctx.waterfall` / `ctx.registerMessageRole` / `ctx.registerSessionEventType`。编排逻辑留在宿主侧，或改走事件订阅形态。
- **结构化克隆边界**：过桥的参数/返回值走结构化克隆（函数、类实例的方法表不可过界——传数据不传行为）；AbortSignal 不过界（取消在本地立即结算 `BRIDGE_CANCELLED`）。
- **预算与生命周期**：应用清单 `budget.memoryMb` 映射域内存硬档（超限终止 + `worker/oom`；只限 JS 引擎堆——是预算工具不是安全墙，宿主缺省 512MB）。域崩溃/冻结/OOM **不自动重启**，`app/failed` 与行状态携带第一手 diagnostic——写健壮的 apply（幂等注册、`ctx.effect` 返清理函数）比指望重启更有效。
- **间接子进程按行收窄（R1 2026-08-29）**：域应用经 `ctx.get('exec')` 调宿主 exec 服务产生的子进程，按**本行有效白名单**软禁（`sandbox.fs.writableRoots` 声明 ∩ 宿主执法基线〔workspace ∪ 行数据根〕；声明缺席 = 全基线）——不吃会话档宽面。声明收窄的行，其子进程写白名单外路径同样被拒（与域本体 PM/OS 两层同族收窄）。「OS 沙箱罩后代」即此通道。

## 5. 生命周期与事件

| 时点              | 行为                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------- |
| boot              | 组合树合成 → jiti 加载 → 形状校验 → 分区 Kahn 轮次激活（硬依赖全就绪）                                        |
| 激活成功          | `app/activated` 活体总线事件（不落 durable——生命周期四词中唯 `app/uninstalled` 是总线 + durable 双落地）      |
| 激活失败          | apply 抛错 → LIFO 回卷已激活件 → `app/failed` + 失败处置两桶（官方行拒启 / 第三方行隔离降级留账，见上）       |
| 静态禁用/平台门控 | 行不解析入口（挂载休眠）→ `app/skipped`                                                                       |
| `/reload`         | 卸载半边（dispose 回卷全部注册）→ 重读组合树 → 重装（`--app` 单区：只动该应用名下第三方行，回执带卸词集警示） |
| 退出              | shutdown 序列：装载件作用域回卷 → jobs 排空 → 落盘屏障 → 关库                                                 |

注册纪律：**一切注册挂 `ctx.effect`**（注册即 effect）——你不需要手工管理注销序，作用域回卷自动完成。

## 6. 应用数据（所有权与生命周期）

应用的一切持久状态归三桶，各走各的正门：**配置**走组合树行 `config` 字段（随 overlay 管理，启动时按你声明的 schema 一次性校验）/ **凭证**走宿主 credentials 面（应用不经手）/ **自有数据**住本节的数据目录。宿主不提供通用 KV 存储与 secret 存储——需要 KV 化的配置回行 config，需要保密的交宿主，剩下的才是你要自己管的。

自有数据契约：

- **目录所有权（双键一桥）**：每个应用行一个数据目录（`<数据目录>/apps/<行 id>/`）。目录键 = 组合树行 id；目录内一份 `data.json` 记 `{ app: '<声明名>', declaredEvents }`——`app` 字段是**认领凭据**（行改名 / 跨包重装后凭它认回旧目录、数据不丢；认领消费面随清单投影批落码，当前该文件先记账后消费）；`declaredEvents` 是事件词表账本（install 时收割你 named export `events` 的键名，卸载检视据此警示受影响会话）。`builtin:` 官方行不走 install，无 data.json。
- **写入纪律**：自有数据是低频配置类数据（设置、缓存索引、账本），不是每轮热数据——热数据走 durable 事件（`ctx.sessions.appendEvent`）或内存态。写文件用原子写（写临时文件 + rename），不留半文件。
- **临时空间 = `tmp/` 子目录（无持久保证）**：大二进制、可重建缓存放数据目录下的 `tmp/`（`<数据目录>/apps/<行 id>/tmp/`）。宿主每次启动清扫该目录内 mtime 超 **7 天**的文件并删空目录——**另一 berry 实例启动也会触发，包括你的应用正在运行的场合**。三条推论：需要持久的数据放 tmp 外；缓存条目按 ≤7 天 TTL 设计（存活只认写 mtime，**读不续鲜**——需续鲜自行重写）；写 tmp 前先 `mkdirSync(recursive)`（空目录可能已被剪除）。
- **默认私有，共享走三桥**：应用间数据共享与能力共享同门——服务面（`provide` 一个读接口）、事件总线（emit 变更）、工具面（注册查询工具）。默认私有由结构保证（各写各的目录）；显式共享 = provide 那一行代码。没有独立的数据授权声明，也没有独立的存储诊断面——服务注册表本身就是共享清单。
- **会话数据不加应用私键**：会话事件日志按会话归属（`sessions` 表记来源应用）；应用读跨会话数据走 `ctx.sessions` 只读投影——同库不同视图，不在事件上分应用库。

卸载处置（`/apps-uninstall` 已落码——两段式：裸调检视、`--confirm` 执行）：

- 装机物（包目录、组合树行）**必删**；数据目录**默认保留**（数据是用户的，不是包的），删除显式问 operator。
- **ignorable 纪律**：有持久语义的自定义事件词汇，注册时一律声明 `ignorable: true`——否则卸载你的应用后，读侧遇未知事件类型会整体拒绝解读会话（宁拒绝不误读），历史会话因卸载变砖。

## 7. 错误码族（`berryagent` 面）

`APP_LOAD_FAILED`（jiti 加载失败）/ `APP_SHAPE_INVALID`（形状违例）/ `APP_CONFIG_INVALID`（行配置不过 schema）/ `APP_INJECT_UNRESOLVED`（硬依赖无解——分区 Kahn 轮次耗尽）/ `APP_APPLY_FAILED`（apply 抛错）/ `APP_ENTRY_UNRESOLVED`（入口解析失败）/ `APP_IMPORT_FORBIDDEN`（import 来源门禁越界——依赖图说明符不在白名单三道，2026-08-26 执法）/ `APP_MAIN_DB_FORBIDDEN`（`berryagent/sqlite` 拒开宿主主库）/ `APP_INSTALL_FAILED`（装机失败）；另有 `COMPOSITION_ROW_INVALID`（组合树行非法）。抛错统一 `AppError(码, 信息)`——字符串码单一路线，无错误类层级。

## 8. 调试

### 快速试件（一步跑——开发循环主力）

```bash
berry run --app-file ./my-app/index.ts "测试一下"
```

零装机、零挂载、零落盘——组合树注入临时行（id=`_quick_test`，挂 chat 应用域），走完整装载管线（jiti 直载 + 形状校验 + Kahn 轮次激活 + apply + 生命周期事件），退出后组合树恢复原状。开发迭代从此不需要 install→mount→reload 三步。

**互斥与适用面**（契约篇 §5.5 不变式 7）：

| 并给形态                           | 语义                                                                 |
| ---------------------------------- | -------------------------------------------------------------------- |
| `--app-file` + `--tick`            | 用法错（两身份分立——任务行 vs 入口文件）                             |
| `--app-file` + `--app`             | 用法错（应用身份与试件注入不共存）                                   |
| `--app-file` + `--no-apps`         | 安全模式胜出（试件行随 Ring 2 全跳——工具不可见）                     |
| `--app-file` + `attach` / `daemon` | 用法错（纯客户端 / 常驻体不适用）                                    |
| `--app-file` + `dump-config`       | 无害忽略（诊断不含快试行——快试诊断以真跑 boot 横幅为准）             |
| TUI 内 `/reload`                   | 快试行随 fresh 读盘消失（预期——每次重跑 `--app-file`，不依赖热重载） |

### 诊断三面

| 工具                 | 用法                            | 看什么                                                                                 |
| -------------------- | ------------------------------- | -------------------------------------------------------------------------------------- |
| `berry dump-config`  | 终端命令                        | 合成树 + 每行装载状态 + 挂载分组 + 默认应用披露——「我到底跑的是什么」的第一入口        |
| `boot-failures.json` | `<数据目录>/boot-failures.json` | 第三方行失败的结构化诊断（行 id / 错误码 / 栈 / 应用作用域）——比启动横幅多了完整调用栈 |
| `/apps`              | TUI 命令                        | 同 dump-config 的装载状态面（交互态）                                                  |

### 日志

**应用内日志走 `ctx.logger`**——带作用域前缀（`context:app:apps:app:<行id>`），与宿主日志统一到进程 stderr，`APP_LOG_LEVEL=debug` 提级后全链可见（应用装载、服务提供、工具管道、审批决议）。

`console.log` / `console.error` 也可以用（jiti 直载的代码运行在宿主进程中，直接输出到 stdout / stderr）——但推荐 `ctx.logger`，因为：(1) 带作用域前缀可过滤自己的应用；(2) 级别可控（warn 只在生产出，debug 开发出）；(3) 结构化字段（`ctx.logger.debug('消息', { key: value })`）。

### 热重载

| 命令                     | 范围                           | 适用场景                     |
| ------------------------ | ------------------------------ | ---------------------------- |
| `/reload`                | 全量（Ring 2/3 全部行）        | 改了 overlay / 换了多件      |
| `/reload --app <应用id>` | 单区（只换该应用名下第三方行） | 开发迭代（他应用运行时不动） |
| `/reload`（run 进行中）  | 排队，run 结算后自动执行       | 不打断当前轮                 |

jiti `moduleCache: false` 保证每次 reload 全依赖图重新求值——改了源码即刻生效，无需重启进程。

### 事件流调试（你的 Agent 的 DVR）

Berry 的会话是 append-only 事件日志——**Agent 的一切行为都是 durable 事实**。调试应用的行为等于读事件日志：

```bash
# 用 events_query 工具（模型侧）：
#   查询最近 100 条事件，按类型过滤
# 用 ctx.sessions（应用侧）：
#   ctx.sessions.eventsOfType('my-app/note')  → 枚举本会话自有词汇事件
#   ctx.sessions.currentSessionId()           → 当前归属会话
```

用观测面查聚合（obs 件）：

```bash
/obs          # 今日总览：llm 调用 / 工具 / 轮次 / 审批 四行
/obs tools    # 按工具聚合（调用次数 / 拦截 / 失败 / 超时 / 时长）
/obs usage    # 按模型聚合（token 四桶）
```

### 常见错误速查

| 错误码                         | 含义                                                    | 修法                                                         |
| ------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------ |
| `APP_SHAPE_INVALID`            | default export 非函数 / name 缺失 / inject 非字符串数组 | 对照 §1 应用形状                                             |
| `APP_IMPORT_FORBIDDEN`         | import 了宿主内部实现                                   | 只 import `berryagent` 虚拟面 + `node:*` + 应用目录树内      |
| `APP_CONFIG_INVALID`           | 行 config 未通过你的 schema                             | 检查 overlay.yaml 中该行的 config 字段                       |
| `APP_INJECT_UNRESOLVED`        | inject 依赖无提供方或依赖环                             | 检查依赖名拼写；跨应用依赖走全局作用域件                     |
| `APP_APPLY_FAILED`             | apply 抛错（看 message 原因）                           | 你的代码 bug——`boot-failures.json` 里有完整栈                |
| `APP_APPLY_TIMEOUT`            | apply 挂起超 10s                                        | 检查是否有永不 resolve 的 Promise                            |
| `CONTEXT_SERVICE_NAME_INVALID` | provide 的服务名形状不对                                | 官方名位单段小写；第三方必含恰一 `/` 域前缀                  |
| `EVENT_UNKNOWN`                | 事件名未注册                                            | 拼错了？先在 `events` 声明或 `registerSessionEventType` 注册 |
| `SESSION_CORE_TYPE_FORBIDDEN`  | 尝试写核心词（user/message 等）                         | 核心词写权属宿主——注册自有词汇替代                           |
| `TOOL_DUPLICATE`               | 同名工具重复注册                                        | 检查是否有同名的官方件或他应用已注册                         |

## 9. 反模式（来自双蓝本 60 包生态读码，编号固定）

1. **类型面 ≠ 运行面**：声明了扩展点类型却不在运行时接线（声明零导线）——贡献必须真注册。
2. **逃生门半造**：开了口子却没有完整语义（半个 API 比没有更糟）。
3. **特权分层塌方**：应用面暴露宿主特权操作（绕过守门/审批/归因）—— Berry 对应防线：核心事件词汇拒写、审批对、source 归因。
4. **peerDep 蔓延**：把宿主当 peer 依赖锁版本自保——应用只依赖 `berryagent` 虚拟面，无版本锁（同仓同版本零漂移；hostVersion 门控 Ring 3 出现再议）。
5. **直开 SQLite 库文件**：跨会话数据必须走 `ctx.sessions` 只读投影/事件面，绕投影攒第二份账 = 双事实源错误。
6. **进程日志独扛 bug**：只在 debug 出现的分支，其行为必须同时是 durable 事件或运行时断言。
7. **绕过数据契约**：自造 KV 文件格式 / 每轮热写配置文件 / 在数据目录外藏状态——数据三桶各走各的正门（见 §6）。

## 10. 分发与托管（怎么把你的应用给别人装）

### 打包契约（装机物识别）

一个可分发的 berry 应用 = 一个包根目录，宿主按固定解析序找入口（与本地开发同一形态）：

```
<包根>/
├── package.json        # npm 源的装机 id = 包名（name 字段）；git 源 = repo 名 / local = 目录名——装机 id 按源推导（回执为准）
├── .app.yaml           # 可选应用清单（与入口同目录）——api 块（版本协商声明，见 §2「清单 api 块」）/ theme / components 等；组合树合成期与 berry apps check 的消费输入
├── index.ts            # 入口（解析序：package.json harness.extensions → extensions/index.ts|.js → index.ts|.js）
└── （自带 node_modules/ 可选——自身依赖自捆分发是正路）
```

入口模块形状 = §1 的单形状纪律（default export 函数 + name/inject/config/events 导出）。npm 源装机进 `<数据目录>/apps/node_modules/<包名>` 自有子树（不碰全局）；git 源克隆进 `apps/git/<host>/<路径分层>`；本地路径直引不拷贝（改码后 `/reload` 即见）。

### 三种分发形态

| 形态                  | 适用                               | 安装                                                                                                                                                                                                                      |
| --------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **npm 公有**          | 开源应用                           | `/apps-install <包名>` 或 `/apps-install <包名>@<版本>`                                                                                                                                                                   |
| **npm 私有 registry** | 团队内部分发                       | 服务端： Verdaccio/Nexus 等私有 registry，发布 `npm publish --registry <你的 registry>`；用户端：`~/.npmrc` 配 `registry=<你的 registry>`（或 `@scope:registry=` 按 scope 走私仓），然后同公有形态 `/apps-install <包名>` |
| **git 仓库**          | 任意 Git 托管（GitHub/Gitea/自建） | `/apps-install <git URL> [git ref]`——repo 根 = 包根（含 package.json 与入口）                                                                                                                                             |
| 本地路径              | 开发迭代                           | `/apps-install ./my-app`（直引不拷贝，改码 reload 即见）                                                                                                                                                                  |

自建 git 托管最简形态：空仓库 + 包根文件直推（package.json + index.ts），无需构建产物——宿主侧 jiti 现场装载 TS。多应用仓库可为每应用留子目录，安装时用本地路径指到子目录（git 源形态 v1 锚定 repo 根）。

### 安装全链（装机 ≠ 生效）

```
/apps-install <来源>      # 装机：入仓库态，零生效
/apps-mount <装机id> --apps <应用id>   # 挂载：写组合行（链 reload）
# 模型面等价动词：apps_install / apps_mount / apps_reload（各过审批对）
```

更新：`/apps-update <装机id>`（npm 重装 / git 按 ref 重克隆 / local 改动即见）。卸载：`/apps-uninstall <id>`（两段式，先检视后 `--confirm`）。
