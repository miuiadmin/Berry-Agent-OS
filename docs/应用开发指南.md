# 应用开发指南

> 面向应用作者：应用形状、inject 服务面、扩展点词汇、组合树、生命周期、应用数据、调试与反模式。

## 1. 应用形状（单形状纪律，钉死）

一个应用 = 一个入口模块，**唯一合法形状是一种函数**：

```ts
// entry.ts（入口解析序：harness.extensions → extensions/index → index）
import { Type } from 'typebox'; // 宿主实例经虚拟注入，勿自装第二份（双实例防线）

export const name = 'my-app'; // 必填：日志归因标识（非空字符串）
export const inject = ['tools', 'prompts']; // 硬依赖服务：全就绪才激活，缺 = 响亮失败
export const optionalInject = ['llm']; // 软依赖：不阻塞激活，ctx.tryGet 探测
export const config = Type.Object({
  // 可选：行配置 schema（启动时一次性校验）
  greeting: Type.Optional(Type.String()),
});
export const events = [
  // 可选：自定义活体事件声明（总线词汇）
  { name: 'my-app/tick', mode: 'emit', note: '周期心跳' }, // name 小写含 '/'
];

export default async function apply(ctx, cfg) {
  // 一切注册走 ctx.effect —— 作用域 LIFO 回卷即注销，/reload 卸载半边自动干净
  const tools = ctx.get('tools');
  ctx.effect(() => tools.register({/* ToolDefinition */}));
}
```

规则：

- **零 import 约束（装载期门禁执法）**：文件应用的 entry.ts 及其**全部依赖图**不能 import 宿主内部实现——可 import 的白名单三道：① 虚拟面六键 `berryagent`（contracts 公共面：AppError / 错误码 / 事件常量与目录 / **ctx 面与服务面契约类型（`AppContext` / `ToolsService` / `PromptsService` 等）**）、`typebox` 三入口（宿主注入同实例，防双实例）、`berryagent/llm`（provider 工厂面：`createProvider` / `hasApi` / `lazyApi` / `anthropicMessagesApi`——写 provider 应用用宿主同版本工厂，勿自捆 pi-ai）、`berryagent/sqlite`（`openDatabase(path)` 开自管库——宿主同实例 better-sqlite3，**主库路径拒开**（`APP_MAIN_DB_FORBIDDEN`），自管库读写全权含建表迁移）；② `node:` 内建（裸名 `path` 等同放行）；③ **应用目录树内**（相对路径与自带 `node_modules`——自身依赖自捆分发是正路）。越界即拒载 `APP_IMPORT_FORBIDDEN`（import 了未使用也拦——解析对账不等使用；错误消息附六键清单与指路）。子路径（如 `berryagent/typebox`）不在白名单——同样被拦，消息列出全部可用键。
- **类型直取**：`import type { AppContext, ToolsService, GateInput } from 'berryagent'` ——ctx 与服务面类型不再需要局部重声明（编辑器/tsc 解析随 npm 分发批提供 `.d.ts`；当前在包外项目里可先 type-only 引用或 `any` 起步，装载期虚拟注入保证运行时正确）。
- 形状违例（default 非函数 / name 缺失 / inject 非字符串数组 / config 非对象 schema）→ `APP_SHAPE_INVALID`，装载即拒。
- apply 抛错 → 加载器先 LIFO 回卷已激活件、再进失败清单；**失败处置两桶**：官方件行失败 = 启动断言拒启（全家桶与宿主同仓同版本，失败即宿主 bug 不带病跑）；**第三方行失败 = 隔离降级**——你的应用装坏了不拖死平台启动，但启动横幅与诊断文件 `<数据目录>/boot-failures.json`（行 id/错误码/栈/应用作用域）会点名，`app/failed` 事件照发——修好后 `/reload` 即回。
- 官方件（`builtin:memory` 等）与文件应用完全同轨装载，只是不经 jiti（宿主随包函数引用）。

## 2. inject 服务面（ctx.get / ctx.tryGet）

| 服务名                 | 面                                                 | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tools`                | `register(def: ToolDefinition): Disposer`          | 贡献模型可见动词。注册即 tools_change → 活跃 loop 工具集原位刷新                                                                                                                                                                                                                                                                                                                                                                        |
| `prompts`              | `registerSection({ id, render }): Disposer`        | 系统提示词具名段。宿主固定分节序；render 仅重建时点求值（随会话冻结，prompt cache 友好）；禁整串替换                                                                                                                                                                                                                                                                                                                                    |
| `llm`                  | `complete()` / `canAfford()`                       | 单发补全唯一合法路径（不走 loop；禁收 apiKey）；canAfford 预算闸门——后台低优先级活必须先问                                                                                                                                                                                                                                                                                                                                              |
| `exec`                 | `exec(cmd, args, opts)`                            | 子进程执行原语（Ring 1 exec 件）：内部合成 def 走同一三段管道——守门/沙箱/durable 落账不旁路；返回结构化 `ExecResult`（exitCode / stdout / stderr / 60KiB 保尾截断标记 / sandbox 归因）；守门拒绝/超时一律 throw `AppError`（调用方是宿主侧代码，异常面比模型面的结构化拒绝更有用）                                                                                                                                                      |
| `fetch`                | `fetch(url, { caller, signal })`                   | 出网抓取原语（web 件）：与模型面 `fetch` 工具同一 execute 同一卫生件（私网拒/限流/字节预算/重定向逐跳），内部合成 def 走同一三段管道——守门/durable 落账不旁路；返回结构化 `WebFetchResult` 九字段（url/finalUrl/status/contentType/text/bytes/truncated/redirects/durationMs）；`caller` 必传应用名（归因进 durable details——服务被调时调用方身份结构性不可知，显式声明是唯一诚实形态）；SSRF/超跳等异常 throw `AppError`（WEB_* 码族） |
| `sessions`             | `appendEvent(type, data)`                          | 向当前活跃会话落 durable 事件（活引用，/new 热切换跟随）。核心词汇拒写（`SESSION_CORE_TYPE_FORBIDDEN`）；只许写自注册词汇（注册走 `ctx.registerSessionEventType`，见 §3 表）                                                                                                                                                                                                                                                            |
| `agent`                | `sendUserMessage()` / `onRunSettled()`             | 以应用身份注入用户消息（source 归因）/ 订阅 run 结算（goal 续跑触发位）                                                                                                                                                                                                                                                                                                                                                                 |
| `subagents`            | `register(provider)`                               | 注册 SubagentProvider（进程内子代理执行器）                                                                                                                                                                                                                                                                                                                                                                                             |
| `jobs`                 | `registerKind()` / `run()` / `create()` / `list()` | 后台任务注册表：状态机 running→stopping→唯一终态，结算必发 job_settled                                                                                                                                                                                                                                                                                                                                                                  |
| `channels`             | `registerCommand(cmd)`                             | TUI 斜杠命令（同名后写胜出）                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ui`                   | `notify()`                                         | UI 通知（三通道自适应：通知器/时间线/状态行）                                                                                                                                                                                                                                                                                                                                                                                           |
| `skills`               | `registerProvider(p)`                              | 技能来源（本地 FS 为默认 provider）。注册/注销即 skills_change → 系统提示词重建（渐进披露热可见）。**provider 契约钉死 FS 假设**：返回的 Skill.filePath 必须真实存在且模型可 read——远端/虚拟来源（hub registry 等）须自物化落盘再提供（「安装即落盘」）                                                                                                                                                                                 |
| `approval` / `sandbox` | 安全栈面                                           | 高级用法；常规应用经工具管道间接受益即可                                                                                                                                                                                                                                                                                                                                                                                                |
| `paths`                | 数据目录路径族                                     | 定位应用自身数据目录与宿主路径（数据契约见 §6）                                                                                                                                                                                                                                                                                                                                                                                         |
| `apps`                 | `list()` / `install()` / `mount()` 等             | 应用管理服务（装机/挂载/更新/卸载——两态动词面；组合树为枚举唯一事实源）                                                                                                                                                                                                                                                                                                                                                                  |

`inject` 是 Kahn 硬依赖（轮次激活：声明即等待，无解响亮失败）；`optionalInject` 是软依赖（激活后 `ctx.tryGet` 探测，缺省 undefined 自行降级）。

## 3. 扩展点词汇

| 扩展点                     | 注册 API                                                           | 出处模块                                                                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工具                       | `ctx.get('tools').register(def)`                                   | tools                                                                                                                                                                                                            |
| 系统提示词段               | `ctx.get('prompts').registerSection({id, render})`                 | app/prompts                                                                                                                                                                                                      |
| TUI 命令                   | `ctx.get('channels').registerCommand(cmd)`                         | channels                                                                                                                                                                                                         |
| 自定义活体事件（总线词汇） | 模块 `events` 声明（`{name, mode, note}`——加载器装载阶段统一登记） | context 总线                                                                                                                                                                                                     |
| LLM provider               | `ctx.get('llm')` 运行时面 `registerProvider`                       | llm                                                                                                                                                                                                              |
| 技能来源                   | `ctx.get('skills').registerProvider(p)`                            | skills——注册即 skills_change（渐进披露热刷新）；FS 假设钉死（见上表注）                                                                                                                                          |
| Job kind                   | `ctx.get('jobs').registerKind(kind)`                               | subagent                                                                                                                                                                                                         |
| 自定义消息角色             | `ctx.registerMessageRole(name, definition)`                        | contracts——应用面角色名**必含 `/` 域前缀**（`memory/recall` 式）；官方件同走此面（无特权）                                                                                                                       |
| 自定义会话事件类型         | `ctx.registerSessionEventType(def)`                                | contracts——应用自有 durable 词汇的注册钥匙（注册后 `ctx.sessions.appendEvent(type, data)` 即可写）；核心词拒注册 `SESSION_CORE_TYPE_FORBIDDEN`；surface 类别词汇负有投影折叠形态声明义务；挂 effect 栈随卸载回卷 |

请求尾注入的标准姿势：订阅 `context_transform`（瀑布钩子，`ctx.on` 直接可订）——每 handler 至多追加一条消息，`memory/recall` / `memory/diff` 即此形态。注入消息用自定义角色时先经 `ctx.registerMessageRole` 注册（`toLlm` 定义 LLM 边界转换——建议映射为防注入句式包裹的 user 消息，`render: {intent:'hidden'}` 不进时间线）；轻量替代 = 直接追加原生 user 角色并自带包装句式（免注册，但语义上是机器注入伪装用户轮）。注意：未注册角色的消息在 LLM 边界被静默过滤并记 debug 日志（角色名入日志）——自造角色名不注册会蒸发。

## 4. 组合树

默认层（官方全家桶，随包）+ 用户 overlay 合成，**字段级后写胜出**：

```yaml
# ~/.berry/overlay.yaml（文件不存在 = 纯默认层，首启零配置即合法）
rows:
  - id: memory # 替换官方行：省略 pkg = 沿用官方引用，只改其余字段
    config: { recallTopK: 5 }
  - id: memory-strict # insert 行必须自带 pkg
    pkg: builtin:memory
    config: { unusedDays: 14 }
  - id: goal # 禁用官方行（真·可卸）
    disabled: true
  - id: darwin-only-thing # 平台门控 + 第三方行范例（必挂 apps + sandbox 块）
    pkg: ./apps/my-thing
    apps: [chat] # 第三方行必填——挂应用作用域（多元素 = 多应用共享件）
    sandbox: { carrier: main } # carrier 三值 main | worker | external
    disabled: darwin
```

- 行字段：`id` / `pkg` / `config` / `disabled` / `fixed` / `sandbox` / `apps`——未知字段拒绝式（pre-release 纪律）。`sandbox` 块（沙箱声明）：`carrier` **必填**三值枚举 `main | worker | external`（main = 主线程直载；worker = 宿主内 worker 线程域；external = per-行 fork 进程域——进程墙隔离，第三方件缺省档），`net` 声明即拒（网络面 v1 不开放）、`fs`/`caps` 纯对象；半块（缺 carrier）机器拒写；`builtin:` 官方行声明 sandbox 块（任何 carrier）= 拒——官方随包件恒主线程。`apps` 键 = 作用域（数组、元素 = 在册应用清单 id）：缺省挂全局作用域（**v1 官方专属**——第三方行不带 `apps` 直接拒绝式拦下，见下方专节）；多元素 = 同一实例服务多应用（挂载只是可见性投影）。
- **Ring 1 必备行**（`tools` 起算，随行树化逐行累加）：组合树必备行**可换实现不可禁用**——overlay 禁用/平台门控/引用解析失败 = 启动断言拒启（`COMPOSITION_ROW_INVALID` 带修法指引）；要换实现请替换行 `pkg` 引用（新件须 provide 同名服务，工具行还须携带管道 executor）。此类行挂宿主独立装载锚：**/reload 不回卷**，行合成结果变化在 `composition/reloaded` 载荷以 `ring1RestartRequired` 报告（重启后生效，不静默吞）。
- `config` 整体替换不做深合并，经应用声明的 schema 启动时一次性校验。运行期改配置两条路：模型面 `apps_configure` 工具（patch 按顶层键整值替换——要改哪些键带哪些键，未列出键保持现值；校验不过即拒不落盘，防错配置写盘后下次启动拒启）或直接编辑 overlay 后 `/reload`。
- 文件应用 `pkg` 字段：包名（装入 `<数据目录>/apps/node_modules` 子树）或显式相对/绝对路径；入口解析序 `harness.extensions` → `extensions/index` → `index`。
- **分发 = npm 三源**（无自定义容器格式）：npm registry 包名 / git 源（含自有托管）/ 本地目录。压缩包过境 = 解压后按本地目录源处理——zip 是搬运方式，不是格式声明。
- 生态挂靠：`package.json` keywords 带 `berry-app`。
- 未安装的行 = `unresolved`，**永不自动安装**——装机是 operator 动作（`/apps-install` 装机入仓 + `/apps-mount --apps` 写行挂载，两步都不静默）。

### 作用域两档与装机/挂载两态（D1-D4 已落码）

- **行增可选 `apps` 键（数组）定作用域**：缺省 = **全局作用域**（v1 官方专属——官方件档，注册面落全局层、进一切组成面）；`apps: [<应用id>, …]` = **应用作用域**（第三方能力件的档位，注册面落该应用域层、只进所列应用的组成面；多元素 = 多应用共享）。四触发拒绝式（`COMPOSITION_ROW_INVALID`）：未知应用 id / 第三方行缺省挂全局（全局作用域 v1 官方专属，第三方跨应用需求走 MCP 桥或挂默认应用）/ Ring 1 必备行带 `apps` / 官方引用行带 `apps`（官方件恒挂全局）。
- **依赖单向**：应用作用域件可 inject 全局作用域件提供的服务；反向与**跨应用作用域** inject 拒启（`APP_INJECT_UNRESOLVED`——分区装载执法：系统区先行收口，每应用各一区，跨区视同目标缺失）。
- **装机/挂载两态**：`install` = 仓库态（代码进装机子树 + provenance 出处落账，不落组合行 = 零生效——**应用独立不生效的机制化**）；挂载动词写行才生效（`mount(id, {apps, config?, rowId?, carrier?})`——`apps` 必填〔第三方件挂应用作用域，挂全局 v1 拒〕，行 id 缺省 = 装机推导 id、`rowId` 显式命名位〔同包第二应用挂载必经〕；`carrier` 三值显式降格位：**缺省不落 sandbox 块 = 闩一装载期推 external**〔出生即进程墙〕，显式 `main`/`worker` = operator 降格，三值落盘皆成块唯缺省零块〔R1 2026-08-29 解冻收口〕；`config` **唯显式 `main` 行可携**——分域行〔worker/external/缺省 external〕的生效 schema 在域侧、宿主拒绝代校验〔带非空 config 挂分域行即拒；行配置手编 overlay 后 `/reload`〕；unmount 删行保码，重挂回装机推导 config 缺省）。同件多应用挂载 = 同一实例服务多应用（实例全局单例，挂载只是可见性投影）。应用清单 components 在场断言值域 = 挂全局 ∪ 挂本应用（**挂他应用 ≠ 在场**）。
- **单区 reload（D3 已落码）**：`/reload --app <应用id>` 只换该应用名下第三方挂载行——他应用运行时不动（驱动与会话不死）；官方件与 Ring 1 行不在此径，其变更走全量 `/reload`。
- **分发不变**：npm 三源。应用包同款——一切装载件同包形态（可零代码，清单文件即应用包唯一源），无独立容器格式；「上市场」= npm 生态本身，不自建商店。
- **渲染主题（D4 已落码）**：清单可声明 `theme: { accent: <色> }`（色 = 白名单色名八字 `red | orange | yellow | green | cyan | blue | magenta | gray` 或 `#rrggbb` 六位 hex；值域外拒装 `APP_INVALID`）。accent 是多应用并行时的会话归属色：聚焦切换随应用换装（状态行 ● 指示符 / 输入框边框 / 页脚标题段），非聚焦摘要行（⧗/✓ 后台状态）各归各色。缺省不写 = 零色恒等（合法缺省态，非待修）。
- **默认应用键（组装批落码）**：清单可声明 `default: true`——**官方专属词汇**，第三方清单携带即拒登记（`APP_INVALID`；发现面接通日执法）。全局恰一：>1 份带标 = 拒启（发版事故级）。运行时解析两跳回落（带标在场 → chat 锚点 → 兜底态不认领），per-open 活取、`/reload` 即时反映。当前全仓唯一带标 = `apps/coder.app.yaml`（代码智能体应用）——它也是**纯清单应用**的活样例：零自有行为件，能力面全走 `components` 六件声明 + `agent.persona` 人格段（人格非任务指令段——open 装配消费于代理默认位，请求侧 persona 被清单钉死覆盖）。

### 运行域（sandbox.carrier）作者须知

第三方件可声明运行域装载：**缺块 = external 进程墙（闩一缺省档，无需声明）**；组合树行写 `sandbox: { carrier: … }` 显式声明（`main` = operator 降格主线程直载；`worker` = 宿主内 worker 线程域；`external` = per-行 fork 进程域——与缺省等价的显式形态）。宿主侧编舞（舰队/心跳/内存档/死亡结算）与整体定位见[架构总览](架构总览.md)「进程隔离与沙箱」；作者侧需知五件：

- **同一段码两域可跑**：main 域拿真作用域 / worker·external 域拿桥接代理——`ctx.provide` 服务、`ctx.get` 调用、事件订阅（经转发器过桥）、工具注册（声明面本地、execute 过桥）两域同形。官方 Echo 金样（`src/app/echo.ts`）即同一入口双拓扑 parity 的活样例——第三方作者与它用同一导入面（`berryagent` 虚拟面）。
- **调用面异步收窄**：非 main 域 `ctx.get` 返回的服务调用是 RPC Promise（唯一形态）；五个同步编排面 throw `BRIDGE_SURFACE_NARROWED`——`ctx.parallel` / `ctx.serial` / `ctx.waterfall` / `ctx.registerMessageRole` / `ctx.registerSessionEventType`。编排逻辑留在宿主侧，或改走事件订阅形态。
- **结构化克隆边界**：过桥的参数/返回值走结构化克隆（函数、类实例的方法表不可过界——传数据不传行为）；AbortSignal 不过界（取消在本地立即结算 `BRIDGE_CANCELLED`）。
- **预算与生命周期**：应用清单 `budget.memoryMb` 映射域内存硬档（超限终止 + `worker/oom`；只限 JS 引擎堆——是预算工具不是安全墙，宿主缺省 512MB）。域崩溃/冻结/OOM **不自动重启**，`app/failed` 与行状态携带第一手 diagnostic——写健壮的 apply（幂等注册、`ctx.effect` 返清理函数）比指望重启更有效。
- **间接子进程按行收窄（R1 2026-08-29）**：域应用经 `ctx.get('exec')` 调宿主 exec 服务产生的子进程，按**本行有效白名单**软禁（`sandbox.fs.writableRoots` 声明 ∩ 宿主执法基线〔workspace ∪ 行数据根〕；声明缺席 = 全基线）——不吃会话档宽面。声明收窄的行，其子进程写白名单外路径同样被拒（与域本体 PM/OS 两层同族收窄）。「OS 沙箱罩后代」即此通道。

## 5. 生命周期与事件

| 时点              | 行为                                                                              |
| ----------------- | --------------------------------------------------------------------------------- |
| boot              | 组合树合成 → jiti 加载 → 形状校验 → 分区 Kahn 轮次激活（硬依赖全就绪）            |
| 激活成功          | `app/activated` 活体总线事件（不落 durable——生命周期四词中唯 `app/uninstalled` 是总线 + durable 双落地） |
| 激活失败          | apply 抛错 → LIFO 回卷已激活件 → `app/failed` + 失败处置两桶（官方行拒启 / 第三方行隔离降级留账，见上） |
| 静态禁用/平台门控 | 行不解析入口（挂载休眠）→ `app/skipped`                                           |
| `/reload`         | 卸载半边（dispose 回卷全部注册）→ 重读组合树 → 重装（`--app` 单区：只动该应用名下第三方行，回执带卸词集警示） |
| 退出              | shutdown 序列：装载件作用域回卷 → jobs 排空 → 落盘屏障 → 关库                     |

注册纪律：**一切注册挂 `ctx.effect`**（注册即 effect）——你不需要手工管理注销序，作用域回卷自动完成。

## 6. 应用数据（所有权与生命周期）

应用的一切持久状态归三桶，各走各的正门：**配置**走组合树行 `config` 字段（随 overlay 管理，启动时按你声明的 schema 一次性校验）/ **凭证**走宿主 credentials 面（应用不经手）/ **自有数据**住本节的数据目录。宿主不提供通用 KV 存储与 secret 存储——需要 KV 化的配置回行 config，需要保密的交宿主，剩下的才是你要自己管的。

自有数据契约：

- **目录所有权（双键一桥）**：每个应用行一个数据目录（`<数据目录>/apps/<行 id>/`）。目录键 = 组合树行 id；目录内一份 `data.json` 记 `{ app: '<声明名>', declaredEvents }`——`app` 字段是**认领凭据**（行改名 / 跨包重装后凭它认回旧目录、数据不丢；认领消费面随清单投影批落码，当前该文件先记账后消费）；`declaredEvents` 是事件词表账本（install 时收割你 named export `events` 的键名，卸载检视据此警示受影响会话）。`builtin:` 官方行不走 install，无 data.json。
- **写入纪律**：自有数据是低频配置类数据（设置、缓存索引、账本），不是每轮热数据——热数据走 durable 事件（`ctx.sessions.appendEvent`）或内存态。写文件用原子写（写临时文件 + rename），不留半文件。
- **临时空间 = `tmp/` 子目录（无持久保证）**：大二进制、可重建缓存放数据目录下的 `tmp/`（`<数据目录>/apps/<行 id>/tmp/`）。宿主每次启动清扫该目录内 mtime 超 **7 天**的文件并删空目录——**另一 berry 实例启动也会触发，包括你的应用正在运行的场合**。三条推论：需要持久的数据放 tmp 外；缓存条目按 ≤7 天 TTL 设计（存活只认写 mtime，**读不续鲜**——需续鲜自行重写）；写 tmp 前先 `mkdirSync(recursive)`（空目录可能已被剪除）。
- **默认私有，共享走三桥**：应用间数据共享与能力共享同门——服务面（`provide` 一个读接口）、事件总线（emit 变更）、工具面（注册查询工具）。默认私有由结构保证（各写各的目录）；显式共享 = provide 那一行代码。没有独立的数据授权声明，也没有独立的存储诊断面——服务注册表本身就是共享清单。
- **会话数据不加应用私键**：会话事件日志按会话归属（`sessions` 表记来源应用）；应用读跨会话数据走 `ctx.sessions` 只读投影——同库不同视图，不在事件上分应用库。

卸载处置（`/apps-uninstall` 已落码——两段式：裸调检视、`--confirm` 执行）：

- 装机物（包目录、组合树行）**必删**；数据目录**默认保留**（数据是用户的，不是包的），删除显式问 operator。
- **ignorable 纪律**：有持久语义的自定义事件词汇，注册时一律声明 `ignorable: true`——否则卸载你的应用后，读侧遇未知事件类型会整体拒绝解读会话（宁拒绝不误读），历史会话因卸载变砖。

## 7. 错误码族（`berryagent` 面）

`APP_LOAD_FAILED`（jiti 加载失败）/ `APP_SHAPE_INVALID`（形状违例）/ `APP_CONFIG_INVALID`（行配置不过 schema）/ `APP_INJECT_UNRESOLVED`（硬依赖无解——分区 Kahn 轮次耗尽）/ `APP_APPLY_FAILED`（apply 抛错）/ `APP_ENTRY_UNRESOLVED`（入口解析失败）/ `APP_IMPORT_FORBIDDEN`（import 来源门禁越界——依赖图说明符不在白名单三道，2026-08-26 执法）/ `APP_MAIN_DB_FORBIDDEN`（`berryagent/sqlite` 拒开宿主主库）/ `APP_INSTALL_FAILED`（装机失败）；另有 `COMPOSITION_ROW_INVALID`（组合树行非法）。抛错统一 `AppError(码, 信息)`——字符串码单一路线，无错误类层级。

## 9. 反模式（来自双蓝本 60 包生态读码，编号固定）

1. **类型面 ≠ 运行面**：声明了扩展点类型却不在运行时接线（声明零导线）——贡献必须真注册。
2. **逃生门半造**：开了口子却没有完整语义（半个 API 比没有更糟）。
3. **特权分层塌方**：应用面暴露宿主特权操作（绕过守门/审批/归因）—— Berry 对应防线：核心事件词汇拒写、审批对、source 归因。
4. **peerDep 蔓延**：把宿主当 peer 依赖锁版本自保——应用只依赖 `berryagent` 虚拟面，无版本锁（同仓同版本零漂移；hostVersion 门控 Ring 3 出现再议）。
5. **直开 SQLite 库文件**：跨会话数据必须走 `ctx.sessions` 只读投影/事件面，绕投影攒第二份账 = 双事实源错误。
6. **进程日志独扛 bug**：只在 debug 出现的分支，其行为必须同时是 durable 事件或运行时断言。
7. **绕过数据契约**：自造 KV 文件格式 / 每轮热写配置文件 / 在数据目录外藏状态——数据三桶各走各的正门（见 §6）。
