# 使用指南

> Berry 的用户面文档：安装、CLI、TUI 命令面、数据目录、环境变量、技能、记忆与委派。

## 1. 安装与启动

要求 Node.js ≥ 22.19。从源码运行：

```bash
git clone <repo> && cd berry
npm install
npm run build
npm link        # 装上 berry 命令

berry           # TUI 交互
```

三个 CLI 入口（手写 argv，无命令框架）：

| 命令                 | 行为                                                                                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `berry`              | TUI 交互。缺省**续接当前目录最新会话**；无会话则新建                                                                                                            |
| `berry run "<指令>"` | 单次执行（headless），退出码即结果。适合脚本/CI                                                                                                                 |
| `berry dump-config`  | 打印生效组合诊断：模型、组合树合成结果、每行插件装载状态。**:memory: 全装配零落盘**（真实装载流程全跑、会话主库在内存即弃——所见即实装），排查配置问题的第一入口 |

旗标：`--version` / `--help` 两个入口通用；`--debug` 日志提级；`berry run --app <应用id>` 进入指定应用开新域单发（缺省不传 = 默认应用；与 `--tick` 互斥；id 不在册清单即报 `APP_NOT_FOUND` 并附在册应用清单）；`berry run --read-only` 只读档单发（沙箱钉死只读——`/tick` 定时任务的 runner 即复用此入口）；`berry run --tick <任务名>` 到点执行入口（OS 定时调起的进程走这里：读任务行 → due 复闸 → 抢占 → 单发，可加 `--read-only --background` 与 runner 同款任务面旗标）；`berry run --sandbox-host` 宿主沙箱单发（宿主进程套 OS 沙箱 wrapper——macOS seatbelt / Linux bwrap；检出后 CLI 重 exec 自身，本进程连同全部插件跑在沙箱内。可写面 = 档位根 ∪ 数据目录〔库与凭证必须可写〕。诚实边界：数据目录内部互害关不住〔策略并集粒度〕/ 非网络沙箱——出网默认放行〔LLM API 刚需〕/ seatbelt profile 非稳定公开接口随 macOS 漂移 / Windows 无后端 fail-closed 拒跑〔退出码 1〕）；`--no-plugins` 安全模式（`berry` / `berry run` / `berry dump-config` 三入口通用）——boot 时组合树空装，默认层与 overlay 全跳过、只装不可卸内核件 + Ring 1 硬装配，用于**坏插件锁死启动的自救**：以此旗标起最小内核壳（TUI 无对话驱动但命令面/插件管理完好），修好 `overlay.yaml` 后 `/reload` 即恢复全树（旗标只影响本次 boot，/reload 读盘不受它约束）。`berry dump-config --no-plugins` 同径可见（打印标记行 + 只剩 Ring 1 行的树）。

退出码编舞：正常退出 0；SIGTERM 143；SIGHUP 129。SIGINT 分档——单会话（TUI 只一个活动会话 / headless run）首次即优雅退出 0、二次 130；多会话在跑时首次 Ctrl+C 只**打断聚焦会话的当前 run**（终值记 aborted，排队消息落审计不跑，退出与后台会话不受扰），打断结算后再按才是新的首次语义，run 未结算窗口内连按两次才 130 硬退。

## 2. 模型与凭证

- 缺省模型 `anthropic/claude-sonnet-5`，`APP_MODEL` 环境变量覆盖（格式 `provider/model-id`）。
- provider 凭证走 pi-ai 凭证链：凭证表（SQLite `credentials`，随 pi-ai 授权流写入）或 provider 环境变量（如 `ANTHROPIC_API_KEY`）。
- `berry dump-config` 可查看当前模型与 provider 状态。

## 3. TUI 命令面

输入以 `/` 开头即命令。内置命令：

| 命令                                    | 行为                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/help`                                 | 列出全部已注册命令（含插件贡献的）                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `/quit`                                 | 退出（多会话在跑也退出——恒全序列；Ctrl+C 才是「打断聚焦会话」键，两者分流）                                                                                                                                                                                                                                                                                                                                                                          |
| `/new`                                  | 开新会话（旧会话退役停摆，事件账保留）                                                                                                                                                                                                                                                                                                                                                                                                               |
| `/app`                                  | 多会话前台：裸调列活动会话（●聚焦 / ⧗后台工作中 / ·空闲，含停摆计数；清单尾部披露可用应用〔缺场应用已滤〕）；`/app new` 开新并聚焦（旧会话驻留后台不退役）；`/app <序号\|id前缀>` 切换前台（序号按当次清单会漂移，id 前缀更稳；切换零准入拒——run 中切入切出均合法，非聚焦会话只落摘要行不绞屏）；`/app <应用清单id> [消息]` 进入该应用开新域（清单 id 命中优先于会话序号/前缀寻址——进入是创建新域不是切换；带消息 = 进入后作为首条用户消息直接提交） |
| `/usage`                                | 用量面板：今日/近 7 日 tokens、会话 top、模型分布、goal 预算联查（llm/usage 底账只读投影）                                                                                                                                                                                                                                                                                                                                                           |
| `/allowlist`                            | 免问清单管理：裸调枚举 allowlist 条目（路径前缀 / bash 词干两族，过期态如实标注）；`/allowlist rm <序号>` 撤销。守门命中 allowlist 即免审批执行，但 `reason=allowlist:<序>` 落 gate/decision 审计账——免问≠免账                                                                                                                                                                                                                                       |
| `/skills`                               | 技能清单与激活状态                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `/plugins`                              | 组合树与插件装载状态（每行 activated / failed / skipped 及原因；**已装未挂**的仓库态件以 ◇ 行呈现并带挂载指引——「装了没挂」不可静默）                                                                                                                                                                                                                                                                                                                |
| `/plugin-install <来源>`                | 装机（npm 包名 / git URL / 本地路径）——**仓库态**：代码入装机子树 + 出处落账，零生效不落组合行（装完见 /plugins ◇ 行）                                                                                                                                                                                                                                                                                                                               |
| `/plugin-mount <装机id> --app <应用id>` | 挂载生效：写组合行（`--app` 必填——第三方件挂应用组合；`--row-id` 行 id 显式命名位，`--config '<json>'` 行初始配置经插件 schema 校验）并自动热重载                                                                                                                                                                                                                                                                                                    |
| `/plugin-unmount <行id>`                | 卸挂载：删组合行保代码与数据域（重挂走 /plugin-mount；受影响会话警示随回执呈报）并自动热重载                                                                                                                                                                                                                                                                                                                                                         |
| `/plugin-toggle <行id>`                 | 启用/禁用某插件行（官方件也可禁——真·可卸；临时停用保配置走此命令，移出组合树走 unmount）                                                                                                                                                                                                                                                                                                                                                             |
| `/plugin-update <装机id>`               | 更新装机件（npm 重装 / git 重克隆 / local 提示改动即见；键域 = 装机推导 id——已装未挂的仓库态件也可更新）                                                                                                                                                                                                                                                                                                                                             |
| `/plugin-uninstall <id>`                | 卸载插件——**两段式**：裸调只检视（装机物 / 数据域体积 / 自定义事件词 / 受影响会话计数 + 确认指引），再打 `/plugin-uninstall <id> --confirm` 才执行（`--purge-data` 连数据域清除，默认保留）。Ring 1 底座行拒卸；重跑行不在 = 残迹收尾或无动作速报（幂等）                                                                                                                                                                                            |
| `/reload`                               | 热重载插件集（卸载→重读组合树→重装）；run 进行中不拒——排队，本次 run 结束后自动执行                                                                                                                                                                                                                                                                                                                                                                  |
| `/skill:<名>`                           | 显式激活某技能（随技能快照逐个注册，`/help` 可见）                                                                                                                                                                                                                                                                                                                                                                                                   |

插件贡献的命令（随官方全家桶在场）：

| 命令                                | 来源           | 行为                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/goal`                             | goal 插件      | 长目标管理：查看状态；`resume` 重新激活（重启后降级 needs-resume 时）；`stop` 人工停止                                                                                                                                                                                                                                                            |
| `/tick`                             | scheduler 插件 | 定时任务：`add <name> [schedule] <prompt>` 添加（schedule = `once@<ISO>` / `every@<n>[mhd]` / `daily@HH:MM` 可选三形状，无则仅手动）/ `list` 列出（含 OS 注册态）/ `rm` 删除（联动注销 OS 定时）/ `run` 手动触发一次 / `enable`·`disable` 注册注销 OS 定时（macOS launchd / Linux crontab——注册的是到点唤起 `run --tick` 的 OS 调度，进程不常驻） |
| `/memory-export` / `/memory-import` | memory 插件    | 记忆库 JSONL 导出/导入。导出 `[路径]` 缺省工作区根时间戳名（**明文 JSON**——含全部记忆与软删/过期行，注意文件去向）；导入按 id 恢复式幂等（已存在跳过、零合并），逐行过密钥扫描                                                                                                                                                                    |

命令注册表同名后写胜出（与组合树语义一致）；插件命令 handler 出错以通知呈现，不崩界面。

> 两态已生效（应用中心装载批 D2）：装机与挂载分离——**独立插件不生效**，装机只是入仓，`/plugin-mount --app` 写行才进组合树（上表即现行行为）。装应用 = 提示式批量装机 + 组件挂入该应用一步到位（`/app-install` 随首个第三方应用包需求落码）。

## 4. 数据目录

缺省 `~/.berry/`（`APP_DATA_DIR` 覆盖）：

```
~/.berry/
├── sessions.db          # SQLite 单库（WAL）：会话事件日志 + 记忆库 + goals + 凭证/模型目录
├── overlay.yaml         # 组合树覆写（不存在 = 用官方默认层，首启零配置即合法）
├── project-aliases.json # 项目根别名表（不存在 = 零重定向；项目目录改名/移位后配
│                        #   { "现根绝对路径": "记账根绝对路径" } 续用旧记忆）
├── skills/              # 技能目录（每个子目录一份 SKILL.md）
└── plugins/             # 文件插件装机子树
```

数据目录与库文件随首次启动自动创建（显式 `APP_DB_PATH` 时建其父目录），无需手动建目录。

会话按启动目录（cwd）归属：每个项目目录有自己的会话序列，TUI 启动续接该目录最新一条。

## 5. 环境变量

| 变量            | 作用                                 | 缺省                                                                                      |
| --------------- | ------------------------------------ | ----------------------------------------------------------------------------------------- |
| `APP_MODEL`     | 覆盖缺省模型（`provider/model-id`）  | `anthropic/claude-sonnet-5`                                                               |
| `APP_DATA_DIR`  | 数据目录                             | `~/.berry`                                                                                |
| `APP_DB_PATH`   | SQLite 库文件路径                    | `<数据目录>/sessions.db`                                                                  |
| `APP_LOG_LEVEL` | 日志级别 debug / info / warn / error | debug（代码上仅 `NODE_ENV=production` 转 info，三入口均不设——实际恒 debug；覆盖用本变量） |

## 6. 技能（SKILL.md）与项目指令（AGENTS.md）

技能 = 一个目录 + 一份 `SKILL.md`（YAML 前置元数据 + Markdown 指令体）。放好即生效，无需注册。发现目录（按优先序）：

1. `<项目>/.agents/skills/` — 项目内技能（设计上仅受信工作区注入项目层；当前版本受信判定缺省放行，判定机制随后续纵切接入）
2. `~/.berry/skills/` — 用户全局（Berry 原生）
3. `~/.agents/skills/` 与 `~/.claude/skills/` — agentskills.io 生态两目录原生兼容扫描
4. 宿主包内 `skills/` — 出厂技能（commit-checklist / plugin-quickstart / troubleshooting 三件样例随包分发，优先级最低——同名时你的技能恒压过出厂件）

- **渐进披露**：系统提示词只注入技能清单（名字 + 描述），指令体由模型按需用 `read` 工具加载——不占常驻上下文。
- 前置元数据可设 `disable-model-invocation: true`（kebab-case 键名，只人可用，模型不可主动加载；TS 字段名 `disableModelInvocation`）。
- `/skills` 查看清单与激活状态。

**项目指令文件**（行为约束，常驻系统提示词——与技能的按需加载相反）：纯 Markdown，无需前置元数据。发现四层全量拼接（通用在前、项目殿后）：

1. `~/.berry/AGENTS.md` — 用户全局（Berry 原生）
2. `~/.agents/AGENTS.md` — agents.md 跨工具标准
3. `~/.claude/CLAUDE.md` — Claude Code 生态兼容（现成文件直接复用）
4. 工作区根 `AGENTS.md`（优先）或 `CLAUDE.md` — 项目层（同层至多取一份，防 symlink 双读）

- 单文件 64KiB 上限，超限截断入段（带截断标注）。
- 改指令文件后 `/reload` 生效（重建时点重读，会话中途不热更——保护 prompt cache）。

## 7. 内建工具族（模型可见动词）

| 工具                                                                                             | 语义                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read` / `write` / `edit` / `ls`                                                                 | fs 工具族。读走 CAS 观察态（读后写检测外部改动），写受可写根 fence。`read` 支持图片：png/jpg/jpeg/gif/webp 返回 image 内容块（模型直接看图，5MiB 上限超限报错）                                                                                                                                                                         |
| `find` / `grep`                                                                                  | 检索族。`find` 按 glob 模式找文件，`grep` 按正则搜内容（`files_with_matches` / 带行号 `content` 双模式，可加 `glob` 过滤）。gitignore 语义、二进制自动跳过、单文件 256KiB 扫描护栏、结果达 200 条早停                                                                                                                                   |
| `agent`                                                                                          | 委派子代理执行一次性任务（subagent 插件在场时）。前台阻塞返回汇报；`background: true` 立返任务 id、结算自动通知                                                                                                                                                                                                                         |
| `agent_<name>`                                                                                   | 声明式子代理的专属工具（见第 10 节）：一个 `agents/*.md` 文件 = 一个具名子代理，每文件自动生成同名委派工具——description 即文件描述，人格/工具面/模型由文件固定                                                                                                                                                                          |
| `goal_get` / `goal_set` / `goal_update`                                                          | 长目标管理（goal 插件在场时）。completed 必附 evidence、blocked 必附 note——参数校验段执法，不靠提示词自觉                                                                                                                                                                                                                               |
| `bash`                                                                                           | 命令执行（exec 件聚落）。一次性执行无交互 stdin；超时缺省 120s 上限 600s；输出 60KiB 保尾截断；受限档下写类命令被拒时结果带 `[sandbox: …]` 标记，可携 `sandbox_permissions` + `justification` 成对发起升权审批                                                                                                                          |
| `memory_write` / `memory_forget` / `memory_restore` / `memory_read` / `memory_search`            | 记忆库基础五件（memory 插件在场时）。`memory_search` 联合记忆库与历史会话全文检索；`memory_write` 可带 `ttlDays` 留存天数（到期自动离开注入面，被引用即续期）                                                                                                                                                                           |
| `memory_freeze` / `memory_unfreeze` / `memory_ttl` / `memory_access_log`                         | 记忆持有面四件（memory 插件在场时）。冻结 = 恒驻简报/免过期/免覆写（冻结条拒删，解冻-再忘是唯一路径）；`memory_ttl` 设置/清除留存天数；`memory_access_log` 查访问流水（recall/search/cite 三源）与被用 top——「你为什么记得这个」的审计面。`memory_read` 带条目 id 可看状态与完整版本链（`memory_restore` 带 revision 可回滚到历史版本） |
| `fetch`                                                                                          | 出网抓取（web 插件在场时）。单参数 `url`；HTML 剥标签转纯文本 + 元数据头（最终 URL/状态码/字节数/截断标注）；目标解析到私网/保留地址被拒（SSRF 防线），重定向最多跟随 5 跳每跳重校验，网络读 2MiB 硬顶、产出 60KiB 保头；非 2xx/非文本返回 isError 结果面不中断                                                                         |
| `plugins_list` / `events_query`                                                                  | 管理面只读两件（admin 插件在场时）。装载态清单（activated/failed/skipped/planned 四态 + 来源 + 失败原因）/ 跨会话 durable 事件查询（时间窗 × 类型 × 应用域过滤，游标分页）                                                                                                                                                              |
| `plugins_install` / `plugins_update` / `plugins_toggle` / `plugins_configure` / `plugins_reload` | 插件生命周期五写词（admin 插件在场时）。**每次调用恒经人手审批**——参数必带 `sandbox_permissions`（`workspace-write` 或 `danger-full-access`）+ `justification`（一句话理由）成对，拒绝即不执行。动词单职责：装/更/启停/配置只写 overlay 不热应用，`plugins_reload` 收尾才生效（有 run 在跑时自动排队，结算后执行）                      |
| `plugins_uninstall_inspect`                                                                      | 卸载预检（只读）：装机物、数据域体积、自定义事件词与受影响会话数、级联警示。卸载执行权在人——模型只草拟报告，由用户运行 `/plugin-uninstall <id> --confirm` 执行                                                                                                                                                                          |

所有工具调用过三段管道：参数 schema 校验 → 安全守门（沙箱/审批/可写根）→ 执行。守门决策（gate/decision）落 durable 日志可审计。

## 8. 记忆系统在会话里的样子（memory 插件在场时）

- **常驻简报**：系统提示词里有 `memory/core` 段——高置信记忆的稳定摘要（重建时点冻结，prompt cache 友好）。
- **按需检索**：每轮按你的 query 注入至多几条相关记忆（hidden 消息，不进时间线）。
- **简报差分**：简报面在会话中变化时（新记忆入库/条目离开），下一轮请求尾注入「+ 新增 / ~ 修正 / − 撤回」差分说明，同时落 `memory/diff` durable 事件——重放会话即重现当时的记忆视图。
- **引用回写**：注入行带 `[m:短id]` 标记，模型作答引用即计入该条目效用（排序/保活的依据）。
- **遗忘**：让模型「忘掉这条」走 `memory_forget`（软删，可 restore）；用户终审权最大——插件的一切自动裁决都可被显式动作覆盖。
- **持有面**：临时性记忆可带 TTL（到期自动离开注入面，行保留、可恢复）；「这条永远记住」走冻结（恒驻简报、免过期免覆写）；条目内容变更有版本链可回滚；每次注入/检索/引用落访问流水可审计。`/memory-export` / `/memory-import` 命令把整库导出/导入 JSONL（明文文件，注意去向）。

## 9. 长目标续跑（goal 插件在场时）

`goal_set` 设定目标（含预算帽）后，插件在每次 run 结算时检查：目标 completed 且预算未尽 → 自动注入续跑提示。守护：

- **激活权在人类**：重启后 active 目标降级 needs-resume，`/goal resume` 重新授权才续跑。
- **预算刹车**：本会话 token 用量达帽即停（stopped/budget），不失控烧钱。
- 完成必须附 evidence——空口无凭不算完成。

## 10. 声明式子代理（agents/*.md）

一个 Markdown 文件就是一个具名子代理——frontmatter 声明元数据，正文即系统提示（与 Claude Code 的 `.claude/agents/*.md` 同形，可直接复用现成文件）：

```markdown
---
name: reviewer # 缺省回落文件基名；须与基名一致
description: 资深代码审读员 # 必填——模型的选择依据
tools: # 可选：工具白名单（缺省全量）
  - read
  - grep
model: anthropic/claude-sonnet-5 # 可选：子模型覆盖
---

你是资深审读员，逐行审查。
```

- **发现位置**（同名时前面的压过后面）：项目 `.agents/agents/` → `~/.berry/agents/` → `~/.agents/agents/` → `~/.claude/agents/`。
- **静态工具**：每个文件自动生成 `agent_<name>` 委派工具——模型看到的是具体工具而非动态选择器；通用 `agent` 工具不受影响。
- **文件即约束**：正文固定子代理人格（请求无法覆盖）、`tools` 与请求工具名单取交集（只收窄不改宽）、`model` 覆盖子模型。
- 坏文件（缺 description / 正文空 / YAML 坏）warning 跳过不影响启动；文件名须为合法工具字符（字母/数字/`_`/`-`）。
