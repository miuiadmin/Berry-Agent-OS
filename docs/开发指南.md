# 开发指南

> 面向贡献者：开发纪律全量。四门禁、模块边界、测试、注释、命名、提交。

## 1. 环境与命令

Node.js ≥ 22.19，npm。

```bash
npm install
npm run dev               # TUI 交互（tsx 直跑；dev 日志缺省 debug）
npm run build             # tsc -p tsconfig.build.json 直出 dist/（发布物形态：零测试/声明/映射产物）+ SPA 打包
npm test                  # vitest run 全量
npm run typecheck         # tsc --noEmit（主 tsconfig 含测试——类型覆盖面宽于 build）
npm run lint:topology     # 模块 DAG 门禁（未声明边/死边双向执法 + 公开面模块计数锚）+ 事件词汇双向校验 + 公开面镜像对照（含 README 头部统计锚）
npm run format:check      # Prettier 检查
npm run format            # Prettier 写入
npm run release           # 发布机器（§11）——真发布
npm run release -- --dry-run              # 发布演习（publish 干跑、写面全收）
npm run release -- --dry-run --inject <谱项>   # 失败注入演习
```

**四门禁 = 提交前提**：typecheck / test / lint:topology / format:check 全绿。

## 2. 模块边界（拓扑门禁）

- 27 模块单向 DAG（全部有码；chat/exec/webui 为件聚落）；边表 = `tools/check-topology.mjs` 白名单。跨模块 import 只许走对方公共面（`contract.ts` / `types.ts` / `index.ts`）。
- `@earendil-works/pi-ai` 裸导入仅 `src/llm/`；`typebox` 仅白名单模块。
- 测试文件豁免跨模块检查，但只许 import 本模块与 vitest。
- 新模块：contract-first——先契约（types/contract/错误码/测试）再实现，边表先加边。

## 3. 事件纪律（check-events）

- 每个事件词汇（总线 / AgentEvent / SessionEvent）在目录**显式注册**——注册即写入许可。
- `tools/check-events.mjs` 做三族双向断言（总线活体目录 ↔ 派发/写点 / AgentEvent 联合 ↔ 派发点 / SessionEvent 目录 ↔ 写点）+ 第 4 组 `EventName` 联合字面量 ↔ 总线目录收口断言，挂 `lint:topology`。新增词汇：注册进目录 + 写点用字面量（扫描器按字面量找写点）+ 总线新名须同时进 `EventName` 联合。
- 新增应用事件注册模块：在 check-events 的 jiti 导入清单追加（保持运行时依赖轻量）。
- 读侧未知类型：宁拒绝不静默丢（`SESSION_FORMAT_UNSUPPORTED`）。

## 4. 测试纪律

分层：**单元模块测试（纯逻辑）→ 组合根全栈测试**。

- **mock 只停在模型层**：faux provider / scripted streamFn，其余全真（真 Context、真 SQLite、真服务面）。禁止 mock 中间层后断言高层模块——假信心。
- 禁止在自动化测试中断言 AI 生成的具体文本内容。
- **修 bug 必须带回归锁测试**（修复前必红）。
- **seam 面一致性套件**：单实现接缝持测试面第二实现验证件，双跑同一断言族——`src/subagent/provider-conformance.test.ts`（out-of-process fixture provider × inprocess）、`src/llm/streamfn-conformance.test.ts`（手写 replay 发射器 × pi-ai 适配）。契约演进时两份套件同步跟进，第二实现暴露的契约漏先修契约再改码。
- 真模型端到端冒烟：`tools/smoke-real.mjs`（手动跑，需真凭证环境）。

## 5. 代码注释（中文，硬规则）

- 所有新写代码必须加充分的中文注释：函数用途、参数含义、关键逻辑分支、状态变量的生命周期。
- 函数/方法用 JSDoc `/** ... */`；关键分支行内 `// 说明为什么`；类型/接口逐字段注释。
- 注释语言统一中文，代码标识符用英文。旧代码不加注释不追究，但只要修改到就顺手补上。

## 6. 命名去品牌化（硬规则）

- **禁止在代码标识符中使用产品名称**（`berry` / `berryAgent` 等）——变量、函数、类、接口、类型、枚举值、常量、文件名、目录名全部禁止。
- 用通用领域语义：`core` / `service` / `agent` / `app` / `runtime`。
- 品牌名只允许出现在：`package.json` name 字段、CLI 命令名（`bin.berry`）、用户可见 UI 文案/文档标题、宿主注入子进程的运行时数据值（如 `AI_AGENT` 值 `'berry'`——与 bin.berry 同族的对外呈现值位）。
- 遇到已有代码中的品牌标识符，当次改动涉及该文件时顺手替换。

## 7. 架构纪律

- **已有机制优先**：问题出现先问「已有机制能不能解决」，再问「需不需要新概念」。90% 的问题应该用已有架构的自然延伸解决。
- **一个新概念必须解决多个问题才值得引入**。
- **补丁过多即重构**：需要在脑中维护「补丁关系图」才能理解某段代码，就该重构了。去掉这段代码架构概念数量若减少 = 它是补丁。
- 新增代码 < 修改架构 < 重新设计。

## 8. 日志纪律

自写轻量 logger（context 模块）。红线：**只在 debug 出现的分支，其行为必须同时是 durable 事件或运行时断言**——「看不见的 bug」不允许靠进程日志独扛。

## 9. 提交

- 一个逻辑完整的变更 = 一次 commit；不相关改动不混。稍大改动完成立即提交，不积攒。
- **逐文件点名 `git add`，慎用 `git add -A`**。
- 提交标题注明变更类型与范围（`feat(memory): ...` / `fix(tools): ...` / `docs: ...`）。

## 10. 并发协作

多 session 同时编辑同一批文件是常态——`file modified since read` 多为兄弟写入而非 bug，重读再改，别硬撞。

## 11. 发布（release 机器）

发布走机器不走人手：`npm run release`（`tools/release.mjs`，手写脚本，npm CLI 为唯一传输层）。六道契约按防线序排定——任一道红即响亮失败，无 skip 出口：

1. **门禁前置**：四门禁逐个真跑 + 工作树净空核验（禁发未提交态）。
2. **registry 探测**（只读三态）：`npm view <包名>@<版本> dist.shasum`——E404 缺席（正常发）/ 在场（进幂等比对）/ 其余不可达拒发。
3. **构建即打包与发布物验收**：清 dist 全新 build → pack 检视（白名单：bin 入口 / SPA / 技能资产 / README 必在；测试产物 / 声明 / 映射 / 源码 / 构建配置必不在）→ 真打包 → 安装冒烟（tarball 装临时 prefix 后 `berry --version` = 版本号）。
4. **幂等收口与 publish 单点**：registry 已有同字节版本（中断重跑态）跳过 publish、后续步骤照跑；同号异质响亮拒；上传物 = 本机打出的 tarball 本体（检视即所传）。触网写面全集 = publish / dist-tag add / git push tag 三点，除此之外零触网写。
5. **dist-tag 终态机器断言**：preview 期统一律 latest === next === 刚发版（alpha/rc 同律）；首个正式版起分叉（latest = 版本号、next 不动）。
6. **尾件 git tag**：`v<版本>` 幂等打挂（同 commit 跳过 / 异 commit 响亮拒）+ push origin。

```bash
npm run release -- --dry-run                  # 演习：门禁/构建/打包/冒烟真做，publish 干跑、写面全收
npm run release -- --dry-run --inject <谱项>  # 失败注入演习：gate-red / shasum-mismatch / assert-fail / interrupt-rerun
npm run release                               # 真发布（六道全跑）
```

失败注入谱与 `tools/release.test.mjs` 同表共用——**测试即演习留档**（注入场景全量收进常规测试面，无凭证也可回归发布机器的行为）。tarball 即用即清：发布收口后仓库根不残留打包产物。OTP 双因子经 `NPM_CONFIG_OTP` 环境变量透传 npm。
