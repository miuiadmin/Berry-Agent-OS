## 环境准备

### 依赖

- Vitest（`pool: 'forks'`, `testTimeout: 30000`, `maxForks: 4`）
- `better-sqlite3`（:memory: 模式用于单元模块测试）

### 环境变量

| 变量 | 用途 | 默认值 |
|------|------|--------|
| `BERRY_LLM_MODE` | LLM 模式：`mock` / `takeover` / `live` | `mock` |
| `BERRY_TEST_LIVE_API_KEY` | 真实测试 API Key | - |
| `LLM_API_KEY` | 备选 API Key | - |
| `LLM_BASE_URL` | 模型 API 地址 | - |
| `LLM_MODEL` | 模型名称 | - |
| `BERRY_TEST_DEBUG` | 启用 debug dump | `false` |

### 运行命令

```bash
npm test                                              # 全部测试（真实测试无 key 自动 skip）
npm test -- --watch                                   # watch 模式
npm test -- src/kernel/task-manager.test.ts           # 单文件
npm test -- --grep "任务生命周期"                      # 按描述过滤
npm run typecheck                                     # 提交前必过

# 真实测试（需 API Key）
BERRY_TEST_LIVE_API_KEY=sk-xxx npm test -- src/testing/real.test.ts
```

## 第 1 层：单元模块测试

### 何时使用

- 纯函数、类的确定性行为
- Schema 解析、数据转换
- 状态机流转
- DB 操作（使用 `:memory:` SQLite）
- 不涉及 IPC、socket 或进程间通信

### 文件命名

`<module>.test.ts`，与源文件同目录。

### 模板

```typescript
import { describe, it, expect, beforeEach } from 'vitest';
import { TaskManager } from './task-manager.js';

describe('TaskManager', () => {
  let tm: TaskManager;

  beforeEach(() => {
    // :memory: DB 或直接实例化
    tm = new TaskManager(/* :memory: db */);
  });

  it('创建任务返回有效 ID', () => {
    const taskId = tm.create({
      sessionId: 'sess-1',
      correlationId: 'corr-1',
      taskType: 'code_task',
      requester: 'test',
      targetAgent: 'code-agent',
      foreground: false,
      inputPayload: {},
    });
    expect(taskId).toMatch(/^task-/);
  });

  it('终态任务忽略重复 complete', () => {
    const taskId = tm.create({ /* ... */ });
    tm.dispatch(taskId);
    tm.start(taskId);
    tm.complete(taskId, { result: 'done' });

    // 第二次 complete 返回 false
    const ok = tm.complete(taskId, { result: 'again' });
    expect(ok).toBe(false);
  });
});
```

### 关键原则

- 只测公开 contract，不 import 其他模块内部实现
- 断言确定性输出，禁止断言 AI 生成内容
- 每个 `it` 只测一个行为点

## 第 2 层：1-to-1 测试

### 何时使用

- 单个模块与其真实依赖的协作验证
- 需要真实 SQLite / 文件 I/O，但不启动完整 CoreService
- Agent 单进程生命周期验证
- Socket handler 路由测试
- 权限链路验证

### 文件命名

`<module>-e2e.test.ts`

### 模板

```typescript
import { afterAll, beforeAll, describe, expect, it } from 'vitest';
import { createHermeticEnv } from '../testing/hermetic-env.js';

describe('Agent 生命周期 1-to-1', () => {
  let env: ReturnType<typeof createHermeticEnv>;

  beforeAll(() => {
    env = createHermeticEnv({ llmMode: 'mock' });
    // env.appHome 是临时 BERRY_HOME；测试代码在此目录下启动目标模块（Agent / HTTP 路由等）
  }, 30_000);

  afterAll(() => {
    env?.cleanup();
  }, 15_000);

  // 通过事件总线 / 任务终结事件等待任务完成，而非 harness.waitIdle
  // DB 访问走 env.appHome 下的 SQLite 文件
});
```

### Takeover 模式：精确控制 LLM 输出

`TakeoverController`（`src/testing/model-takeover.ts`）在生产 `takeover` 模式下由 `bootstrap.ts` 自动实例化并注入到 service 容器。1-to-1 测试启动目标 Agent 后，从 service 容器取出 controller 拦截模型请求并注入确定性回复：

```typescript
// takeover 模式下，bootstrap 实例化 TakeoverController 并注入 service 容器
const controller = serviceContainer.get('takeoverController')!;

// 并行：触发一次需要 LLM 的操作 + 等待拦截
const req = await controller.waitForRequest(10_000);
expect(req.agent).toBeDefined();
controller.respond(req.requestId, '这是测试回复');
```

### 1-to-1 与旧"集成测试"的区别

旧 Harness E2E 测试启动完整 CoreService + 所有 Agent 进程，是重量级全系统测试。1-to-1 测试只验证目标模块与其直接依赖，不启动完整系统，更快更聚焦。

## 第 3 层：真实测试（HTTP API 对话）

### 何时使用

- 验证完整后端 HTTP 服务 + 真实模型 API 的端到端兼容性
- Nightly CI / 手动运行，不阻塞 PR
- 依赖环境变量提供 API Key

### 核心原则

**必须像前端一样调用 CRUD HTTP API。** 不使用 harness 内部 socket 方法，而是通过 HTTP 接口交互，验证从 HTTP 请求到响应的完整链路。

### 模板

```typescript
import { afterAll, afterEach, beforeAll, describe, expect, it } from 'vitest';

const HAS_KEY = !!(process.env.BERRY_TEST_LIVE_API_KEY || process.env.LLM_API_KEY);

// 直接 fetch 后端 HTTP API（与前端完全相同的方式），不依赖任何包装类
const BASE = process.env.BERRY_TEST_BASE_URL ?? 'http://localhost:3888';

async function api(path: string, init?: RequestInit) {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: { 'content-type': 'application/json', ...(init?.headers ?? {}) },
  });
  if (!res.ok) throw new Error(`${path} -> ${res.status}`);
  return res.status === 204 ? null : res.json();
}

describe.skipIf(!HAS_KEY)('真实测试 — HTTP API 对话', () => {
  afterEach(() => {
    // 每个用例之间重置状态（按需）
  });

  it('通过 API 创建对话并发送消息', async () => {
    const conv = await api('/api/conversations', { method: 'POST', body: '{}' });
    expect(conv.id).toBeTruthy();

    const msg = await api(`/api/conversations/${conv.id}/messages`, {
      method: 'POST',
      body: JSON.stringify({ content: '1+1=?' }),
    });
    expect(msg.response?.length).toBeGreaterThan(0);
  }, 90_000);

  it('多轮对话保持上下文', async () => {
    const conv = await api('/api/conversations', { method: 'POST', body: '{}' });
    await api(`/api/conversations/${conv.id}/messages`, {
      method: 'POST', body: JSON.stringify({ content: '请记住数字 42' }),
    });
    const reply = await api(`/api/conversations/${conv.id}/messages`, {
      method: 'POST', body: JSON.stringify({ content: '我刚才说的数字是什么？' }),
    });
    // 不断言具体回复内容，只断言结构
    expect(reply.response?.length).toBeGreaterThan(0);
  }, 120_000);

  it('对话 CRUD 完整流程', async () => {
    const conv = await api('/api/conversations', { method: 'POST', body: '{}' });
    expect(conv.id).toBeTruthy();

    const list = await api('/api/conversations');
    expect(list.some((c: any) => c.id === conv.id)).toBe(true);

    const detail = await api(`/api/conversations/${conv.id}`);
    expect(detail.id).toBe(conv.id);

    await api(`/api/conversations/${conv.id}`, { method: 'DELETE' });
    const afterDelete = await api('/api/conversations');
    expect(afterDelete.some((c: any) => c.id === conv.id)).toBe(false);
  }, 60_000);

  it('Agent 状态查询', async () => {
    const agents = await api('/api/agents');
    expect(Array.isArray(agents)).toBe(true);
    expect(agents.length).toBeGreaterThan(0);
  }, 60_000);
});
```

### 真实测试断言原则

- **必须通过 HTTP API 交互**，禁止使用 harness 内部 socket 方法
- **不断言具体内容**（模型输出不确定）
- 断言 HTTP 层面的性质：
  - 状态码正确（200/201/204 等）
  - 响应 JSON 结构符合契约（字段存在、类型正确）
  - 响应非空
  - 无 error 返回
  - 对话能保持上下文（多轮消息关联同一 session）
  - WebSocket 事件与 HTTP API 状态一致
- 超时设置 90-120s
- 使用 `BERRY_TEST_LIVE_API_KEY` 或 `LLM_API_KEY` 环境变量

const env = createHermeticEnv({ llmMode: 'takeover' });

## 常见陷阱

### 1. 超时设置不够宽松

```typescript
// 错误：1-to-1 测试用默认 5s 超时
it('启动服务', async () => { /* ... */ });

// 正确：1-to-1 显式设置 15-30s
it('启动服务', async () => { /* ... */ }, 30_000);

// 真实测试设置 60-120s
it('真实对话', async () => { /* ... */ }, 90_000);
```

### 2. 忘记 afterAll 清理

```typescript
// 错误：泄漏进程和临时目录
afterAll(async () => {
  // 少了 env.cleanup()
});

// 正确：hermetic 环境必须显式清理
afterAll(async () => {
  if (env) await env.cleanup();
}, 30_000);
```

### 3. 真实测试断言具体内容

```typescript
// 错误：模型输出不确定
expect(result.response).toBe('1加1等于2。');

// 正确：只断言结构性质
expect(result.response.length).toBeGreaterThan(0);
expect(typeof result.response).toBe('string');
```

### 4. 1-to-1 测试未用 hermetic 环境

```typescript
// 错误：直接启动服务，读取 ~/.berry
const service = new CoreService();

// 正确：通过 createHermeticEnv 自动隔离
import { createHermeticEnv } from '../testing/hermetic-env.js';
const env = createHermeticEnv({ llmMode: 'mock' });
await env.start();
```

### 5. takeover 模式下 waitForRequest 超时

`TakeoverController` 接管时，如果 Agent 启动慢，等待 model request 可能超时：

```typescript
// 给足够的等待时间
const req = await controller.waitForRequest(10_000); // 不要用 1000
```

### 6. 断言 DB 状态时机

任务分发是异步的，断言 DB 前要等待：

```typescript
// 错误：发消息后立即查 DB
// tasks 可能为空！

// 正确：等待任务完成再查（用事件总线 / 任务终结事件等待，而非 harness.waitIdle）
await waitForTaskComplete(taskId, 10_000);
const tasks = db.prepare('SELECT * FROM agent_tasks').all();
```

### 7. 环境变量启用全局 debug

```bash
BERRY_TEST_DEBUG=1 npm test
```

## Hermetic 环境原理

`createHermeticEnv()` 做了以下隔离：

1. 创建临时 `BERRY_HOME`（`mkdtempSync`）
2. 清除所有 `ANTHROPIC_*`、`CLAUDE_*`、`OPENAI_*` 环境变量（live 模式除外）
3. 设置 `TZ=UTC`、`LANG=en_US.UTF-8`（消除本地化差异）
4. 设置 `BERRY_LLM_MODE`（控制 LLM 后端行为）
5. `cleanup()` 恢复所有环境变量 + 删除临时目录

这确保测试不会读写真实用户数据，也不会受机器环境影响。

## LLM 模式对比

| 模式 | 用途 | 模型调用 | 确定性 | 速度 |
|------|------|---------|--------|------|
| `mock` | 1-to-1 测试 | 返回固定空/模板响应 | 高 | 快 |
| `takeover` | 精确控制场景 | 测试代码拦截并注入响应 | 完全确定 | 快 |
| `live` | 真实测试 | 真实 API 调用 + 真实 HTTP 服务 | 不确定 | 慢 |

### 选择建议

- 验证单个模块确定性行为 → **单元模块测试**（无 LLM）
- 验证单模块与真实依赖协作 → **1-to-1 测试**（`mock` / `takeover`）
- 验证完整系统端到端 → **真实测试**（`live`，通过 HTTP API）
