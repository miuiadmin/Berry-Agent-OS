## 环境准备

### 依赖

- Vitest（`pool: 'forks'`, `testTimeout: 30000`, `maxForks: 4`）
- `better-sqlite3`（:memory: 模式用于单元测试）

### 环境变量

| 变量 | 用途 | 默认值 |
|------|------|--------|
| `BERRY_LLM_MODE` | LLM 模式：`mock` / `takeover` / `live` | `mock` |
| `BERRY_TEST_LIVE_API_KEY` | Smoke 测试 API Key | - |
| `LLM_API_KEY` | 备选 API Key | - |
| `LLM_BASE_URL` | 模型 API 地址 | - |
| `LLM_MODEL` | 模型名称 | - |
| `BERRY_TEST_DEBUG` | 启用 debug dump | `false` |

### 运行命令

```bash
npm test                                              # 全部测试（smoke 无 key 自动 skip）
npm test -- --watch                                   # watch 模式
npm test -- src/kernel/task-manager.test.ts           # 单文件
npm test -- --grep "任务生命周期"                      # 按描述过滤
npm run typecheck                                     # 提交前必过

# Smoke 测试
BERRY_TEST_LIVE_API_KEY=sk-xxx npm test -- src/testing/smoke.test.ts
```

## 第 1 层：单元测试

### 何时使用

- 纯函数、类的确定性行为
- Schema 解析、数据转换
- 状态机流转
- DB 操作（使用 `:memory:` SQLite）
- 不涉及 IPC、socket 或进程间通信

### 文件命名

`<module>.test.ts`，与源文件同目录。

### 模板

```typescript
import { describe, it, expect, beforeEach } from 'vitest';
import { TaskManager } from './task-manager.js';

describe('TaskManager', () => {
  let tm: TaskManager;

  beforeEach(() => {
    // :memory: DB 或直接实例化
    tm = new TaskManager(/* :memory: db */);
  });

  it('创建任务返回有效 ID', () => {
    const taskId = tm.create({
      sessionId: 'sess-1',
      correlationId: 'corr-1',
      taskType: 'code_task',
      requester: 'test',
      targetAgent: 'code-agent',
      foreground: false,
      inputPayload: {},
    });
    expect(taskId).toMatch(/^task-/);
  });

  it('终态任务忽略重复 complete', () => {
    const taskId = tm.create({ /* ... */ });
    tm.dispatch(taskId);
    tm.start(taskId);
    tm.complete(taskId, { result: 'done' });

    // 第二次 complete 返回 false
    const ok = tm.complete(taskId, { result: 'again' });
    expect(ok).toBe(false);
  });
});
```

### 关键原则

- 只测公开 contract，不 import 其他模块内部实现
- 断言确定性输出，禁止断言 AI 生成内容
- 每个 `it` 只测一个行为点

## 第 2 层：集成测试（Harness E2E）

### 何时使用

- 多模块协作（Agent 生命周期、IPC 通信、DB 状态链路）
- 需要真实启动 CoreService + Agent 进程
- 验证 socket handler 路由
- 权限链路端到端验证

### 文件命名

`<module>-e2e.test.ts`

### 模板

```typescript
import { afterAll, beforeAll, describe, expect, it } from 'vitest';
import { TestHarness } from '../testing/harness.js';

describe('Agent 生命周期 E2E', () => {
  let harness: TestHarness;

  beforeAll(async () => {
    harness = new TestHarness({ llmMode: 'mock' });
    await harness.start();
  }, 30_000);

  afterAll(async () => {
    if (harness) await harness.stop();
  }, 15_000);

  it('发送消息获得非空回复', async () => {
    const result = await harness.sendMessage('hello');
    expect(result.response).toBeTruthy();
    expect(result.sessionId).toBeTruthy();
  }, 15_000);

  it('waitIdle 等待所有任务完成', async () => {
    await harness.sendMessage('trigger a task');
    await harness.waitIdle(10_000);

    const db = harness.getDb();
    const stuck = db.prepare(
      `SELECT COUNT(*) as cnt FROM agent_tasks WHERE status NOT IN ('completed','failed','cancelled','timeout')`
    ).get() as { cnt: number };
    expect(stuck.cnt).toBe(0);
  }, 20_000);
});
```

### Takeover 模式：精确控制 LLM 输出

```typescript
import { TestHarness } from '../testing/harness.js';

describe('Takeover 模式', () => {
  let harness: TestHarness;

  beforeAll(async () => {
    harness = new TestHarness({ llmMode: 'takeover' });
    await harness.start();
  }, 30_000);

  it('拦截模型请求并注入回复', async () => {
    const controller = harness.getTakeoverController()!;

    // 并行：发消息 + 等待拦截
    const msgPromise = harness.sendMessage('写一首诗');
    const req = await controller.waitForRequest(5000);

    expect(req.agent).toBeDefined();
    expect(req.purpose).toBeDefined();

    // 注入确定性回复
    controller.respond(req.requestId, '这是测试回复');

    const result = await msgPromise;
    expect(result.response).toContain('测试回复');
  }, 15_000);
});
```

## 第 3 层：Smoke 测试（真实模型）

### 何时使用

- 验证完整链路与真实模型 API 的兼容性
- Nightly CI / 手动运行，不阻塞 PR
- 依赖环境变量提供 API Key

### 模板

```typescript
import { afterAll, afterEach, beforeAll, describe, expect, it } from 'vitest';
import { resolveRealTestConfig, applyRealTestEnv } from '../cli/real-test-profile.js';
import { TestHarness } from './harness.js';
import { createLiveContext, sendWithRetry, assertNoErrors, assertModelCallCount } from './live-test-helpers.js';
import type { LiveTestContext } from './live-test-context.js';

const HAS_KEY = !!(process.env.BERRY_TEST_LIVE_API_KEY || process.env.LLM_API_KEY);

describe.skipIf(!HAS_KEY)('Smoke — 功能场景', () => {
  let harness: TestHarness;
  let ctx: LiveTestContext;
  let applied: ReturnType<typeof applyRealTestEnv>;

  beforeAll(async () => {
    const config = resolveRealTestConfig({ profile: 'override' });
    applied = applyRealTestEnv(config);
    harness = new TestHarness({ llmMode: 'live', timeoutMs: 120_000 });
    await harness.start();
    ctx = createLiveContext(harness, { debugOnFailure: true });
  }, 120_000);

  afterEach((testCtx) => {
    if (testCtx.task.result?.state === 'fail') {
      ctx.dumpOnFailure(testCtx.task.name);
    }
    ctx.reset();
  });

  afterAll(async () => {
    if (harness) await harness.stop();
    if (applied) applied.cleanup();
  }, 30_000);

  it('简单问答', async () => {
    const result = await sendWithRetry(harness, ctx, '1+1=?');
    expect(result.response.length).toBeGreaterThan(0);
    assertModelCallCount(ctx, { min: 1, max: 5 });
    assertNoErrors(ctx);
  }, 60_000);
});
```

### Smoke 断言原则

- **不断言具体内容**（模型输出不确定）
- 只断言结构性质：非空、类型正确、无 error、session 保持
- 使用 `sendWithRetry` 处理偶发网络问题
- 超时设置 60-90s

## TestHarness API

```typescript
class TestHarness {
  constructor(options?: HarnessOptions);

  // 生命周期
  start(): Promise<void>;               // 启动 CoreService + 等待 Agent ready
  stop(): Promise<void>;                 // 优雅停止 + 清理临时目录

  // 消息发送
  sendMessage(msg: string, sessionId?: string): Promise<MessageResult>;
  sendMessageStreaming(msg: string, sessionId?: string): Promise<StreamingResult>;

  // 任务
  dispatchEvolutionTask(input: {
    taskType: 'learning_review' | 'skill_task' | 'plugin_task' | 'code_task';
    sessionId?: string;
    inputPayload?: Record<string, unknown>;
  }): Promise<Record<string, unknown>>;
  waitIdle(maxWaitMs?: number): Promise<void>;  // 等待所有 agent_tasks 终结

  // 状态访问
  getDb(): Database.Database;            // 访问测试 DB
  getStatus(): Promise<AgentStatusMap>;  // 查询 Agent 状态
  getEventBus(): EventBus | null;        // 获取事件总线
  getTakeoverController(): TakeoverController | null;
  getAppHome(): string;                  // 临时 BERRY_HOME 路径
  getIpcCapture(): IpcCapture;           // IPC 消息录制

  // Live context
  setLiveContext(hook: LiveContextHook): void;
}
```

### HarnessOptions

```typescript
interface HarnessOptions {
  timeoutMs?: number;       // socket 请求超时（默认 30000）
  llmMode?: 'mock' | 'takeover' | 'live';
  liveContext?: LiveContextHook;
}
```

### MessageResult / StreamingResult

```typescript
interface MessageResult {

interface StreamingResult {
  chunks: StreamingChunk[];
  finalResponse: string;
  sessionId: string;
  taskId: string;
  progressEvents: Array<{ status: string; summary: string }>;
```

## LiveTestContext API

`LiveTestContext` 是 Smoke 测试的核心检查工具，自动收集 span、日志、事件、model request 等信息。

### 创建

```typescript
const ctx = createLiveContext(harness, { debugOnFailure: true });
```

### 查询方法

| 方法 | 返回 | 说明 |
|------|------|------|
| `getModelRequests(filter?)` | `ModelRequestRecord[]` | 查询 model_requests 表 |
| `getLastRequest()` | `ModelRequestRecord \| null` | 最近一次请求 |
| `countRequests(filter?)` | `number` | 请求计数 |
| `getTotalTokens()` | `{ input, output, total }` | 累计 token 用量 |
| `getTotalLlmLatency()` | `number` (ms) | 累计 LLM 延迟 |
| `getAgentTasks(filter?)` | `TaskRecord[]` | 查询 agent_tasks 表 |
| `getTaskTimeline(sessionId?)` | `TaskRecord[]` | 任务时间线 |
| `getToolCalls(filter?)` | `ToolCallRecord[]` | 查询 tool_calls 表 |
| `countToolCalls(filter?)` | `number` | 工具调用计数 |
| `getApprovalRequests(filter?)` | `ApprovalRecord[]` | 权限审批记录 |
| `getSpans()` | `Span[]` | 所有 trace span |
| `getSpanTree()` | `SpanTreeNode[]` | 树形 span 结构 |
| `getSpansByName(name)` | `Span[]` | 按名称过滤 span |
| `getSpansByAttribute(key, value?)` | `Span[]` | 按属性过滤 span |
| `getLogs(filter?)` | `LogEntry[]` | 运行时日志 |
| `getLogErrors()` | `LogEntry[]` | error 级别日志 |

| `getIOTranscript()` | `IOEntry[]` | socket I/O 记录 |
| `getIpcMessages(filter?)` | `CapturedMessage[]` | IPC 消息捕获 |
| `getIpcFlow(correlationId)` | `CapturedMessage[]` | 按 correlationId 追踪 |
| `getMetricsSnapshot()` | `MetricsSnapshot` | 运行时指标快照 |
| `buildDebugDump()` | `TestDebugDump` | 完整调试快照 |

## Fixture 录制与回放

Fixture 系统用于在 takeover 模式下录制 LLM 交互，后续可确定性回放。

### Fixture 数据结构

```typescript
interface FixtureData {
  name: string;
  description?: string;
  userMessage: string;
  interactions: FixtureInteraction[];
  expectedResponse?: string;
}

interface FixtureInteraction {
  request: {
    agent: string;
    purpose: string;
    modelTier?: string;
    promptHash?: string;
    toolsHash?: string;
  };
  response: {
    content: string;
    toolCalls?: Array<{ id: string; name: string; input: Record<string, unknown> }>;
    stopReason?: string;
  };
  expect?: FixtureExpectation;
}
```

### 录制 Fixture

```typescript
import { saveFixture, type FixtureData } from '../testing/fixtures.js';

// 在 takeover 模式中手动构建
const fixture: FixtureData = {
  name: 'simple-chat',
  description: '简单问答场景',
  userMessage: '你好',
  interactions: [
    {
      request: { agent: 'brain', purpose: 'routing' },
      response: { content: JSON.stringify({ intent: 'chat', targetAgent: 'conversation' }) },
    },
    {
      request: { agent: 'conversation', purpose: 'chat' },
      response: { content: '你好！有什么可以帮你的？' },
    },
    {
      request: { agent: 'brain', purpose: 'review' },
      response: { content: JSON.stringify({ verdict: 'approve' }) },
    },
  ],
};

saveFixture('tests/fixtures/simple-chat.json', fixture);
```

### 回放 Fixture

```typescript
import { loadFixture, replayFixture } from '../testing/fixtures.js';

it('回放简单对话 fixture', async () => {
  const fixture = loadFixture('tests/fixtures/simple-chat.json');
  const result = await replayFixture(harness, fixture, { timeoutMs: 10_000 });

  expect(result.matchedAll).toBe(true);
  expect(result.mismatches).toHaveLength(0);
  expect(result.response).toContain('你好');
});
```

## ConversationBuilder 多轮测试

用于构建多轮对话测试场景，支持每轮后断言。

```typescript
import { ConversationBuilder } from '../testing/conversation-builder.js';

it('多轮对话保持上下文', async () => {
  const result = await new ConversationBuilder(harness, ctx)
    .turn('请记住数字 42')
    .assertResponse((r) => expect(r.length).toBeGreaterThan(0))
    .turn('我刚才说的数字是什么？')
    .assertResponse(/42/)
    .assertAfterTurn((ctx) => {
      assertModelCallCount(ctx, { min: 2 });
    })
    .assertFinal((result, ctx) => {
      expect(result.turns).toHaveLength(2);
      expect(result.sessionId).toBeTruthy();
      assertNoErrors(ctx);
    })
    .withRetry({ maxRetries: 1 })
    .run();
});
```

## 调试工具

### dumpOnFailure

在 `afterEach` 中配置，测试失败时自动输出完整调试信息到 stderr：

```typescript
const dump = ctx.buildDebugDumpJSON();
```

## 常见陷阱

### 1. 超时设置不够宽松

```typescript
// 错误：集成测试用默认 5s 超时
it('启动服务', async () => { /* ... */ });

// 正确：E2E 显式设置 15-30s
it('启动服务', async () => { /* ... */ }, 30_000);

// Smoke 测试设置 60-90s
it('真实对话', async () => { /* ... */ }, 60_000);
```

### 2. 忘记 afterAll 清理

```typescript
// 错误：泄漏进程和临时目录
afterAll(async () => {
  await harness.stop();
  // 少了 applied.cleanup()
});

// 正确
afterAll(async () => {
  if (harness) await harness.stop();
  if (applied) applied.cleanup();
}, 30_000);
```

### 3. Smoke 测试断言具体内容

```typescript
// 错误：模型输出不确定
expect(result.response).toBe('1加1等于2。');

// 正确：只断言结构性质
expect(result.response.length).toBeGreaterThan(0);
expect(typeof result.response).toBe('string');
```

### 4. 集成测试未用 hermetic 环境

```typescript
// 错误：直接启动服务，读取 ~/.berry
const service = new CoreService();

// 正确：通过 TestHarness 自动隔离
const harness = new TestHarness({ llmMode: 'mock' });
await harness.start();
```

### 5. ctx.reset() 遗漏

每个 `it` 之间必须 reset，否则上一个用例的 span/log/event 会污染下一个：

```typescript
afterEach(() => {
  ctx.reset();
});
```

### 6. waitForRequest 超时

takeover 模式下，如果 Agent 启动慢，`waitForRequest` 可能超时：

```typescript
// 给足够的等待时间
const req = await controller.waitForRequest(10_000); // 不要用 1000
```

### 7. 并行测试竞争

Vitest 默认并行执行测试文件。E2E 测试启动完整 CoreService，端口/socket path 会冲突：

- 每个 E2E 测试使用独立的 `TestHarness`（内部 hermetic 环境自动隔离）
- 不要在 E2E 测试之间共享全局状态
- `maxForks: 4` 限制并发数

### 8. 断言 DB 状态时机

任务分发是异步的，断言 DB 前要等待：

```typescript
// 错误：发消息后立即查 DB
await harness.sendMessage('do something');
const tasks = db.prepare('SELECT * FROM agent_tasks').all();
// tasks 可能为空！

// 正确：等待任务完成
await harness.sendMessage('do something');
await harness.waitIdle(10_000);
const tasks = db.prepare('SELECT * FROM agent_tasks').all();
```

## Hermetic 环境原理

`createHermeticEnv()` 做了以下隔离：

1. 创建临时 `BERRY_HOME`（`mkdtempSync`）
2. 清除所有 `ANTHROPIC_*`、`CLAUDE_*`、`OPENAI_*` 环境变量（live 模式除外）
3. 设置 `TZ=UTC`、`LANG=en_US.UTF-8`（消除本地化差异）
4. 设置 `BERRY_LLM_MODE`（控制 LLM 后端行为）
5. `cleanup()` 恢复所有环境变量 + 删除临时目录

这确保测试不会读写真实用户数据，也不会受机器环境影响。

## LLM 模式对比

| 模式 | 用途 | 模型调用 | 确定性 | 速度 |
|------|------|---------|--------|------|
| `mock` | 集成测试 | 返回固定空/模板响应 | 高 | 快 |
| `takeover` | 精确控制场景 | 测试代码拦截并注入响应 | 完全确定 | 快 |
| `live` | Smoke 测试 | 真实 API 调用 | 不确定 | 慢 |

### 选择建议

- 验证多模块协作逻辑 → `mock`
- 验证特定 prompt 链路和工具调用 → `takeover`
- 验证模型兼容性和完整端到端 → `live`
