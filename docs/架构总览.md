# 架构总览

> Berry 1.0 的整体架构：三环装配模型、模块 DAG、事件系统、组合根装配序、插件装载机制。本文是公开面的架构文档，面向贡献者与插件作者；实现细节以代码与模块注释为准。

## 1. 核心命题

Berry 是 **Berry Agent OS——跑 AI 应用的个人操作系统**。固定内核只司四职能：

```
装（组合树装载插件）· 跑（loop 骨架承载运行）· 守（安全栈拦险）· 存（事件日志落史）
```

装载件分三种产品角色，一句话判据：**被启动的是应用，被调用的是库，被依赖的是后台服务**。

| 角色 | 判据 | 例 |
|---|---|---|
| **应用** | 被启动为运行（前台会话 / 后台 job），带自己的 agent | 对话应用 `builtin:chat`（第二官方应用，当前默认入口）；代码智能体应用（预装默认应用的终态——coding 优先，待 exec 工具族纵切后组装，落地前由对话应用兼任） |
| **库** | 被调用，无自有运行实例 | fs 工具族、技能包 |
| **后台服务** | 被依赖，常驻服务而非被用户打开 | memory（消费事件流、跨会话注入） |

**对话是应用，不是内核**：首启 TUI 进入的对话体验是第一方预装应用——内核只提供执行原语（loop 骨架之于 agent 运行，如 CPU 之于进程），连默认对话都没有；同一 OS 可装不同的对话应用。当前官方默认层首行即 `builtin:chat` 对话应用：组合根只持活引用槽，会话选择/续接、驱动构造、durable 绑定全部在件内完成。预装默认应用的终态是**代码智能体应用**（coding 优先的第一场景），组装待 exec 工具族落地。

每一次应用运行转的是同一条核心循环：

```
问（用户输入）→ 做（LLM 循环 + 工具）→ 守（安全栈守护）→ 存（事件日志持久）
```

两条设计红线：

1. **内核不感知任何增强域**。记忆、子代理、目标管理……在内核里没有概念位——它们是插件在扩展点上的注册物。卸载官方全家桶，核心循环照常运转。
2. **双重自进化走涌现路径**。使用进化（越用越懂你）与技能进化（SKILL.md 沉淀）由插件组合涌现，不设中枢调度器 / 议会 / 进化引擎。

应用面机制（应用清单声明、启动面、应用级授权与预算账户）设计已定稿，随 M2+ 落地——第一纵切 `builtin:chat` 对话应用已落码（默认层首行，驱动装配在件内）。

## 2. 三环装配

| 环 | 定义 | 当前成员 | 判据 |
|----|------|----------|------|
| **Ring 0 内核** | 不可卸载的宿主 | 11 个模块（= 17 有码 − Ring 2 增强六件〔官方五件 + skills〕；下表 Ring 1 行四件**含于其中**为可换子集，非另计。见 §3） | 卸掉它，进程无法自举 |
| **Ring 1 底座** | 可换不可缺位 | persist（SQLite）/ llm（pi-ai 适配）/ tools（三段管道 + 检索族）/ exec（命令执行管道 + bash 工具） | 卸掉它，首启核心循环「问→做→守→存」断 |
| **Ring 2 增强** | 真·可卸 | 官方全家桶五件：`chat`（对话应用，默认层首行）/ `memory` / `subagent` / `goal` / `scheduler`（定时任务，默认层第五行）（+ 技能、通道命令等扩展） | 核心循环完好，只少长进与便利 |
| Ring 3 生态 | 第三方插件 | （未开放） | — |

一句话判据：**卸掉它首启核心循环断 → 底座；核心循环完好、只少长进与便利 → 增强。**

Ring 2 默认装配 = 官方全家桶（写好一个默认随包一个）。每一件经 `/plugin-toggle` 即减，减掉不破坏任何内核承诺。

## 3. 模块 DAG

18 个模块单向依赖（拓扑白名单由 `tools/check-topology.mjs` 钉死，`npm run lint:topology` 验证；17 有码 + mcp 一席占位〔exec 2026-08-25、scheduler tick 2026-08-26 入册〕。chat/exec 为件聚落单列——件口径与模块口径同图）：

```
contracts   L0 公共契约：错误码注册表（AppError 单基类 + 字符串码）、LLM 消息/流/
            消息角色 + 会话事件词汇注册表（插件面域名式/核心词宿主留）、工具/事件类型、插件契约
context     L1 运行时基座：作用域（effect LIFO 回卷 / fork 级联 / stale 护栏）、
            事件四模式（emit/serial/parallel/waterfall）、服务注册表 provide/get、自写 logger、
            canonical 工作区根（git commondir 归并 + project-aliases 重定向）
session     会话事件日志（append-only + surfaceOp 遮蔽 + 64KiB 护栏 + 恢复合成 + 投影 derive）
persist     SQLite 物理层（统一迁移框架 user_version 门禁 + write-behind 批落 +
            凭证/模型目录 Store 适配）
agent       loop 骨架（AgentEvent 10 型、steering/followUp、convertToLlm）
llm         pi-ai 适配（模型标识解析 / Models 宿主 / StreamFn 永不抛错 / ctx.llm.complete）
tools       三段管道（schema 校验 → 守门 → 执行）+ fs 工具族（CAS 观察态 / 可写根 fence）
            + 检索族 find/grep（gitignore 遍历 / 正则 / glob 过滤——只读免批）
safety      沙箱三档 + 审批对 + carve-out + 可写根推导（守门行安装进工具管道）
skills      SKILL.md 双层结构 + 注册表 + 渐进披露注入系统提示词
channels    TUI 通道 + 命令面（registerCommand / registerRenderer）
chat        官方件·件聚落 src/chat/：对话应用（ConversationDriver 驱动 + durable 接线 +
            resume 续接 + ctx.agent provide——默认层首行 builtin:chat，对话是应用不是内核）
memory      官方件：记忆库（表族/合并管线/提取双路/双路注入/检索/效用进化/差分追注）
subagent    官方件：Job 注册表（ctx.jobs）+ SubagentProvider 契约 + in-process provider
goal        官方件：goals 表 + 五值状态机 + 工具三件 + 预算刹车 + 续跑触发
scheduler   官方件：jobs 表 v7（reserve-then-run 执行前抢占）+ /tick add|list|rm|run
            命令面（第一刀手动触发；runner = 子进程 berry run --read-only 单发）
exec        官方件·件聚落 src/exec/：spawn 管道（失败二分 / 进程组树杀 / 60KiB 保尾预算 /
            env 白名单 deny-by-default）+ bash 工具件（升权词汇首个消费者）+
            ctx.exec 服务（内部 def 同管道不旁路）+ environment 披露段
app         组合根：装配序（ctx→通道→持久→llm→工具→安全→技能→插件装载→命令）+
            CLI 三入口 + /reload（对话驱动装配已迁 chat 件，组合根纯「装」）
```

依赖方向只能从上往下；跨模块只能 import 对方 `contract.ts` / `types.ts` / `index.ts` 公共面。`@earendil-works/pi-ai` 裸导入仅允许出现在 `src/llm/`。

## 4. 事件系统（三族词汇，全部显式注册）

| 族 | 载体 | 词汇量 | 校验 |
|----|------|--------|------|
| **运行时总线事件** | `ctx.emit` / `ctx.on`（context 模块） | 16 项 | `tools/check-events.mjs` 双向断言 |
| **AgentEvent（loop 内活体事件）** | agent loop 产出 → 组合根接线落库/上屏 | 10 型 | 同上 |
| **SessionEvent（durable 会话事件）** | `session.append` 写入 append-only 日志 | 15 类（核心 14 + 插件扩展 `memory/diff`） | 同上 |

纪律：

- 每个事件词汇在 `LIVE_EVENT_CATALOG` / 事件类型注册表**显式注册**——注册即写入许可，无 declaration merging。
- 读侧遇未知类型且非 `ignorable`：**整体拒绝解读**（`SESSION_FORMAT_UNSUPPORTED`），宁拒绝不静默丢。
- 插件可注册自有 surface / log-only 事件词汇（首例：memory 插件的 `memory/diff`，surface 类别）；核心词汇（user/message 等）的写入权属宿主，插件经 `ctx.sessions.appendEvent` 伪造内核词会被 `SESSION_CORE_TYPE_FORBIDDEN` 响亮拒绝。

## 5. 会话模型：事件日志 + 投影

- **事实只有一份**：append-only 事件日志（`events` 表）。模型历史、UI 时间线、检索索引全部是日志的**投影**（derive），可随时重建。
- **遮蔽而非删除**：compaction / surfaceOp 以遮蔽事件表达「这段不再进模型上下文」，原始事件永不物理删除——审计与回放完整。
- **分叉**：任意事件前缀可种子分叉出子会话（subagent 委派即用此机制，origin='delegation'）；边界必须落在已结算的 turn 上。
- **恢复**：进程重启后从日志重放合成运行时态；TUI 启动缺省续接当前目录最新会话（`/new` 开新会话）。
- **护栏**：单事件 64KiB 上限；write-behind 批落 + 落盘屏障（flush）。

## 6. 组合根装配序（src/app/assembly.ts）

```
ctx（createContext，① 根作用域）
 ├─ ①b project-aliases 表装载（canonical 根重定向——数据目录别名表，一次装载）
 ├─ ② 通道/UI 服务（channels + ui 聚合器）
 ├─ ③ 持久层（persist Store；persist:false 时全链降级；durable 转发壳在此）
 ├─ ④ llm 运行时（pi-ai Models 宿主 + StreamFn）+ 具名服务族
 │     （llm.complete / jobs / subagents / sessions；ctx.agent 随 chat 件）
 ├─ ⑤ 工具注册表 + 三段管道（fs 四件 + 检索两件在此注册，bash 工具件在 ⑥b 审批服务后注册；gate/decision 落 durable）
 ├─ ⑥ 审批 + 守门行（安全栈接线：审批对 + 沙箱档 + 可写根推导）
 ├─ ⑦ 技能注册表 + 具名提示词段服务（ctx.prompts）
 ├─ ⑧ 装载层接线（tools_change 等活视图刷新义务——驱动本体随 chat 件）
 ├─ ⑨ 插件装载（组合树合成 → jiti 加载 → Kahn 轮次激活）
 │     └─ 默认层首行 builtin:chat 对话应用件：件内即完成会话选择/续接、
 │        驱动构造（ConversationDriver：launch 防重入 + steering + followUp）、
 │        durable 绑定与 ctx.agent provide——其后 memory / subagent / goal
 │        与文件插件完全同轨装载
 ├─ ⑨b 内置命令（help/quit/new/skills + 插件管理五件〔含 /reload〕）
 └─ ⑩ 交互模式审批接线（ctx.ui 应答；headless fail-closed）
```

服务提供时点全部早于插件装载——插件 `inject` 即得（Kahn 轮次按依赖排序激活；缺服务 = 启动断言拒启）。

## 7. 插件装载（组合树 + jiti）

- **组合树**：默认层（官方全家桶四行：chat 对话应用〔首行〕/ memory / subagent / goal）+ `~/.berry/overlay.yaml` 字段级覆写（行字段 `id` / `plugin` / `config` / `disabled` / `fixed`，未知字段拒绝式）。同名行后写胜出。
- **加载**：文件插件入口解析顺序 `harness.extensions` → `extensions/index` → `index`；未安装的行标记 `unresolved`，**永不自动安装**（装机是 operator 动作：`/plugin-install`）。
- **执行**：jiti 加载 entry.ts（moduleCache 关闭，/reload 可重载）；形状校验（named export 走 `Object.hasOwn` 防 jiti 命名空间穿透冒充）；apply 抛错先 fork LIFO 回卷已激活件再进失败清单。
- **生命周期事件**：`plugin/activated` / `plugin/failed` / `plugin/skipped` 落 durable 日志；失败行非空 = 启动断言拒启（聚合清单一次抛全）。
- **热重载**：`/reload` = 卸载半边（dispose 回卷全部注册）→ 重读组合树 → 重装。

插件形态与扩展点词汇的完整说明见 [插件开发指南](插件开发指南.md)。

## 8. 存储布局（SQLite 单库 + 统一迁移）

`~/.berry/sessions.db`（WAL 模式），`PRAGMA user_version` 门禁递进：

| user_version | 内容 |
|---|---|
| 1（基线） | `events` / `sessions` / `store_state` / `projection_checkpoints` / `credentials` / `model_catalog` |
| 2 | memory 表族：`memories` + `memory_fts`（trigram） |
| 3 | `session_fts`（跨会话检索投影）+ `session_fts_state` |
| 4 | memories 增列 `usage_count` / `last_used_at`（效用进化） |
| 5 | `goals` 表（goal 插件） |

迁移框架规则：只前进不回退；库内 version 高于宿主已知 = **拒绝打开**（宁拒绝不误读）；DDL 与 `user_version` 前进同事务，半迁移状态不可见。
