# 架构总览

> Berry 1.0 的整体架构：三环装配模型、模块 DAG、事件系统、组合根装配序、插件装载机制。本文是公开面的架构文档，面向贡献者与插件作者；实现细节以代码与模块注释为准。

## 1. 核心命题

Berry 是 **Berry Agent OS——跑 AI 应用的操作系统**。固定内核只司四职能：

```
装（组合树装载插件）· 跑（loop 骨架承载运行）· 守（安全栈拦险）· 存（事件日志落史）
```

装载件分三种产品角色，一句话判据：**被启动的是应用，被调用的是库，被依赖的是后台服务**。

| 角色         | 判据                                                | 例                                                                                                                                                                                     |
| ------------ | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **应用**     | 被启动为运行（前台会话 / 后台 job），带自己的 agent | 对话应用 `builtin:chat`（当前默认入口；代码智能体应用转正后退居第二官方应用）；代码智能体应用（预装默认应用的终态——coding 优先，命令执行纵切已落、组装随下一批，落地前由对话应用兼任） |
| **库**       | 被调用，无自有运行实例                              | fs 工具族、技能包                                                                                                                                                                      |
| **后台服务** | 被依赖，常驻服务而非被用户打开                      | memory（消费事件流、跨会话注入）                                                                                                                                                       |

**对话是应用，不是内核**：首启 TUI 进入的对话体验是第一方预装应用——内核只提供执行原语（loop 骨架之于 agent 运行，如 CPU 之于进程），连默认对话都没有；同一 OS 可装不同的对话应用。当前官方默认层首行即 `builtin:chat` 对话应用：组合根只持活引用槽，会话选择/续接、驱动构造、durable 绑定全部在件内完成。预装默认应用的终态是**代码智能体应用**（coding 优先的第一场景），命令执行纵切已落，组装随下一批。

每一次应用运行转的是同一条核心循环：

```
问（用户输入）→ 做（LLM 循环 + 工具）→ 守（安全栈守护）→ 存（事件日志持久）
```

两条设计红线：

1. **内核不感知任何增强域**。记忆、子代理、目标管理……在内核里没有概念位——它们是插件在扩展点上的注册物。卸载官方全家桶，核心循环照常运转。
2. **双重自进化走涌现路径**。使用进化（越用越懂你）与技能进化（SKILL.md 沉淀）由插件组合涌现，不设中枢调度器 / 议会 / 进化引擎。

应用面机制（应用清单声明、启动面、多应用并行、应用级授权与预算账户）已落码——`builtin:chat` 对话应用为默认层首行（驱动装配在件内），`/app` 四动词（裸清单 / new 驻留 / 序号|id 前缀切换 / 清单 id 进入——带消息则进入后作为首条用户消息直接提交）可切换驻留的前台应用。

**应用与插件的装载关系（应用中心装载面——四刀序 D1-D4，D1/D2 已落码）**：应用是独立安装物——有自己的代码、主题与程序，以 npm 三源分发上「市场」（不自建商店）；插件是通用件，装在哪个应用上都行，但**独立不生效**——装机只入仓库（`install` = 仓库态，零生效），写组合行挂载才生效（挂载独立动词，D2 已落码）。挂载目标两档：**系统组合**（行缺省——母体 = OS，官方件全挂此档服务所有应用，memory 跨应用积累即「操作者状态长在同一份上」的机制面）与**应用组合**（行带 `app: <应用id>`——母体 = 该应用，第三方能力件的档位：组成面/授权面/预算随宿主应用收拢）。系统组合 v1 官方专属；应用组合件可依赖系统组合件，反向与跨应用不可。四刀序：D1 清单投影（已落码）→ D2 装机/挂载两态（已落码）→ D3 per-app reload → D4 应用主题。

## 2. 三环装配

| 环              | 定义           | 当前成员                                                                                                                                                                                                                                               | 判据                                  |
| --------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| **Ring 0 内核** | 不可卸载的宿主 | 12 个模块：contracts / context / session / agent / safety / channels / app / bridge（固定八件）+ Ring 1 行四件（persist / llm / tools / exec——可换子集，下表另列非另计。见 §3）                                                                        | 卸掉它，进程无法自举                  |
| **Ring 1 底座** | 可换不可缺位   | persist（SQLite）/ llm（pi-ai 适配）/ tools（三段管道 + 检索族）✅ 已挂组合树默认层（`builtin:tools` 必备行——禁用即拒启，2026-08-26 行树化首刀）/ exec（命令执行管道 + bash 工具）                                                                     | 卸掉它，首启核心循环「问→做→守→存」断 |
| **Ring 2 增强** | 真·可卸        | 官方全家桶（默认层十行中的九行）：`chat`（对话应用，默认层首行）/ `memory` / `subagent` / `goal` / `scheduler`（定时任务）/ `mcp` / `web` / `compaction`（长会话压缩）/ `admin`（平台管理面）（+ 技能、通道命令等扩展；第七行 `tools` 为 Ring 1 必备） | 核心循环完好，只少长进与便利          |
| Ring 3 生态     | 第三方插件     | 市场口径 = npm 三源（设计已定）；第三方件挂**应用组合**（系统组合 v1 官方专属）；开放随应用中心装载面推进（D1/D2 已落码，D3/D4 在序）                                                                                                                  | —                                     |

一句话判据：**卸掉它首启核心循环断 → 底座；核心循环完好、只少长进与便利 → 增强。**

Ring 2 默认装配 = 官方全家桶（写好一个默认随包一个）。每一件经 `/plugin-toggle` 即减，减掉不破坏任何内核承诺。

## 4. 事件系统（三族词汇，全部显式注册）

| 族                                   | 载体                                   | 词汇量                       | 校验                              |
| ------------------------------------ | -------------------------------------- | ---------------------------- | --------------------------------- |
| **运行时总线事件**                   | `ctx.emit` / `ctx.on`（context 模块）  | 26 项                        | `tools/check-events.mjs` 双向断言 |
| **AgentEvent（loop 内活体事件）**    | agent loop 产出 → 组合根接线落库/上屏  | 10 型                        | 同上                              |
| **SessionEvent（durable 会话事件）** | `session.append` 写入 append-only 日志 | 21 类（核心词 + 插件扩展面） | 同上                              |

纪律：

- 每个事件词汇在 `LIVE_EVENT_CATALOG` / 事件类型注册表**显式注册**——注册即写入许可，无 declaration merging。
- 读侧遇未知类型且非 `ignorable`：**整体拒绝解读**（`SESSION_FORMAT_UNSUPPORTED`），宁拒绝不静默丢。
- 插件可注册自有 surface / log-only 事件词汇（首例：memory 插件的 `memory/diff`，surface 类别）；核心词汇（user/message 等）的写入权属宿主，插件经 `ctx.sessions.appendEvent` 伪造内核词会被 `SESSION_CORE_TYPE_FORBIDDEN` 响亮拒绝。

## 5. 会话模型：事件日志 + 投影

- **事实只有一份**：append-only 事件日志（`events` 表）。模型历史、UI 时间线、检索索引全部是日志的**投影**（derive），可随时重建。
- **遮蔽而非删除**：compaction / surfaceOp 以遮蔽事件表达「这段不再进模型上下文」，原始事件永不物理删除——审计与回放完整。
- **分叉**：任意事件前缀可种子分叉出子会话（subagent 委派即用此机制，origin='delegation'）；边界必须落在已结算的 turn 上。
- **恢复**：进程重启后从日志重放合成运行时态；TUI 启动缺省续接当前目录最新会话（`/new` 开新会话）。
- **护栏**：单事件 64KiB 上限；write-behind 批落 + 落盘屏障（flush）。

## 6. 组合根装配序（src/app/assembly.ts）

```
ctx（createContext，① 根作用域）
 ├─ ①b project-aliases 表装载（canonical 根重定向——数据目录别名表，一次装载）
 ├─ ② 通道/UI 服务（channels + ui 聚合器）
 ├─ ③ 持久层（persist Store；persist:false 时全链降级；durable 转发壳在此）
 ├─ ④ llm 运行时（pi-ai Models 宿主 + StreamFn）+ 具名服务族
 │     （llm.complete / jobs / subagents / sessions；ctx.agent 随 chat 件）
 ├─ ⑤ 工具注册表 + 三段管道（三层注册表：全局层 + 应用域分片 + 驱动层；检索两件全局层注册，
 │     fs+bash 五件随 ⑨ chat 件驱动 open 落本会话域层〔S5：bash 升权闭包绑本驱动 approval——全局层退役〕；gate/decision 落 durable）
 ├─ ⑥ 审批 + 守门行（安全栈接线：审批对 + 沙箱档 + 可写根推导 + allowlist 免问存储）
 ├─ ⑦ 技能注册表 + 具名提示词段服务（ctx.prompts）
 ├─ ⑧ 装载层接线（tools_change 等活视图刷新义务——驱动本体随 chat 件）
 ├─ ⑨ 插件装载（组合树合成 → jiti 加载 → Kahn 轮次激活）
 │     └─ 默认层首行 builtin:chat 对话应用件：件内即完成会话选择/续接、
 │        驱动构造（ConversationDriver：launch 防重入 + steering + followUp）、
 │        durable 绑定与 ctx.agent provide——其后 memory / subagent / goal
 │        与文件插件完全同轨装载
 ├─ ⑨b 内置命令（help/quit/new/app/usage/allowlist/skills + 插件管理五件〔含 /reload〕）
 └─ ⑩ 交互模式审批接线（ctx.ui 应答；headless fail-closed）
```

服务提供时点全部早于插件装载——插件 `inject` 即得（Kahn 轮次按依赖排序激活；缺服务 = 启动断言拒启）。

## 7. 插件装载（组合树 + jiti）

- **组合树**：默认层（官方全家桶十行：chat 对话应用〔首行〕/ memory / subagent / goal / scheduler / mcp / tools / web / compaction / admin——Ring 1 树化行与官方件按插入序）+ `~/.berry/overlay.yaml` 字段级覆写（行字段 `id` / `plugin` / `config` / `disabled` / `fixed` / `runtime`〔worker 域声明 `'main'|'worker'` 缺省 `'main'`〕，未知字段拒绝式。挂载目标键 `app` 规范已定、随装载批收键——当前版本写它会被拒绝式拦下）。同名行后写胜出。
- **装机/挂载两态（D2 已落码）**：`/plugin-install` = **仓库态装机**（代码入装机子树 + provenance 出处落账，不落组合行 = 零生效）；挂载动词 `/plugin-mount` / `/plugin-unmount` 写/删组合行，挂载时必填挂载目标（`--app <应用id>`——第三方行挂系统 v1 拒绝，启动断言执法）。仓库态件在 `/plugins` 呈现 `installed-unmounted` 态（◇ 行带挂载指引）——「装了没挂」不可静默不可见。第三方行的技能/命令注册 v1 裁死拒载（provider 全局注入无域层——防跨应用漏注入，域层随首个真实第三方需求落地）。
- **加载**：文件插件入口解析顺序 `harness.extensions` → `extensions/index` → `index`；未安装的行标记 `unresolved`，**永不自动安装**（装机是 operator 动作：`/plugin-install`；卸载同样 operator 动作：`/plugin-uninstall` 两段式——检视后 `--confirm` 执行）。
- **执行**：jiti 加载 entry.ts（moduleCache 关闭，/reload 可重载）；形状校验（named export 走 `Object.hasOwn` 防 jiti 命名空间穿透冒充）；apply 抛错先 fork LIFO 回卷已激活件再进失败清单。
- **生命周期事件**：`plugin/activated` / `plugin/failed` / `plugin/skipped` / `plugin/uninstalled` 落 durable 日志；失败行非空 = 启动断言拒启（聚合清单一次抛全）。
- **热重载**：`/reload` = 卸载半边（dispose 回卷全部注册）→ 重读组合树 → 重装；run 进行中排队（全部驱动 idle 后自动执行一次，连发合并）。

插件形态与扩展点词汇的完整说明见 [插件开发指南](插件开发指南.md)。

| 7            | scheduler `jobs` 表（/tick 第一刀）                                                                                            |
| 8            | goal 需求写入列（goal-needs-write）                                                                                            |
| 9            | scheduler jobs v9（schedule 三形状 + 执行前抢占 + 记因/归属列）                                                                |
| 10           | `sessions` 增列 `importer`（导入者归因——origin='import' 行强制溯源）                                                           |
| 11           | memory 持有面：`memories` 增列 `frozen` / `ttl_days` / `expires_at` + `memory_versions`（版本链）+ `memory_access`（访问流水） |

迁移框架规则：只前进不回退；库内 version 高于宿主已知 = **拒绝打开**（宁拒绝不误读）；DDL 与 `user_version` 前进同事务，半迁移状态不可见。

## 9. 进程隔离与沙箱

隔离分两层 + 一个生态预留：

- **进程内护栏（案一）**：safety 席的守门/审批/升权编舞挂在 tools 三段管道 pre-execute——所有工具调用（含插件注册的）过同一守门面，无旁路。
- **worker 分域（案二，已落码）**：组合树行声明 `runtime: 'worker'` 即装载进专属 worker 子进程域（bridge 席承载协议端点，舰队编舞住组合根）。要点：
  - **故障域分域**非安全边界——worker 崩溃/冻结/OOM 只死该域：意外死亡结算（在途调用 `BRIDGE_WORKER_EXITED` + 行状态 failed + `plugin/failed` 广播，携带第一手 diagnostic），主进程无恙，**不自动重启**；
  - **内存预算硬执行面**：`resourceLimits.maxOldGenerationSizeMb`（应用清单 `budget.memoryMb` 换算，多应用共享组件取最严；宿主缺省 512MB）——超限 worker 终止 + `worker/oom` 事件；只限 JS 引擎堆，是预算工具不是安全墙；
  - **心跳冻结检测**：ping/pong 节律（缺省 15s × 丢 3 拍 ≈ 45s）判冻结 → watchdog kill 走意外死亡结算；boot 冷启窗归 load 超时监督，两窗互不借判据；CPU 燃烧不可判（无原语，如实收窄——打点照登不动手）；
  - **调用面收窄**：worker 域五个 ctx 同步编排面（`parallel` / `serial` / `waterfall` / `registerMessageRole` / `registerSessionEventType`）throw `BRIDGE_SURFACE_NARROWED`；服务调用面是 RPC Promise 唯一形态；官方件永主线程（机器执法：`builtin:` 行声明 worker 拒绝）；
  - **观测**：`worker/spawned|froze|oom` 活体事件 + `dump-config` 组合树 `@worker` 域标注。
- **宿主沙箱（e1，已落码）**：`berry run --sandbox-host`——宿主进程整体套 OS 沙箱（macOS seatbelt / Linux bwrap），CLI 检出后重 exec 自身；可写面 = 档位根 ∪ 数据目录；平台无后端 fail-closed 拒跑。诚实边界四条见[使用指南](使用指南.md)旗标段。
- **生态预留（案三）**：Ring 3 第三方重隔离需求升 fork（子进程池）——**桥接协议不换只换 carrier**，当前未启用。
