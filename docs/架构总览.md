# 架构总览

> Berry 1.0 的整体架构：三环装配模型、模块 DAG、事件系统、组合根装配序、应用装载机制。本文是公开面的架构文档，面向贡献者与应用作者；实现细节以代码与模块注释为准。

## 1. 核心命题

Berry 是 **Berry Agent OS——跑 AI 应用的操作系统**。固定内核只司四职能：

```
装（组合树装载应用）· 跑（loop 骨架承载运行）· 守（安全栈拦险）· 存（事件日志落史）
```

装载单位归一为「应用」，差异由**类型 × 作用域**两正交轴承载。类型三档（呈现层派生标签），一句话判据：**被启动的是应用型，被调用的是扩展型，被依赖的是服务型**。

| 类型       | 判据                                                | 例                                                                                                                                                                                                                 |
| ---------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **应用型** | 被启动为运行（前台会话 / 后台 job），带自己的 agent | **berrycode 代码智能体应用**（预装默认应用，`default: true` 清单键声明，2026-08-30 组装落码——纯清单应用，能力面全走 components 六件声明）；chat 对话应用（回落链第二跳锚点——默认应用缺场时兜住「仍有可对话入口」） |
| **扩展型** | 被调用，无自有运行实例                              | fs 工具族、技能包                                                                                                                                                                                                  |
| **服务型** | 被依赖，常驻服务而非被用户打开                      | memory（消费事件流、跨会话注入）                                                                                                                                                                                   |

**对话是应用，不是内核**：首启 TUI 进入的体验是第一方预装应用——内核只提供执行原语（loop 骨架之于 agent 运行，如 CPU 之于进程），连默认对话都没有；同一 OS 可装不同的对话应用。当前官方默认层首行即 `builtin:chat` 对话应用：组合根只持活引用槽，会话选择/续接、驱动构造、durable 绑定全部在件内完成。预装默认应用的终态**代码智能体应用已于 2026-08-30 组装落码**：berrycode 纯清单应用（零自有行为件），`/new` 无参启动与首启续接默认进入 berrycode 域。

**默认应用键（组装批落码）**：应用清单 `default: true` 声明默认应用——**官方专属词汇**（第三方清单携带即拒登记，发现面接通日执法），全局恰一（>1 份带标 = 拒启）。解析两跳回落：带标清单且组件在场 → 该应用；否则 chat 在场 → chat（回落锚点：默认应用被禁用时仍有可对话入口）；再否则 undefined 兜底态——TUI 无驱动起屏 + 警示、run 退 1，**不认领任意在册应用**（静默换域裁死）。解析是 per-open 活取：每次 open 按当下组合树投影即时计算，`/reload` 换件即时反映；string resume（`berry "继续"`）按会话 `app` 标签归域——标签在场且应用在场即改钉该域，NULL 存量（默认应用键之前的事件）默认归 berrycode 域。

每一次应用运行转的是同一条核心循环：

```
问（用户输入）→ 做（LLM 循环 + 工具）→ 守（安全栈守护）→ 存（事件日志持久）
```

两条设计红线：

1. **内核不感知任何增强域**。记忆、子代理、目标管理……在内核里没有概念位——它们是应用在扩展点上的注册物。卸载官方全家桶，核心循环照常运转。
2. **双重自进化走涌现路径**。使用进化（越用越懂你）与技能进化（SKILL.md 沉淀）由应用的组合涌现，不设中枢调度器 / 议会 / 进化引擎。

应用面机制（应用清单声明、启动面、多应用并行、应用级授权与预算账户）已落码——`builtin:chat` 对话应用为默认层首行（驱动装配在件内），`/app` 四动词（裸清单 / new 驻留 / 序号|id 前缀切换 / 清单 id 进入——带消息则进入后作为首条用户消息直接提交）可切换驻留的前台应用；默认入口 = berrycode 代码智能体应用（`default: true` 清单键，无参启动即进）。

**应用的装载与生效（应用中心装载面——四刀序 D1-D4 已全落码，2026-08-30 收口）**：装载单位归一为「应用」，差异由类型 × 作用域两正交轴承载——应用型件是独立安装物（有自己的代码、主题与程序，以 npm 三源分发上「市场」，不自建商店）；扩展型/服务型件装在应用上生效，但**独立不生效**——装机只入仓库（`install` = 仓库态，零生效），写组合行挂载才生效（挂载独立动词，D2 已落码）。作用域两档：**全局作用域**（行 `apps` 键缺省——服务所有应用，官方件全挂此档，memory 跨应用积累即「操作者状态长在同一份上」的机制面）与**应用作用域**（行带 `apps: [<应用id>, …]`——数组，多元素 = 多应用共享件；第三方能力件的档位：组成面/授权面/预算随宿主应用收拢）。全局作用域 v1 官方专属；应用作用域件可依赖全局作用域件，反向与跨应用不可。四刀序：D1 清单投影（已落码）→ D2 装机/挂载两态（已落码）→ D3 装载分面分区 + 单区 reload（已落码）→ D4 应用主题 accent（已落码——聚焦换装 + 多应用各归各色）。

## 2. 三环装配

| 环              | 定义           | 当前成员                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | 判据                                  |
| --------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| **Ring 0 内核** | 不可卸载的宿主 | 12 个模块：contracts / context / session / agent / safety / channels / app / bridge（固定八件）+ Ring 1 行四件（persist / llm / tools / exec——可换子集，下表另列非另计。见 §3）                                                                                                                                                                                                                                                                                                                                                     | 卸掉它，进程无法自举                  |
| **Ring 1 底座** | 可换不可缺位   | persist（SQLite）/ llm（pi-ai 适配）/ tools（三段管道 + 检索族）✅ 已挂组合树默认层（`builtin:tools` 必备行——禁用即拒启，2026-08-26 行树化首刀）/ channels（TUI 通道 + 命令面）✅ 已挂组合树默认层（`builtin:channels` 必备行——2026-08-30 Web 通道纵切刀一第二行树化，tools 同律禁用即拒启）/ exec（命令执行管道 + bash 工具）                                                                                                                                                                                                      | 卸掉它，首启核心循环「问→做→守→存」断 |
| **Ring 2 增强** | 真·可卸        | 官方全家桶（默认层十六行中的十四行）：`chat`（对话应用，默认层首行）/ `memory` / `subagent` / `goal` / `scheduler`（定时任务）/ `mcp` / `web` / `compaction`（长会话压缩）/ `admin`（平台管理面）/ `checkpoint`（工作区快照回退）/ `lsp`（语言服务器桥）/ `webui`（Web 通道——SSE + 微路由 + 回环三防线 + token 鉴权恒在场，`enabled` 缺省 false 惰性零监听，`--port` 开面）/ `obs`（观测面——第十五行）/ `browser`（浏览器自动化——第十六行）（+ 技能、通道命令等扩展；`tools`〔第七行〕与 `channels`〔第十三行〕两行为 Ring 1 必备） | 核心循环完好，只少长进与便利          |
| Ring 3 生态     | 第三方应用     | 市场口径 = npm 三源（设计已定）；第三方件挂**应用作用域**（全局作用域 v1 官方专属）；开放随应用中心装载面推进（D1-D4 已全落码）                                                                                                                                                                                                                                                                                                                                                                                                     | —                                     |

一句话判据：**卸掉它首启核心循环断 → 底座；核心循环完好、只少长进与便利 → 增强。**

Ring 2 默认装配 = 官方全家桶（写好一个默认随包一个）。每一件经 `/apps-toggle` 即减，减掉不破坏任何内核承诺。

## 4. 事件系统（三族词汇，全部显式注册）

| 族                                   | 载体                                   | 词汇量                       | 校验                              |
| ------------------------------------ | -------------------------------------- | ---------------------------- | --------------------------------- |
| **运行时总线事件**                   | `ctx.emit` / `ctx.on`（context 模块）  | 27 项                        | `tools/check-events.mjs` 双向断言 |
| **AgentEvent（loop 内活体事件）**    | agent loop 产出 → 组合根接线落库/上屏  | 10 型                        | 同上                              |
| **SessionEvent（durable 会话事件）** | `session.append` 写入 append-only 日志 | 28 类（核心词 + 应用扩展面） | 同上                              |

纪律：

- 每个事件词汇在 `LIVE_EVENT_CATALOG` / 事件类型注册表**显式注册**——注册即写入许可，无 declaration merging。
- 读侧遇未知类型且非 `ignorable`：**整体拒绝解读**（`SESSION_FORMAT_UNSUPPORTED`），宁拒绝不静默丢。
- 应用可注册自有 surface / log-only 事件词汇（首例：memory 应用的 `memory/diff`，surface 类别）；核心词汇（user/message 等）的写入权属宿主，应用经 `ctx.sessions.appendEvent` 伪造内核词会被 `SESSION_CORE_TYPE_FORBIDDEN` 响亮拒绝。
- **总线词汇另有应用声明层**：官方件自有词经件 `events` 声明在装载期登记（运行时词汇面 = 目录 ∪ 声明层，撞名即拒）——在树首例 = obs 件 `obs/alert`；词汇承诺位在各件声明，目录计数不含声明层。

## 5. 会话模型：事件日志 + 投影

- **事实只有一份**：append-only 事件日志（`events` 表）。模型历史、UI 时间线、检索索引全部是日志的**投影**（derive），可随时重建。
- **遮蔽而非删除**：compaction / surfaceOp 以遮蔽事件表达「这段不再进模型上下文」，原始事件永不物理删除——审计与回放完整。
- **分叉**：任意事件前缀可种子分叉出子会话（subagent 委派即用此机制，origin='delegation'）；边界必须落在已结算的 turn 上。
- **恢复**：进程重启后从日志重放合成运行时态；TUI 启动缺省续接当前目录最新会话（`/new` 开新会话）。
- **护栏**：单事件 64KiB 上限；write-behind 批落 + 落盘屏障（flush）。

## 7. 应用装载（组合树 + jiti）

- **组合树**：默认层（官方全家桶十六行：chat 对话应用〔首行〕/ memory / subagent / goal / scheduler / mcp / tools / web / compaction / admin / checkpoint / lsp / channels / webui / obs / browser——Ring 1 树化行与官方件按插入序；`tools`〔第七行〕/ `channels`〔第十三行〕为 Ring 1 必备，`webui`〔第十四行〕`enabled` 缺省 false 惰性零监听）+ `~/.berry/overlay.yaml` 字段级覆写（行字段 `id` / `pkg` / `config` / `disabled` / `fixed` / `sandbox` / `apps`，未知字段拒绝式。`sandbox` 块 = 载体声明：`carrier` 必填三值 `main|worker|external`、`net` 声明即拒（v1 无 net 执法基线）、`fs`/`caps` 纯对象、`builtin:` 官方行声明块即拒；`apps` 键 = 作用域声明，缺省 = 全局作用域〔v1 官方专属〕）。同名行后写胜出。
- **装机/挂载两态（D2 已落码）**：`/apps-install` = **仓库态装机**（代码入装机子树 + provenance 出处落账，不落组合行 = 零生效）；挂载动词 `/apps-mount` / `/apps-unmount` 写/删组合行，挂载时必填作用域（`--apps <应用id>[,…]` 多值 = 多应用共享件；`--carrier main|worker|external` 显式降格位，缺省不落 sandbox 块 = external 进程墙——第三方行挂全局作用域 v1 拒绝，启动断言执法）。仓库态件在 `/apps` 呈现 `installed-unmounted` 态（◇ 行带挂载指引）——「装了没挂」不可静默不可见。第三方行的技能/命令注册 v1 裁死拒载（provider 全局注入无域层——防跨应用漏注入，域层随首个真实第三方需求落地）。
- **加载**：文件件入口解析顺序 `harness.extensions` → `extensions/index` → `index`；未安装的行标记 `unresolved`，**永不自动安装**（装机是 operator 动作：`/apps-install`；卸载同样 operator 动作：`/apps-uninstall` 两段式——检视后 `--confirm` 执行）。
- **执行**：jiti 加载 entry.ts（moduleCache 关闭，/reload 可重载）；形状校验（named export 走 `Object.hasOwn` 防 jiti 命名空间穿透冒充）；apply 抛错先 fork LIFO 回卷已激活件再进失败清单。
- **生命周期事件**：`app/activated` / `app/failed` / `app/skipped` 活体总线；`app/uninstalled` 双落地（总线 + 当前会话 durable 流）。失败处置两桶：官方形引用行（pkg 缺省 ∪ `builtin:` 前缀）失败 = 启动断言拒启（聚合清单一次抛全——官方件是平台职能面，不带病跑）；第三方行失败 = 隔离降级——跳过继续启动 + 诊断文件 `<数据目录>/boot-failures.json`（行 id/错误码/栈/应用作用域）+ 启动横幅点名，`app/failed` 照逐行广播（隔离 ≠ 静默）。
- **热重载**：`/reload [--app <应用id>]` 两径——全量径 = 卸载半边（dispose 回卷全部注册）→ 重读组合树 → 重装；`--app` 单区径（D3）= 只重载该应用的挂载行，他应用运行时不动，回执带**卸词集警示**（该区旧事件词 ∖ 新词非空即列出——卸载后仍在途的事件将找不到处理器）。run 进行中排队：全量径等全部驱动 idle 后自动执行一次（连发合并），单区径按应用分槽——他应用的 run 不阻断。

应用形态与扩展点词汇的完整说明见 [应用开发指南](应用开发指南.md)。

## 9. 进程隔离与沙箱

隔离分两层 + 一个生态预留：

- **进程内护栏（案一）**：safety 席的守门/审批/升权编舞挂在 tools 三段管道 pre-execute——所有工具调用（含应用注册的）过同一守门面，无旁路。应用行的守门/审计监听经**守门行传导**进两处隔离作用域（子代理装配〔委托时点〕与对话驱动 fresh 作用域〔首工具调用时点惰性传导〕——`safety/gate.ts` 单源，判据 = 应用装载锚前缀 + main 行集；否则 fresh 作用域空 handler 表使应用行结构性不可达，checkpoint 捕获监听即首例实证）。
- **分域装载（案二，已落码）**：组合树行经 `sandbox.carrier` 声明分域（`worker` = 宿主内 worker 线程域；`external` = per-行 fork 进程域——第三方行缺省档，缺块即出生进 external）即装载进专属域（bridge 席承载协议端点，舰队编舞住组合根）。要点：
  - **故障域分域**非安全边界——域崩溃/冻结/OOM 只死该行：意外死亡结算（在途调用 `BRIDGE_WORKER_EXITED` + 行状态 failed + `app/failed` 广播，携带第一手 diagnostic），主进程无恙，**不自动重启**；
  - **内存预算硬执行面**：`resourceLimits.maxOldGenerationSizeMb`（应用清单 `budget.memoryMb` 换算，多应用共享组件取最严；宿主缺省 512MB）——超限域终止 + `worker/oom` 事件；只限 JS 引擎堆，是预算工具不是安全墙；
  - **心跳冻结检测**：ping/pong 节律（缺省 15s × 丢 3 拍 ≈ 45s）判冻结 → watchdog kill 走意外死亡结算；boot 冷启窗归 load 超时监督，两窗互不借判据；CPU 燃烧不可判（无原语，如实收窄——打点照登不动手）；
  - **调用面收窄**：分域行（worker/external）五个 ctx 同步编排面（`parallel` / `serial` / `waterfall` / `registerMessageRole` / `registerSessionEventType`）throw `BRIDGE_SURFACE_NARROWED`；服务调用面是 RPC Promise 唯一形态；官方件永主线程（机器执法：`builtin:` 行声明 sandbox 块即拒）；
  - **观测**：`worker/spawned|froze|oom` 活体事件 + `dump-config` 组合树 `@worker` / `@external` 载体标注。
- **宿主沙箱（e1，已落码）**：`berry run --sandbox-host`——宿主进程整体套 OS 沙箱（macOS seatbelt / Linux bwrap），CLI 检出后重 exec 自身；可写面 = 档位根 ∪ 数据目录；平台无后端 fail-closed 拒跑。诚实边界四条见[使用指南](使用指南.md)旗标段。
- **运行域升格（原「案三」生态预留——2026-08-29 已拍板开闸并落码）**：第三方件缺省运行域 = external fork 域（per-行域进程墙，非共享池）——**桥接协议不换只换 carrier**。external 载体三层执法：进程墙（per-行 fork）+ Node permission-model 中层（写白名单推导）+ OS 沙箱层（宿主基线 ∩ 行声明 writableRoots 交集执法，装载期 probe fail-closed）；PM 中层不是墙（UDS bind 逃逸 PoC 实证——CVE-2026-21711 同型，诚实边界见[运维手册](运维手册.md) §7.1）。
