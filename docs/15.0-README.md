# 15.0 架构总览

> 15.0 是 BerryAgent 后端的**已落地架构标准**之一（与 [22 对话内联统一](../设计文档/废弃/22-对话内联统一.md) 共同构成当前标准）。本文档面向**新加入项目的开发者**，
> 用 10 分钟让你理解 15.0 的核心架构、数据流和扩展点。**前进设计线**（17.0 滚动计划循环 / 18.0 berryagentOS 概念）见 [设计文档/index.md](../设计文档/index.md)。

## 一句话总结

**15.0 = 13.0 灵魂版 + Brain 中心化治理（控制流）+ 存储层加固（数据层）。**
Brain 是观察者 + 调度员 + 仲裁员 + 中枢治理者，**永远不直接回复用户**。

## 15.0 双支柱（在 13.0 基础上的增量）

15.0 互不依赖、可并行落地的两条演进线：

### 第一支柱 · Brain 中心化治理（控制流）

把 Brain 从「即时审核者」升级为「中枢治理者」，四个机制闭环：

| 机制 | 内容 |
|------|------|
| **A. 权限三级审批** | L1 规则（PermissionEngine）→ L2 Brain（语义判断）→ L3 用户（高风险确认）；YOLO 模式全交 Brain |
| **B. 统一升级通道（BrainEscalation）** | Brain 决定不了时，转 Conversation Agent 问用户，归一化所有「转人工」触发点 |
| **C. 后置检查 Auditor Agent** | 被动事后审计，扫描 DB + artifacts 给 Brain 出报告（不阻塞主流程） |
| **D. Brain 指挥通道（brain.command）** | Brain 可向所有 Agent 发号施令（17 种手段），补足被动审核的缺口 |

### 第二支柱 · 存储层加固（数据层）

给 13.0 定型的对话/审计表打「地基补丁」，对标 Hermes + OpenClaw：

- **FTS5 双索引**（unicode61 + trigram）— CJK 短语/子串搜索
- **应用层 jitter 写竞争退避** — 高并发写不冲突
- **PASSIVE WAL 定期 checkpoint** — 避免 WAL 无限增长
- **声明式 schema 演进**（`_reconcile_columns`）— ADD COLUMN 声明式补列
- **落盘前 redact / secret 清洗** — secret 不落 DB
- **JSONL transcript-tail 工具** — 运维侧 tail 对话流

> 详细设计见 [`设计文档/21-架构升级-15.0.md`](../设计文档/废弃/21-架构升级-15.0.md)。

## 核心设计原则

### 1. Brain 不直接回复用户

- 所有用户消息经 Conversation Agent 处理
- Brain 只做：调度（谁来做）+ 组织（mission/squad）+ 审核（approve/modify/reject）+ 纠偏（中途干预）+ 治理（15.0：指挥/升级/事后审计）
- 任何 agent 都不能 `to: 'brain'` 发送消息（KernelRouter.gate() 硬阻止）

### 2. 数据流：DB 是事实源，JSON 文件是缓存

- Mission / Squad / HandoffContext 持久化到 `~/.berry/missions/<mission_id>/plan.json` + `squad.json`
- Brain decisions / corrections / user preferences 持久化到 SQLite
- Session 历史持久化到 `conversations` 表（15.0：FTS5 双索引 + 落盘 redact）
- Skill / Plugin / Config 以文件为事实源

### 3. 模块化解耦（contract-first）

```
模块A ─────────── contract ─────────── 模块B
   │                                     │
   └─ 监听 EventBus 事件 ←───────────────┘
```

- 跨模块通信：EventBus / IPC / StateCache
- 不允许跨模块直接 import 内部实现
- 每个模块必须能独立单测

### 4. 安全防护（15.0 升级为权限三级）

```
L1 规则: PermissionEngine.checkPermission (allow-all / ask / deny-all / yolo)
              ↓
L2 Brain: 高风险/不确定时 Brain 语义判断（YOLO 模式全交 Brain）
              ↓
L3 用户: 最危险操作转用户确认（BrainEscalation → Conversation ask_user）
              ↓
硬约束: PermissionCoordinator.checkActiveScope (blockTools/blockPaths)
              ↓
工具自检: 特定 tool 自己的检查（如 run_command 的 blocklist）
              ↓
事后审计: Auditor Agent 扫描 DB/artifacts 给 Brain 出报告（15.0 新增）
```

## 数据流：一个用户消息的一生

```
1. User 发送消息
   ↓
2. WS 收到 → kernel/handlers/unified-handlers.ts
   ↓
3. PendingRequest 创建 + SessionManager 保存
   ↓
4. Brain.route.request IPC → Brain Agent 思考
   ├─ 简单消息 → FallbackRouter 直发
   ├─ 复杂消息 → Brain LLM 决定 intent + targetAgent
   └─ mission 任务 → Brain LLM 创建/更新 plan
   ↓
5. KernelRouter.gate() 安全检查 (to ≠ 'brain', 频率限制, 调用深度)
   ↓
6. DialogRouter / Conversation Agent 处理
   ├─ Conversation 自己回答
   ├─ Delegate 给 Code/Learning/Skills 等按需 Agent
   └─ 触发 Plan Task → MissionManager.updatePlan
   ↓
7. 工具调用走权限三级（L1 规则 → L2 Brain → L3 用户）
   └─ Brain 决定不了 → BrainEscalation → Conversation ask_user（15.0）
   ↓
8. Brain.review.request IPC → Brain 审核
   ↓
9. BrainDecisionRecorder.recordReviewDecision (outcome=good/bad/neutral)
   + MissionManager.updatePlan 自动 mark task done/failed
   + sensitive data 自动脱敏（15.0 落盘 redact）
   ↓
10. WS 推送 review_info → 前端显示审核结果
    └─ 用户可点击「还原 Brain 修改」→ POST /api/brain/restore-original
       ├─ 触发 brain.feedback 事件
       └─ Evolution Engine stub → PatternMatcher → user_preferences
   ↓
11. Auditor Agent 异步后置审计（15.0 新增，不阻塞主流程）
    └─ 扫描本轮 DB 记录/artifacts → 给 Brain 出 risk report
```

## 关键数据结构

### HandoffContext

```ts
interface HandoffContext {
  originalInstruction: string;        // 原始用户指令
  intentAnchor: { goal, successCriteria, scope } | null;
  filesRead: string[];                // 已读文件
  filesModified: Array<{ path, diffHash? }>;
  agentConversations: Array<{ with, summary, at }>;
  currentProgress: string;
  blockers: Array<{ reason, raisedAt, raisedBy }>;
  scopeSnapshot?: { blockPaths, blockTools };
  handoffAt: number;
  fromAgent: string;
}
```

### MissionContext

```ts
interface MissionContext {
  missionId, goal: string;
  currentTaskId, currentTaskWhat: string;
  squadRole: 'lead' | 'work' | 'check';
  squadOn, squadGoal: string;
  squadTeammates: Array<{ agent, role, on, status }>;
  completedTasks, inProgressTasks: Array<{ id, what, result? }>;
  unresolvedSignals: Array<{ from, type, msg, at }>;
}
```

## 常见场景

### 场景 A：用户问简单问题

```
User → WS → KernelRouter → Conversation Agent
                       ↓
                     LLM 直接回答
                       ↓
                Brain review (auto-approve for A级)
                       ↓
                  final.response → WS → 前端
                       ↓（异步）
                 Auditor 后置审计扫描（15.0）
```

### 场景 B：用户问代码问题

```
User → WS → KernelRouter → Brain.route.request
                              ↓
                            Brain LLM: intent=code
                              ↓
                          Brain sends review.request to code agent
                              ↓
                          Code Agent 通过 AgentPort 用工具
                            └─ 工具走权限三级（L1 规则 / L2 Brain / L3 用户）
                              ↓
                          Code Agent 提交 turn.final
                              ↓
                          Brain.review (B级审核)
                              ↓
                          Conversation 包装回复
                              ↓
                          final.response → WS
```

### 场景 C：用户启动复杂 mission

```
User → WS → KernelRouter → Brain.route.request
                              ↓
                            Brain LLM: 创建 mission spec
                              ↓
                          MissionManager.createMission()
                          + autoGenerateSquad()
                              ↓
                          EventBus emits mission.created/updated
                              ↓
                          Frontend 显示 mission UI
                              ↓
                          mission.task_ready → 自动派发到 Code/Learning agent
                              ↓
                          Plan tasks 按依赖顺序执行
                              ↓
                          每完成一个 → BrainDecisionRecorder 记录 + plan auto-mark-done
                              ↓
                          全部完成 → mission.completed 事件
```

### 场景 D：worker 失败触发纠偏

```
Code Agent 失败（连续 3 次或预算超限）
                              ↓
                          CorrectionFlow.handleCheckpointNeeded
                              ↓
                          Brain.checkpoint.evaluate
                              ↓
                          Brain LLM 决定 action=adjust + instruction
                              ↓
                          applyAdjust:
                            ├─ PermissionCoordinator.setActiveScope(blockTools)
                            ├─ StateCache.set('correction', lesson)
                            ├─ BrainDecisionRecorder.recordReviewDecision
                            ├─ CorrectionFrequencyDetector.record (累积)
                            └─ EventBus.emit('brain.correction')
                              ↓
                          Code Agent 通过 PermissionCoordinator.checkActiveScope
                          拦截到 forbidden tools → 必须改用允许的工具
```

## 扩展指南

### 添加新 Agent

1. 在 `src/agents/bundled/<name>/` 创建目录
2. 写 `agent.json` manifest（参考 `brain/agent.json`）
3. 写 `entry.ts` 用 `startResidentAgent` 或 `startModuleAgent`
4. 在 `src/agents/index.ts` 注册

### 添加新 Tool

```ts
import type { ToolDefinition } from './types.js';
import { z } from 'zod';

export const myTool: ToolDefinition = {
  name: 'my_tool',
  description: '...',
  inputSchema: z.object({...}),
  dangerLevel: 'moderate',  // 'safe' | 'moderate' | 'dangerous'
  execute: async (input) => ({ content: '...' }),
};
```

然后在 `src/tools/index.ts` 添加到 `builtinTools` 数组。

### 添加新 EventBus 事件

1. 在 `src/contracts/messages.ts` 的 `EventMap` 添加类型
2. 在消费者端直接用 `getEventBus().emit('your.event', {...})`（类型安全，无需 `as any`）
3. 在 `src/web/ws-event-bridge.ts` 添加到 `BRIDGED_EVENTS` 或 `STREAM_EVENT_MAPPING`

### 添加新 Brain Review 场景

1. 在 `src/agents/bundled/brain/prompts.ts` 加新场景描述
2. 在 `entry.ts` 的 `review.request` handler 加新分支
3. 写测试覆盖新场景

## 关键性能指标

- AgentPort.request() 默认超时 60s
- DialogueRouter per-target 上限 2 个对话
- MissionContext 注入由 Brain LLM 在每次 turn 开头读取（缓存于 StateCache）
- BrainDecisionRecorder 持久化 < 5ms
- brain_corrections 表查询（5min 窗口）< 10ms

## 设计纪律（CLAUDE.md）

1. **无 if/else 补丁**：每个新概念解决多个问题
2. **无 backward-compat shim**：直接重构
3. **Brain 必经审核**：所有回复路径走 review
4. **模块化解耦**：通过 EventBus / IPC / StateCache
5. **命名去品牌化**：代码标识符无 `berry` 等品牌词
6. **中文 JSDoc + 行内注释**：新代码注释齐全
7. **测试覆盖**：所有新功能必有单测
8. **pre-commit hook**：typecheck + 全测试套件100% 通过
