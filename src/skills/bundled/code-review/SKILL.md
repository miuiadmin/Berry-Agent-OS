## 触发条件

- 用户请求 code review
- 用户提交代码变更请求审查
- 用户要求检查代码质量

## 执行规则

### 1. 确认审查范围

审查参数：$ARGUMENTS

目标文件：$file_path
关注领域：$focus_area

### 2. 审查维度

按以下维度逐一检查：

**正确性**
- 逻辑是否正确
- 边界条件是否处理
- 错误处理是否完善

**安全性**
- 是否存在注入风险
- 敏感数据是否暴露
- 权限检查是否充分

**性能**
- 是否有不必要的计算
- 是否有 N+1 查询
- 内存使用是否合理

**可维护性**
- 命名是否清晰
- 职责是否单一
- 是否符合项目约定

### 3. 输出格式

```markdown
## Code Review: $file_path

### 严重问题 (必须修复)
- [ ] ...

### 建议改进
- [ ] ...

### 亮点
- ...

### 总结
<一句话评估>
```

### 4. 注意事项

- 优先指出安全和正确性问题
- 建议要具体，给出修改示例
- 不要纠结于风格偏好（除非违反项目规范）
- 如果 $focus_area 指定了关注点，该维度优先详述
