## 触发条件

- 用户请求生成 API 文档
- 用户要求从代码提取接口说明
- 用户需要更新已有 API 文档

## 执行规则

### 1. 扫描目标

分析 $target_path 中的：
- 导出的函数/类/接口
- JSDoc / TSDoc 注释
- Zod schema 定义
- 路由注册

### 2. 提取信息

对每个 API 端点或公开接口提取：
- **名称** — 函数名/路由路径
- **方法** — GET/POST/PUT/DELETE（如适用）
- **参数** — 类型 + 描述 + 是否必填
- **返回值** — 类型 + 描述
- **错误码** — 可能的错误响应
- **示例** — 请求/响应示例

### 3. 输出格式

```markdown
# API 文档: <模块名>

## <接口名称>

**描述**: ...
**路径**: `METHOD /path`

### 请求参数

| 参数 | 类型 | 必填 | 描述 |
|------|------|------|------|
| ... | ... | ... | ... |

### 响应

\`\`\`json
{ ... }
\`\`\`

### 错误码

| 状态码 | 描述 |
|--------|------|
| ... | ... |
```

### 4. 注意事项

- 优先使用代码中已有的注释和类型信息
- 缺失的描述用 `[TODO: 补充描述]` 标记
- 保持与项目已有文档风格一致
- 如果存在 OpenAPI/Swagger 定义，优先参考
